## A. 리그 MVP
**범위**: 설정(팀 2~6·턴 1~9·규칙 4가지[녹아웃+무제한, 공식+3/5/8분]), 팀 선택(15팀 격자, 중복 불가, SPECIAL 줄은 해금 시), 팀별 사람/컴퓨터(사람 ≤1), 리그 메뉴(경기하기/성적 보기/설정 변경), 대전표(팀×팀 `승-패` 누적, 대각선·다 치른 칸 선택 불가), 승패표(순위·M/C·팀·승·패·승률·남은 경기), 순위=자기보다 승률(천분율 내림) 높은 팀 수(동률 같은 번호), 컴-컴 카드=즉시 판정, 사람 낀 카드=실제 경기(사람 좌석 0, 스테이지=오른쪽 팀 홈), 우승 화면(순위 0인 팀 전부 참가 순), 닉네임당 리그 1개 저장·이어하기. 후속: 컴-컴 관전, 개막식, 트로피·전광판 그림, 사람끼리 카드, 온라인 리그, 리그 곡.
**서버 규칙**: 데이터 `league={teams:[{team,com}],turns,rules:{mode,time},res:[[[승,패]]],done}`; 파생(w,l,rate=floor(w*1000/(w+l)),left=(n-1)*turns-w-l,rank)은 저장하지 않고 계산. 카드 `(i,j)`는 i≠j이고 `res[i][j]` 합<turns. 즉시 판정: 상위 바이트 a,c(낮거나 같은 쪽 절반), `p=floor(a*256/(a+c))`, 난수 1바이트 `r<=p`면 왼쪽 승(analysis/29 §2-5). 스테이지: 오른쪽 팀 → 표 0x1257A → `romStage` → `stage`(campaign.json 15행과 대조 일치). 기권=패 기록, `draw_cap`·`error`=미기록. 22·23·24 팀 거절. 저장은 progress.js 패턴의 별도 파일(예: `data/progress/league.json`, 닉네임 소문자 키, 원자적 교체).
**프로토콜(제안)**: `league_get`→`league_state{league,table,special}`, `league_new{teams,turns,rules}`, `league_config{com,rules}`, `league_play{i,j}`(컴-컴: 즉시 판정 → `league_result{i,j,winner,quick:true}`+`league_state`; 사람 낀 카드: 비공개 방 → `room_joined{room.league}` → `game_start{league}`), `league_end{champions}`, `league_abandon`. 오류 코드 `LEAGUE_NONE/LEAGUE_INVALID/LEAGUE_CARD_INVALID/LEAGUE_TEAM_LOCKED`(토스트). 방은 특훈 방 방식(끝나면 삭제→`room_left`→클라이언트가 리그 메뉴로), `room_list` 제외, `set_team`·`start` 거절.
**클라이언트 화면**: 진입 창, 설정, 팀 선택, 사람/컴퓨터, 리그 메뉴, 승패표, 대전표, 우승(기존 UI 토큰·`pixtext.js`·`lineup.js`·`prematch.js`·`room.js` 격자 재사용, 설명 문구 없음, 에러는 토스트).
**인수조건 10개**: ①3팀 2턴 생성 시 남은 경기 4·전원 `.000` 1위, 팀 수 1·7·턴 0·10·중복·팀 22~24 거절 ②해금 전 SPECIAL 줄 없음·서버 거절, 해금 계정은 선택 가능 ③승률 floor, 순위 규칙(1000/0/0→1·2·2위, 500/500/0→1·1·3위, 500/500/500→1·1·1위) 단위 테스트 ④같은 카드 2번(2턴) 후 3번째·대각선 거절 ⑤즉시 판정 a=103,c=103,r=46 → 왼쪽 승(p=84), r=85 → 오른쪽 승; 팀 1·3 상위 바이트 103, 팀 15 가 173 ⑥컴-컴 카드는 경기 화면 없이 기록 ⑦사람-컴 카드는 라인업→편성→경기, 사람 좌석 0, 스테이지=오른쪽 팀 홈, 정상 종료 뒤 한 번만 기록, 기권=패배, draw_cap·error 미기록 ⑧공식·5분이면 `rules.mode='official'·limitFrames=18000`, 녹아웃이면 0 ⑨전원 남은 경기 0이면 우승 화면(공동 1위 전부), 전원 컴퓨터 3팀 리그 끝까지 ⑩재접속·서버 재시작 뒤 이어하기가 설정·대전표·승패표 그대로, `처음부터`는 확인 뒤 덮어씀, `npm test` 60과 하니스 73 PASS 유지.
**검증 범위**: 전역 규칙대로 핵심 동작+에러 없음(서버 단위 테스트는 ③·⑤와 리그 한 바퀴 정도).
**분배·순서**: ①박백엔 — 첫 증분 "전원 컴퓨터 리그가 서버 메시지만으로 끝까지" (인수조건 1·3·4·5·6·9, 서버 약 350~450줄+테스트 약 100줄) → 사람 경기 연동 → PROTOCOL §10 ②윤프론 — 화면 8개+라우팅(`main.js`에서 `room.league`가 있으면 대기실로 가지 않기, 특훈과 같은 분기)+로비 진입 항목(로비 개편과 같은 파일이므로 개편 완료 후), 약 600~800줄 ③정검수(중복 기록·검증 누락·방 정리 누수 중심) ④강화면(전원 컴퓨터 3팀 2턴 끝까지+사람 1경기+이어하기).
**리스크**: 로비 개편(`lobby.js`·`app.css`) 충돌, 무제한 녹아웃 30분 `draw_cap` 반복 가능, 원작 화면 좌표는 캡처 `analysis/gfx/modes/lg_*.png`만 있고 수치 미추출(MVP는 배치만 맞춤), `teams.json` 능력치가 ROM 원값인지는 인수조건 5로 검증.

## B. 온라인 랭킹(래더) — [자작]
**전제**: 닉네임이 곧 신원(README, PROTOCOL §8.3). `results.jsonl` 레코드에 players·winner·endReason·rules·vsCpu가 있으나 `ranked` 표시와 읽기 기능이 없다.
**권고 기본값**: Elo 초기 1000·K=32(첫 10경기 K=48)·하한 100, 입장은 방 목록의 랭크 방(방 만들 때 `ranked`, 목록 탭/필터), 랭크 방 규칙은 녹아웃·5분 고정(`set_rules` 거절), 정상 종료·기권(기권 쪽 패배)만 반영, `draw_cap`·`error`·GO 이전 종료는 변동 없음, 어뷰징 방어(같은 상대 24시간 3경기까지 반영·같은 IP 두 세션 미반영[선택]·최근 10경기 중 기권 3회면 30분 잠금), 시즌 없음(`season:1` 필드만), 순위표 상위 50명+내 순위(5경기 미만은 "배치 중"), 저장 별도 JSON(`data/progress/ranking.json`, 닉네임 키 `{rating,w,l,games,recent[],season}`), 결과 레코드에 `ranked:true`·`ratingDelta` 기록. SPECIAL 허용·22~24 금지.
**프로토콜(제안)**: `create_room.ranked`, `room_list/room_state.ranked`, `ranking_list{top?}`→`{top:[{rank,nick,rating,w,l}],me}`, `ranking_result{matchId,counted,why?,before,after,delta,oppBefore}`; 오류 `RANKED_LOCKED`·`RANKED_RULES_FIXED`.
**인수조건 7개**: ①랭크 방 구분·규칙 고정, 컴퓨터·캠페인·특훈·리그는 영향 없음 ②1000 대 1000 승리 시 +16/−16(배치 구간 +24/−24) ③퇴장·유예 초과는 기권 패배, draw_cap·error·GO 이전 변동 없음 ④같은 상대 24시간 4번째 경기는 `counted=false` ⑤`ranking_list`가 상위 50명+내 순위, 5경기 미만 제외 ⑥재시작 후 유지, 파일 손상 시 원본 보존+빈 상태 시작 ⑦결과 화면에 레이팅 변동, 로비에서 순위표 진입, 오류는 토스트.
**열린 질문(사용자 확인 필요 1개)**: 닉네임 소유 장치 — (가) 없음 (나) 비밀번호 (다) 브라우저 영구 토큰(권고, 기기 변경 시 닉네임 상실). 캠페인·리그 저장 보호에도 영향. 비밀번호를 받으면 개인정보 처리 항목이 생긴다(공개 전 메모).
**분배·순서**: 리그 → 로비 개편 마무리 → 랭킹. 박백엔 서버 약 250~350줄(+소유 장치 시 150~250줄·`hello` 변경), 윤프론 화면 약 300~400줄(로비 탭, 방 만들기 옵션, 결과 변동, 순위표), 정검수(보안 포함)→강화면(두 브라우저).
**리스크**: 인증 없이는 순위표가 탈취·다중 계정으로 오염될 수 있고 어뷰징 방어는 비용을 올릴 뿐이다. 같은 IP 판정은 `TRUST_PROXY` 설정이 틀리면 전원 미반영(배포 환경 확인). `onGameEnd` 분기(캠페인·특훈·리그·랭크) 순서 꼬임 주의. 연결 품질 차이 미측정.
