## 2. 전체 흐름

```
전원 → SEGA 로고 → 오프닝(약 42초) → 타이틀(GAME / OPTION)
                                        │ 640f 방치 → 어트랙트 데모 경기(3600f) → SEGA 로고
        OPTION: 조작 TYPE(1P/2P), B.G.M. TEST, S.E. TEST, EXIT
        GAME → 모드 메뉴 "モードを選んでください"
               1 倒せ!闘球の強豪たち (스토리)
               2 1PvsCOM
               3 1Pvs2P
               4 闘球リーグ
               5 炎の猛特訓
```
- 타이틀·오프닝·어트랙트·OPTION 은 `10_intro_title.md` [확인]. 모드 메뉴 5항목과 상태 번호(`$E600` = 0x9C/0xA4/0xAC/0xB4/0x94)는 표 0x10A58 [확인].
- 모드 메뉴에서 B = 타이틀로 [판독만 0x10A20]. 각 모드 첫 화면에서 B = 모드 메뉴로 [판독만].
- 경기가 끝난 뒤 돌아갈 곳은 모드별 표 0x40D8: 스토리 → 0x9C(스토리 흐름 계속), 1PvsCOM·1Pvs2P → 0x88(모드 메뉴), 리그 → 0xB4(리그 흐름 계속) [판독만 표] / 1PvsCOM·리그·스토리는 [확인]. 특훈은 이 표를 쓰지 않고 자체 경로(0x3C12)로 0x94 에 돌아온다 [확인].

### 2-1. 경기 전 공통 화면 3종
| 화면 | 내용 | 나오는 모드 |
|---|---|---|
| 규칙 창 | `ルール` ノックアウト/こうしき, `しあいじかん` むせいげん/3/5/8分, EXIT | 1PvsCOM, 1Pvs2P (리그는 리그 설정 창에 같은 항목) |
| 라인업 VS | 양 팀 엠블럼·팀명·약칭 + 선수 7명 얼굴·이름, 가운데 VS | 전 대전 모드 |
| 편성(포메이션) | 팀 패널 + 고른 선수의 얼굴·이름·능력치 6줄 막대 + 코트 위 7명 배치. 사람 팀은 자리 교대 가능, COM 팀은 보기 전용 | 전 대전 모드 |
- 세 화면의 좌표·입력은 `11_team_select.md` §4, `20_prematch_screens.md` §3 [확인].
- 규칙: ノックアウト = 체력제(맞으면 데미지, 0 이 되면 아웃). こうしき = `$E680`=1, 데미지 없음 + 맞은 공이 바닥에 닿거나 상대가 잡으면 쓰러짐이 끝날 때 아웃(같은 편이 노바운드로 잡으면 세이프) + 제한 시간 사용 + 필살 슛은 일반 슛으로 나감 [확인, 29 문서 §3·§4-1-1. 처음 적었던 '맞으면 즉시 아웃·필살 슛 불가'(`04_rules.md`·`05_match_rules.md` 판독)는 오독이라 2026-11-18 정정]. こうしき 를 고르면 むせいげん 이 회색이 되고 시간이 3分으로 바뀐다 [확인: `lg_01_settings.png`].
- こうしき 경기 HUD 는 체력 막대 대신 가운데에 `6-7` 같은 숫자 쌍이 나온다 [확인: `lg_08_official_rule_hud.png`]. 숫자의 뜻은 남은 인원 [확인, 29 문서 §3-3].
- [2026-11-18 정정, 29 문서 §3] 시간 줄의 값은 3/5/8분 3개뿐이고 ノックアウト 에서는 줄이 잠겨 `むせいげん` 으로만 표시된다(체력제 + 제한 시간 조합은 원작에 없음) [판독만 0x14716·0x16958]. こうしき 의 피격은 "즉시 아웃"이 아니라 **맞은 공이 바닥에 닿거나 상대가 잡으면 쓰러짐이 끝날 때 아웃, 같은 편이 노바운드로 잡으면 세이프**다 [확인: 바닥 → 아웃, 상대 캐치 → 아웃, 같은 편 캐치 → 세이프. 뒤의 둘은 2026-11-18 원작 실행으로 확정(29 §4-1-1)]. 필살은 차지는 되지만 일반 슛으로 나간다 [확인]. 시간 종료 동수는 TIME UP·PLAY OFF 배너(181f + 181f) 동안 선수가 멈춘 뒤 양쪽 남은 인원 1 로 재개 [확인].

진행 규칙
- 팀 선택 없음. 플레이어는 언제나 玉川小(T.D). 경기 수 15(`$E688` 0~14) [판독만 0x118C6] / 1→2전, 3→4전 진행 [확인].
- 이기면 다음 경기, 지면 컨티뉴(횟수 제한 코드 없음 [판독만]).
- **세이브 지점은 4곳뿐**: 3·7·11번째 경기를 이긴 직후와 15번째(최종) 승리 후. 저장 값은 "다음에 할 경기 번호"이고 불러올 때 3/7/11/14 가 아니면 저장 없음으로 처리한다 [판독만 0x14076 표] / 3번째 승리 후 세이브 창과 RAM `$E5A0` = `00 03 'DANPEI'` 기록 [확인].
- 최종 승리 시 `$E500` bit0 = SPECIAL TEAM 해금(대전 팀 선택에 해외 강팀 7개 행 추가, `11_team_select.md`) [판독만 0x11904]. 해금 비트도 스토리 저장 바이트에 함께 들어가고 타이틀에서 다시 읽는다 [판독만 0x12BFA, 0x1028C].

### 3-2. 1PvsCOM — 0xA4
팀 선택(1P 확정 → COM 팀도 1P 가 고름) → 규칙 창 → 라인업 → 편성 1P → 편성 COM → 경기 → 승리 포즈 → **모드 메뉴로 복귀** [확인]. 결과 화면·전적 저장 없음 [확인: 승리 포즈 뒤 바로 0x88].

### 3-3. 1Pvs2P — 0xAC
1PvsCOM 과 같은 구조. 팀 선택은 두 패드 동시, 편성은 1P → 2P 순서 [확인 `20_prematch_screens.md`]. 경기 후는 모드 메뉴 [판독만 표 0x40D8].

진행 규칙
- 총당: 한 턴에 모든 쌍이 1경기. 남은 경기 수 = (팀 수 − 1) × 턴 수 [확인: 3팀 1턴 → 2, 4팀 2턴 → 6].
- 모든 팀의 のこり 가 0 이면 우승 화면 [판독만 0x1634A] / 2팀 1턴에서 1경기 뒤 우승 화면 [확인].
- 순위(0x16E56) = 자기보다 승률이 높은 팀 수. 승률(천분율 내림)만 본다. 동률은 같은 순위 번호, 공동 1위는 우승 화면에 전부 차례로 나온다 [확인, 29 문서 §2-2·§2-6]. 승점·득실 없음.
- 2턴 이상: 같은 카드를 턴 수만큼 치르고 칸에 `승-패` 가 쌓인다. 다 치른 카드는 선택 불가 [확인, 29 §2-3].
- COM 끼리 즉시 판정: 팀 레이팅(선수 7명 × 능력치 8종 가중합, 0x3460)의 상위 바이트 두 개에서 낮은 쪽을 절반으로 깎고, 그 비율과 난수 1바이트를 비교해 승패를 정한다 [판독만 0x34DE]. 강한 팀이 더 유리해지는 구조.
- MAN 끼리 카드: 왼쪽 1P 패드, 오른쪽 2P 패드 [확인]. 2P 패드가 없으면 카드가 선택되지 않는다 [판독만 0x16054]. SPECIAL TEAM 은 해금 비트가 서 있으면 리그 팀 선택에 7칸 줄로 나오고 고를 수 있다 [확인(해금 비트 poke), `lg_09_special_team_select.png`]. 상세·즉시 판정 식·저장 레코드 필드는 29 문서 §2.
- 캡처에서 리그 경기는 こうしき·5분으로 했다(HUD 숫자 쌍, 시계 5:00) [확인].

| 완료 | 대사(`よし、とりあえず…マスターしたようだな`) 뒤 모드 메뉴 | [확인] |
| 거절 | `とっくんは いやだ!` → 모드 메뉴 | [판독만 0x10E7E] |
- 구성: 사이드 A = 팀 22(주인공 쪽), 사이드 B = 팀 24(연습 상대), 스테이지 13(학교 운동장), 규칙은 체력제이고 통계 집계 켜짐 [판독만 0x3750].
- [2026-11-18 갱신] 합격선은 치트 없이 패드 입력만으로 다시 돌려 확인했다: 캐치 5개 = 재시도, 6개 = 다음 단계, 필살 9개 = 재시도, 10개 = 완료 [확인(실입력), 29 문서 §1-2]. 단계별 투구(5.5 / 6.5 / 7.5+차지 px/f), 말풍선 10종, HUD 좌표, 보상 없음은 29 문서 §1.
- 조언 대사에 담긴 조작 규칙(원문): 캐치는 공이 닿기 직전 B, 잡은 직후 재빨리 B 를 누르면 받은 슛을 그대로 되돌려 던짐, 필살 슛은 점프 중 B 를 눌러 모으다가 공이 새하얘질 때 뗌, 대시 점프는 체공이 길어 던지기 쉬움.
- 머리띠 선수가 누구인지 [미확정].

## 4. 저장 (백업 EEPROM)

- 헤더 0x1B0 `RA E840 200001` + 비트뱅잉 루틴 0x152BC(읽기)·0x153B2(쓰기) = 직렬 EEPROM [판독만, `01_header_vectors.md`].
- 패스워드 입력 화면은 이번에 재생한 범위(§3 의 [확인] 화면 전부)에서 나오지 않았다 [확인]. 스토리·리그의 이어하기는 둘 다 EEPROM 읽기로 처리된다 [판독만].

| 영역 | RAM 사본 | 크기 | 내용 | 쓰는 시점 |
|---|---|---|---|---|
| 스토리 | `$E5A0` | 8바이트(워드 2~5) | 해금 플래그 1 + 다음 경기 번호 1 + 서명 `DANPEI` 6 | 세이브 창에서 はい [확인 RAM] |
| 리그 | `$E5A8` | 32바이트(워드 6~21) | 설정(팀 수·턴 수·규칙·시간)·참가 팀(bit7 = COM)·대전 결과(니블 압축)·합계 검사값·서명 `DANPEI` | 개막식, 매 경기 후 [판독만] |
- 리그는 1개만 저장된다(영역이 하나) [판독만].
- 자작 에뮬레이터는 EEPROM 읽기를 0 으로만 돌려주므로 つづきから(스토리·리그)는 돌려 보지 못했다. 불러오기 흐름은 [판독만 0x14022, 0x16F6A].

## 5. 개발용(디버그) 기능 — 제품 기능 아님

- `$E6A4` = 디버그 플래그. SEGA 로고 첫 120f 안에 2P 패드로 7단계 입력을 넣으면 켜지고 효과음 0xC2 [판독만 0x2B98, 0x58D8, 입력 순서 미해독].
- 켜진 상태의 일시정지: 1P A = 경기 재시작, 1P B = 선수 파라미터 24항목 뷰어(상태 0x30/0x34, 문자열 0xEA7A 를 쓰는 화면), 1P C = `パターン チェック モード TEAM NO.`(상태 0x18/0x1C), 2P A / 2P C = 1P쪽 / 2P쪽 즉시 승리 [확인: 패턴 체크 화면 `dbg_pattern_check.png`, 즉시 승리] [판독만: 나머지].
- 스토리 はじめから 에서 `ラウンドをえらんでください` 라운드 선택이 뜬다 [확인 `tr_04_special_and_debug_round_select.png`]. 특훈 일시정지에서 2P A = 카운터 채우기 [확인], 2P C [판독만].
- 이번 조사에서 경기 결과를 빨리 내는 데 이 기능을 썼다(RAM `$E6A4`=1 직접 설정).

## 6. '경기 전 팀 소개(에이스·칭호)' 화면 — 재조사 결과

요구된 화면: 팀 엠블럼·팀명·약칭 + 에이스 얼굴·이름 + 칭호(`도내 최강 체력치 보유 (12)` 류) + 6줄 게이지.

확정한 것
1. **0xEA7A 히라가나 라벨은 개발용 파라미터 뷰어 전용**이다. 디버그 플래그가 켜진 일시정지에서 B 로만 들어가는 상태 0x30/0x34 이고, 같은 일시정지의 C 가 `パターン チェック モード` 인 것을 화면으로 봤다 [확인 + 판독만]. 이전 판단(20 문서 §8-1)이 맞다.
2. **5개 모드의 경기 전 화면을 전부 재생했고 그런 화면은 없었다** [확인]. 이번에 추가로 본 곳: 스토리 서브 7(맞대면 대사), 스토리 2전·4전 진입, 리그 서브 0~15 전부, 특훈 전 구간. 20 문서가 "렌더러 한계로 검게 나와 미확인"이라던 리그·특훈 프레임은 윈도 플레인 합성으로 다시 봤다.
3. **능력치 막대 루틴(0xEC2E, 나눗수 표 0xE9CC)의 호출처는 3곳뿐**: 편성 화면 2곳(0x14E84, 0x15274)과 디버그 뷰어(0xE666). 선수 이름 표 0x753FA 를 읽는 코드도 편성(0x1517E 계열)과 디버그(0xEBAE)뿐이다 [판독만, `xref.py`].
4. 스크린샷의 괄호 숫자는 **편성 화면 막대 칸 수 공식**(`2*floor(v/18) + 반올림 1`)과 4팀 모두 일치한다: 115 → 12, 127 → 14, 140 → 15, 144 → 16. 20 문서의 `floor(hp/9)` 추정과 같은 값이며 ROM 근거가 있는 쪽은 이 공식이다 [확인: 계산 대조].

판단
- 원작 메가드라이브 ROM 에는 **독립된 팀 소개(에이스·칭호) 화면이 없다**고 본다. 내용이 가장 가까운 것은 **편성 화면의 COM 보기**(팀 패널 + 고른 선수의 얼굴·이름·6줄 막대)다 [확인 `gfx/prematch/fm_com_view_hover.png`].
- "도내 최강/전국 최강/세계 발군/세계 최강" 같은 **칭호 문구와 '에이스' 지정은 ROM 에서 찾지 못했다**. 편성 화면의 초기 커서는 EXIT 이고 에이스를 자동으로 띄우지 않는다 [확인].
- 스크린샷이 어디서 온 것인지는 알 수 없다(다른 기종판, 한국 정발판 화면, 공략 자료 이미지 가능성 [추정]). 원본 이미지를 받으면 대조할 수 있다.
- 남은 가능성: 스토리 서브 12~21(중간 이벤트·엔딩)은 화면으로 보지 않았다. 다만 막대·이름 루틴 호출처가 없으므로 능력치 게이지가 거기 있을 가능성은 낮다 [판독만 근거의 추정].

### 7-2. 권고 구현 순서
1. 규칙 창(시간) → 2. 라인업 VS → 3. 특훈 캐치 → 4. 특훈 필살 슛 → 5. 리그(혼자) → 6. こうしき 규칙 → 7. 편성 교대 → 8. SPECIAL 해금 → 9. 리그 온라인 확장.

- 구현 전에 필요한 추가 조사: 특훈 단계별 투구 표, 리그 순위 정렬, こうしき 시간 종료 판정. 모두 `t_md_step.py` 로 재생 가능한 범위다. → **2026-11-18 완료: `29_training_league_spec.md`**(조사 결과 + 엔진·서버·클라이언트 구현 명세 초안). 29 문서의 권고 순서는 특훈 캐치 → 특훈 필살 → こうしき → 리그. → こうしき 까지 구현 완료(2026-11-18, 29 §4-1-1), 남은 것은 리그.

## 11. 제한 시간별 캠페인 시뮬 사용법 (2026-11-18, 박백엔 — 임밸런 재측정용)

엔진은 바꾸지 않았다. `Match` 옵션 `limitFrames` 는 §10 에서 이미 들어가 있다(`server/engine/match.js` 91행, 판정 `checkTime` 1896행, 테스트 `test/engine.test.js` "경기별 제한 시간"). 이번에는 측정 도구 두 개가 그 옵션을 받게만 했다. 플래그·환경변수를 주지 않으면 두 도구 모두 종전과 같은 경기를 돌린다.

### 11-1. 제한 시간 규칙 [사실, match.js checkTime]
- `limitFrames` 는 **경기 시계**(`m.clock`, GO 이후 프레임) 기준이다. 60 = 1초, 18000 = 5분(기본, `rules.json time.limitFrames`), 0 = 무제한.
- 시계가 `limitFrames` 에 닿으면 남은 인원이 많은 쪽 승(`timeup`). **동수면 끝나지 않고 서든데스**(다음 아웃이 승패, `sudden_death`).
- 무승부 상한(`draw_cap`, winner -1): 제한 있음 = max(15분, limitFrames), 무제한 = 30분.

### 11-2. 사람 좌석 봇 (문서 26 의 도구, 승률 재측정은 이쪽)
```
LIMIT=10800 node tools/campaign_remeasure.mjs 60 aggr25,aggr50,aggr75        # 3분
LIMIT=28800 node tools/campaign_remeasure.mjs 60 aggr75,aggr100 8 14         # 8분, k8~14
LIMIT=0 JSON=out.json node tools/campaign_remeasure.mjs 60 aggr50            # 무제한 + JSON 저장
```
- `LIMIT` = 프레임. 나머지 인자·환경변수(`FM`, `ENGINE`, `OVLV`, `OVSP`, `JSON`)는 문서 26 §1-3 그대로.
- 도구의 틱 상한이 80,000 이라 `LIMIT=0` 에서 22분을 넘는 경기는 "미종료" 칸에 잡힌다(30분 `draw_cap` 까지 가지 않는다).
- 백업 엔진(`ENGINE=`)이 §10 이전 것이면 `limitFrames` 옵션을 모르므로 `LIMIT` 이 무시된다.

### 11-3. 컴퓨터 대 컴퓨터 (빠른 훑어보기)
```
node tools/campaign_sim.mjs [seeds=40] [botLevel=2] [campaignJson|-] [kFrom=0] [kTo=14] [--limit=프레임] [--nosd] [--even] [--json=경로]
node tools/campaign_sim.mjs 20 2 - 0 14 --even --limit=10800 --json=out.json
```
- `--limit` = 위 `limitFrames`. `--nosd` = 서든데스에 들어가면 멈추고 무승부로 센다(엔진 규칙은 그대로, 집계만). `--even` = 짝수 시드 `1000*(k+1)+2*i`(종전 시드 1..N 은 엔진이 최하위 비트를 버려 절반이 같은 경기다. 새 측정은 `--even` 을 쓸 것). `--json` = 표와 같은 값을 파일로.
- 출력 끝에 `승/패/무 | 평균프레임 | 평균 남은 인원(나:상대)` 열이 붙었다. 무 = `draw_cap` + 미종료(틱 70,000 초과) + `--nosd` 중단.
- 환경변수 `OV`, `FIXBOUNCE` 는 종전 그대로. 한 경기 약 0.2~0.4초(15경기 x 20시드 = 1~2분).
- 좌석0 도 엔진 두뇌라 절대 승률이 아니다(문서 26 T9 설명).

### 11-4. 읽을 때 주의
- 제한을 짧게 주면 "전멸 승부"가 아니라 "그 시점 인원 우세"를 재게 된다. 예: k8 시드 5개, 기본 5분 = 0승 5패(평균 16,726프레임, 남은 인원 0.60:5.20), `--limit=3600 --nosd` = 0승 1패 4무(6.80:7.00). 속도를 위해 제한을 줄인 값을 5분 경기의 승률로 읽으면 안 된다.
- 실제 선택지는 규칙 창의 0/10800/18000/28800 이다. 이 네 값으로 재는 것을 권한다.
