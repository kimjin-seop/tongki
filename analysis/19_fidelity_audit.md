# 19. 원작 충실도 감사 (2026-11-17)

합격 기준: "체감 비슷함"이 아니라 **원작과 동일**(프레임·픽셀·수치 일치). 판정은 아래 "동일성 기준"으로 한다.
표기: **[측정]** = 원작 에뮬(analysis/scripts/m68k.py, 저장 상태 `analysis/state/ctrl0.pkl`)과 우리 엔진(`server/engine`, node 직접 구동·서버 접촉 없음)에서 같은 입력으로 직접 잰 값 / **[문서]** = 기존 analysis 문서(04~17)의 확인값을 재측정 없이 인용 / **[추정]** = 코드·화면 정황 / **[사람]** = 영상 대조 필요.
"68k 직역" = 수정에 원작 68000 로직을 그대로 옮기는 작업이 필요한 항목. (제외 주제: CPU AI, 오프닝/스토리 컷, 효과음 — 3절 "현재 상태 기록"만)

재현 스크립트: `analysis/scripts/audit_oracle.py`(원작 이동·점프·캐치), `audit_throw.py`(원작 투구), `audit_ours.mjs`(우리 엔진), `audit_orig_shots.py`/`audit_shots.mjs`(원작·우리 화면). 캡처: `_verify/audit1/{orig,ours}/`, 나란히: `_verify/audit1/cmp_*.png`.

## 6. 차분 테스트 하니스 설계안
목표: 같은 입력열로 원작 에뮬과 우리 엔진을 돌려 프레임별 상태(선수 14명+공: x,y,z,vx,vy,vz, 타입/서브, 타이머, HP, 남은 인원, RNG)를 비교, 첫 불일치 프레임과 필드를 보고.

구성
1. **원작 쪽 트레이서**(Python, 대부분 존재): `drv.py`+`odump`로 RAM 0xC000+k*0x80(선수 14·공 0xC700)·0xE700/E780(사이드)·RNG 상태를 매 프레임 JSONL 덤프. 입력열(JSON: 프레임별 패드 2바이트) 재생. 신규 작업: 필드 맵 정리, RNG 상태 주소 확정(0x14EA 루틴의 시드 변수), 시작 상태 저장(점프볼 직후 `ctrl0.pkl`처럼 고정). 0.5일.
2. **우리 쪽 트레이서**(Node): `new Match(...)` 후 `tick(inputs)`마다 동일 필드를 같은 스키마로 덤프(`audit_ours.mjs`가 골격). 동일 시작 상태를 만들려면 엔진에 **상태 주입 API**(선수 위치·스탯·소유자·RNG 시드·시계)가 필요. 1일.
3. **입력·좌표 정규화**: 원작 패드 비트(U1 D2 L4 R8 B16 C32 A64 S128)는 이미 우리 BIT와 같음. 좌표는 16.16 정수 그대로 비교(고정소수 일치 요구). 1프레임 입력 지연 규약을 맞춤(우리 엔진이 입력을 다음 틱에 반영하므로 오프셋 정의 필요). 0.5일.
4. **비교기·리포트**: 첫 불일치 프레임, 필드, 차이값, 이후 N프레임 궤적 diff. 시나리오 세트(걷기 8방향, 대시, 점프, 대시점프, 지상/공중 투구, 패스, 캐치, 웅크림, 피격→아웃→교체, 점프볼, 선 이탈, 바운스 스테이지별) 약 15개. 1일.
5. **RNG 일치**: 원작 RNG(0x14EA)를 rng.js가 이미 이식했다고 주석 표기 — 호출 순서까지 같아야 AI·토스가 일치. AI 제외 시나리오(사람 입력만)부터 시작 → 호출 순서 불일치는 2단계에서.
6. **카메라/화면 비교**(선택): 원작 SAT(스프라이트 속성표)와 우리 render 스프라이트 위치 비교. 렌더러가 브라우저 캔버스라 DOM 캡처 후 이미지 diff. 2일.

소요 추정(1인): 이동·점프·투구·바운스까지 비교 가능한 1단계 **약 3일**, 캐치·피격·아웃·교체·점프볼 확장 **+3일**, AI·필살기까지 **+1~2주**. 하니스 자체보다 **불일치 수정(직역)** 이 대부분을 차지한다. 직역 대상 루틴: 0x7A60/0x780E(이동·대시), 0x70E2~0x7166(투구), 0x6D90/0x974C(선 이탈), 0xA428~0xA6C2(공 비행·바운스), 0x85CC(공 줍기·조작 전환), 0x8CF0·0x73AC(캐치), 0x84AC(피격), 0xADB8~(필살기).

권고 순서: 하니스 1단계 → #1 걷기식(즉시) → #4 대시 → #2/#3 투구 → #6/#5 영역 표·선 이탈 → 바운스 전 스테이지.

## 7. 한계(정직한 범위)
- 재측정한 것: 걷기·대시·점프·대시점프·캐치자세 타이머·웅크림·투구(지상) 선딜/초기값·이동 한계. 나머지(피격/아웃/캐치 판정/필살기 궤적/AI/바운스 전 스테이지)는 기존 문서 인용 또는 미측정.
- 원작 측정은 자작 에뮬(`m68k.py`) 결과로, 에뮬 오차 가능성은 낮으나 실기 영상 대조는 하지 않았다.
- 우리 엔진 비교 시 조작 선수를 pid0로 고정하고 점프볼 종료 후 20프레임 대기 상태를 시작점으로 썼다(원작은 ctrl0.pkl, 같은 팀0 슬롯0, s2=16). 시작 위치가 완전히 같지 않아 위치 절대값이 아니라 속도·타이밍을 비교했다.
- 우리 화면 캡처는 headless Edge 1194x672, 원작은 320x224 렌더 3배. 픽셀 diff는 수행하지 않았다.
