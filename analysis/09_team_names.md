## A. 팀 이름

### A-1. 핵심 발견: 이름 텍스트는 ROM 에 있다 [확인]
- `03_graphics.md` 의 "텍스트는 그래픽, SJIS 없음" 은 절반만 맞다. 팀·선수 이름은 **자체 1바이트 문자코드**로 ROM 에 저장돼 있다.
  - 팀 레코드 `0x74F8E + 12*팀` : 약칭 3바이트(ASCII) + 팀명 8바이트 + 1 (0x15072/0x15096 이 읽음)
  - 선수명 `0x753FA + 56*팀 + 8*선수` : 8바이트 x 7명 (0x1517A)
  - 문자 변환 루틴 ROM `0x21C0`(0x1429A 경유): 타일 0x60~=히라가나(あ=0x60 … ん=0x8D), 0x97~=가타카나(ア … ン=0xC4, 소문자 ァ~ョ=0xC5~0xCD), 0x93~0x96=っゃゅょ, 0x1D=ー, 바이트 0x97~0xAF/0xE7~0xFF = 탁점(0xCE)/반탁점(0xCF) 합성.
  - 검증: 팀 선택→라인업(대진) 화면을 에뮬레이터로 띄워 화면 글자와 대조(いちげきだんぺい, たまがわしょう, ギリシャンズ 등 일치). 소문자/장음 코드는 화면 대조로 확정.
- 팀 선택 화면은 **15칸**(3행x5열): `T.D S.A B.A A.T HOK / KYO OKI TOK CHN URS / EGY GRE BRA CHI USA` = ROM 팀 `0 1 3 2 5 / 6 7 4 10 11 / 14 12 13 9 8` [확인: 약칭이 ROM 레코드와 일치, GRE=팀12 는 에뮬 선택으로도 확인]. 팀 15~24 는 선택 불가(스토리 전용).

### B-2. 방식 (stage_00 과 동일 규약 + 보강)
- far = VDP 평면 B(64x12 타일), near = 평면 A(64x28, 색0 투명), flat = far 를 카메라 96 정렬로 깔고 near 를 덮음. world→img 식은 stage_00.json 과 같다.
- **검증**: ROM 로더(0x4DCC/0x4DEA/0x4E82)를 에뮬레이터에서 스테이지 0~13 전부 실행한 뒤 VRAM(타일, 평면 A/B 타일맵)·팔레트와 파이썬 디코드 결과가 **전수 일치**. 기존 stage_00 far/flat 과 픽셀 동일, near 는 알파·불투명 픽셀 동일(투명 픽셀 RGB 만 다름; 기존 파일은 수정하지 않음).
- **스크롤은 스테이지마다 다름(중요)**: stage_00 의 "far 0.75" 는 그 스테이지 한정. ROM `0x2F6C` 가 `$E682` 별 점프표로 계산하고 VDP reg11 은 0(전체)/2(8px 행별)(표 0x48F8, 0x48D8). 행별 스테이지(02,03,04,06,07,12)는 near 상단 행이 0.25/0.5 배로 따로 움직이고 far 는 0.5~0.875. 각 json `parallax.near_rows/far_rows` 에 `shift = 96 + rounding((cam-96)*factor)` 로 기록(cam 0~191 전수 대조 오차 0). 기존 stage_00 json 의 far 0.75 는 정확.
- near 우선순위: 0x5010 이 ROM 스테이지 3,4,7,10(NN 02,06,03,07)에서 평면 A 상단 8행의 우선순위 비트를 해제. PNG 는 우선순위를 담지 않음 [확인(코드·VRAM), 엔진 영향은 미검증].
- 광고판 글자(SEGA)는 stage_00 처럼 near 에 포함(UI 타일 0x593~0x596, 위치 타일 (34,9) 전 스테이지 공통). stage_13 은 위치 미검증으로 생략. 시간제한 규칙에서는 이 자리에 M:SS 타이머가 그려짐.
- 추가 기록: 스테이지별 BGM 명령(표 0x50D2, 대전용), 마찰·바운스.

### B-3. 못 한 것 / 불확실
- 경기 연출 중 카메라 추적 규칙(공 따라감)과 수직 스크롤($E00E) 미분석. x_range [0,192) 는 평면 폭 유도(0x31BE 상한 0xBF 와 일치).
- 코트 선 위치는 stage_00 의 world↔image 식을 그대로 적용(시각 확인만). 판정은 server/data/court.json 사용 권장.
- 팔레트 애니메이션·페이드 여부 미확인(정적 팔레트만).
- 대전 모드의 스테이지가 `$E683`(= `$E682` 워드 하위 바이트 기록) 경로로 적용된다는 해석은 [추정 수준 높음] (스토리 표와 15/15 일치).

### B-4. 문서 정정
- `03_graphics.md` 1-B 의 Enigma 플래그 설명(bit0=vflip, bit1=hflip)은 반대: **헤더 bit1=vflip(0x1000) 비트를 먼저, bit0=hflip(0x800) 를 나중에** 읽는다(flags=3 인 ROM 스테이지 0·6 맵과 VRAM 대조로 확정). `scripts/enigma.py` 는 그대로 두고 `extract_stages.py` 에 교정판 내장.
- `analysis/gfx/preview_stages_16.png` 는 타일맵을 64열 행우선으로 읽는 근사라 실제 배치(32열x28행 두 반쪽)와 다르다.
