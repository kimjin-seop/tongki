# 06. 필살기(특수 공 0x90) 규칙 해독 - 코드 판독 + 자작 68000 에뮬레이터 실행 검증

본인 소유 ROM 의 개인 학습용 분석. 외부 반출 금지. 구현 없음(분석/사양만).
표기: **[확인]** = 코드 판독 + 에뮬레이터 실행으로 일치 확인 / **[코드]** = 코드만 읽음(실행 미검증) / **[추정]** / **[미확인]**.
도구: `analysis/scripts/m68k.py`, `drv.py`, 이번에 추가한 `t_special.py`(ID별 궤적 추적), `t_special_all.py`(전 ID 일괄), `t_special_hit.py`, `t_special_hit2.py`(피격/캐치 판정), `t_special_win.py`(차지 윈도), `t_special_return.py`, `t_special_fx.py`(연출 화면/팔레트).
공통 실험 설정: 상태 `ctrl0.pkl`, 선수 0(팀0 슬롯0, s4=28, s6=88)에게 공을 쥐여 주고 C(점프)→B 홀드→해제. `$E694`(강제 ID, 아래 §1)로 ID 를 지정. 궤적은 "충돌 무시"(공 위험 플래그 $3 bit6/7 을 매 프레임 지워 선수 충돌 제거)와 "z 부스트(+120)"(공을 높이 띄워 지면 착지 전 패턴을 길게 관찰) 두 변형으로 추적. 부스트는 관찰 편의용 실험 조작이며 실제 게임 조건이 아니다.

## 0. 요약
- 필살기는 **ID 0~53 의 54종**, 공 타입 0x90 의 핸들러 0xADB8 이 `ID → 점프표(0xAE0C) → 동작 핸들러`로 처리한다. 동작 핸들러는 **서로 다른 것이 30개**이고 (같은 핸들러를 여러 ID 가 공유), ID 별로 다른 것은 (a) 위력(0x187FA), (b) 시작 효과음, (c) 공 그래픽/스프라이트, (d) 잔상 오브젝트 패턴, (e) 동작 핸들러 선택이다.
- 필살기 공은 **충돌/캐치/피격 규칙이 일반 투구와 완전히 같다**(같은 히트박스, 같은 판정 함수). 다른 점은 ① 위력이 선수 능력치가 아니라 ID 표값 ② 비행 중 궤적이 ID 별로 스크립트화 ③ 방향키 보정(조향) 무시 ④ 벽/바닥에 닿으면 즉시 일반 바운스 공(0x1C)이 됨.
- 궤적은 전부 **"투구 순간의 속도 벡터 V0 를 저장해 두고, ID 별 상태기계가 그 V0 를 배율(1/4, 1/2, 1, 1.5, 2) 또는 가감속하는 것"**이라 웹 재구현이 쉽다. 예외는 루프(sin/cos) 계열(ID 48/49/53) 하나.

## 1. 발동 조건과 공 타입 0x14 → 0x90 전이
### 1.1 호출 위치 [확인]
공중 투구 실행부 0x71BC(= 서브 0x0C "투구 실행", 사람/CPU 공통; 공중/지상 모두 이 경로)에서 일반 투구 값을 모두 계산한 뒤 **0x71F2 에서 `bsr 0x8BEE`** 로 공 타입을 결정한다. 외야 투구(0x9AD2)는 이 판정을 호출하지 않으므로 **항상 일반(0x14)**.
계산 순서(공=$C700, 투구 선수 a0):
1. `$42(공)=$3E(공)`; 위력 `$1A(공)` = 0x89AA: `s4 + (점프중 ? s4/4) + (대시중 ? s4/4) + (차지카운터$18 ≤15 ? $18)`. 실측: s4=28, 차지8 → 43.
2. 속도 `$74(공)` = 0x7D0C: `s6*16 + (점프 0x100) + (대시 0x100) + (차지≤15 ? 차지*16)`. **수평속도(px/frame) = $74/256** [확인: 차지 4/8/12/13/15 에서 $74/수평속도=256.0].
3. 속도벡터 0x7D90: 수평은 목표(`$E21E`) 방향 단위벡터 x $74/256, vz 는 높이차/비행시간으로 계산(0x22DA/0x2254) [코드]. 결과가 `$30/$34/$38(공)` (16.16, px/frame), `$70(공)`=조준 보조값.
4. 0x8BEE 가 타입 결정 → `$3(공)` bit6 set(위험 플래그), bit4 clear(보유 해제), `$52(공)`=투구자 사이드.

### 1.2 0x8BEE 판정표 [확인(★은 에뮬레이션 실측), 나머지 코드]
```
if E697(리그/특훈 플래그)!=0:
     if 투구자 사이드==E700(1P): E69C 0,1,2 -> 일반 ; E69C==3 -> 아래 일반 판정
     (CPU 쪽 또는 E69C==3) -> 아래
if E694(강제ID, 부팅 후 쓰는 코드 없음)!=0 -> 무조건 특수(ID=E694 하위바이트)   # 디버그/치트용 [코드]
if E680!=0 (규칙/제한시간 모드) -> 일반
if 슬롯($1A(a0)) >= 4 (외야) -> 일반
if 공.$76 != 0 -> 특수(ID 유지, §3.3)            # "특수 공을 받아낸 직후" 반격 규칙
★ 차지카운터 $18(a0) 가 (15 - E69E) <= $18 <= 15 이면 특수, 아니면 일반.  E69E=2(부팅 시 0x3D6 에서 2 대입, 이후 쓰기 없음) -> 13,14,15
일반: 공.$76=0; 공 타입 0x14
```
- ★ 차지 윈도 실측(`t_special_win.py`): B 홀드 8~12프레임 → 타입 0x14(위력 43~47), **13/14/15 → 타입 0x90**(태그 22, 위력은 아래), 16 이상 → 자동 발사되지만 카운터 16 이라 **윈도 밖 → 일반 0x14**(위력 35: 차지 가산이 빠짐 = 카운터 ≤15 조건).
- ★ **지상 투구는 항상 일반**: 지상 B 홀드 1~20프레임 모두 타입 0x14, 위력 28(=s4). 차지 카운터가 지상에서는 올라가지 않는다(`$18`=0). 따라서 **필살기 = 점프(C) 후 공중에서 B 를 13~15프레임 누르고 떼기**.
- 리그 모드(E697≠0): ID 는 0x16(22) 고정(0xB810) [코드].
- 규칙 모드 E680≠0: 항상 일반 [코드]. (E680=1 이 시간제한 모드)

### 1.3 ID 결정 0xB7D8 [확인 + 코드]
```
공.타입 = 0x90
if E697: ID=22
else:
   d0 = E694 (강제 ID)
   if d0==0:
        if 공.$40 != 0: ID 유지(공.$14 그대로)   # §3.3 반격 시 이전 ID 유지
        else: d0 = ROM[0x18732 + team*8 + 선수번호($50(a0))]   # team=$4(side), 25팀x8바이트
   if (int8)d0 < 0: d0 = ROM[0xB82E + (rand()&0x1F)]           # -1 = 무작위 32종표
   공.$14 = d0
```
- ★ 실측: 팀0 선수0 → 태그 22 (`special_shots.csv` 0,0,22 와 일치).
- **무작위 풀(0xB82E, 32항목)**: `1,2,4,5,6,8,11,12,13,15,18,20,22,25,26,27,48,49,31,33,34,37,39,40,6,6,43,48,49,51,53,53` (6, 48, 49, 53 은 중복되어 가중치 높음). CSV 에서 -1 은 팀23 선수0(보스급)뿐 [코드].
- 팀23 선수1~6, 팀24 전원은 CSV 상 ID 0, 위력 255: **ID 0 은 점프표에서 "직선 1.5배" 핸들러**, 위력표값 0xFF 는 "덮어쓰지 않음" 이라 위력=일반 투구 계산값 [코드; 팀23/24 로 실행 못 해 미검증].
- 선수번호 = 로스터 번호(0~6)이고 슬롯이 외야(≥4)인 순간엔 특수 불가이므로, 로스터 4~6 번이 내야로 들어왔을 때만 그 번호의 ID 를 쓴다 [코드].

### 1.4 0x90 초기화 (공 핸들러 0xADB8 첫 프레임) [확인]
다음 프레임에 타입 0x90 핸들러가 실행되며 `bset 7,(a0)` 초기화 플래그가 없을 때:
```
$12 = 0xC001 (스프라이트 속성)   ; $3 bit4 clear, bit6 set
a4c0: $6 = 2 (스프라이트 프레임; 조건부 6/8)   ; $1E=0 ; $16(서브)=0
b922: if ROM[0x187FA+ID] != 0xFF: $1A(공 위력) = ROM[0x187FA+ID]       # 위력 덮어쓰기
b856: 효과음 ID = ROM[0xB866+ID] -> 사운드큐(0x16B6)
E26A..E272 = V0 (투구 순간의 $30/$34/$38 3개 long)            # 전역 1개
$76(공)=1
```
- ★ 실측(ID22): 전이 프레임(f0)에 type=0x90,위력=50(일반 계산값),속도 V0=(7.42,0.46,-2.80). f0+1 에서 위력=75, 속도=V0x1.5(11.13,0.69,-4.20).
- 이후 매 프레임: `핸들러[ID]` → 0xBA9C(스프라이트 프레임 $6 선택) → 0xB940(공 그래픽 DMA 선택).
- 방향키 보정(0xA46A, 일반 투구 0x14 는 매 프레임 적용)은 **특수 공 핸들러가 호출하지 않는다** → 특수는 투구 후 조향 불가 [코드, 궤적에 입력 없는 실험만 수행].

### 1.5 비행 종료 공통 처리 0xA728 [확인]
모든 ID 핸들러는 마지막에 공통 이동 루틴을 호출한다.
```
facing 플래그(x,y 속도 부호)            # 0xA85C
pos += vel   (x,y,z 각각 16.16)         # 0x1B26  (※ 중력 없음. 필살기는 vz 를 핸들러가 직접 조작)
벽 처리 0xA7EA: x<0x10 -> x=0x10, vx=-vx/4 ; x>=0x1F0 -> x=0x1F0, vx=-vx/4
                y<0x10 -> y=0x10, vy=-vy/2 ; y>=0xF8 -> y=0xF8, vy=-vy/2 ; (닿으면 플래그)
플래그면 타입=0x1C(바운스 공)            # 필살기 종료
z >= 0x180 -> vz=0, 타입=0x1C
z <= 0 (착지) -> 위험플래그(bit6)가 서 있으면 vx/=2, vy/=2, vz=+2.0, z=0, 타입=0x1C  # 0xA7CC
```
★ 실측: ID8 이 x=496(0x1F0)에서 타입 0x1C, vx=-1.855(=-7.42/4); 지면에서 vx/2, vz≈+2 로 바운스. **즉 필살기는 벽/바닥에 닿는 순간 끝나고 일반 바운스 공(핸들러 0xA54E)이 된다(위력 `$1A`와 태그 `$14`는 그대로 남음)**.

- **잔상/분신 오브젝트(타입 0x84, 핸들러 0xA8EC, 위치 `$CB00`부터 0x80 간격 최대 4개)**: ID 별로 개수·패턴(`$1A`)이 정해지고 매 프레임 공(`$C700`) 기준으로 자기 위치를 덮어쓴다. 공이 0x90 이 아니게 되면 0xB914 검사로 전부 삭제(0xAD9E) [★ `t_special`로 ID 별 생성 확인]:

  |---|---|---|
  | 0x00 | 위치 이력 버퍼 `$F000`(프레임별 6B)으로 꼬리 따라오기 | 사용처 미발견(0xAD7C 가 4개를 만드는 루틴은 호출처를 못 찾음) [미확인] |
  | 0x04 | 이력 `$F018`(과거 위치) | 26 (1) |
  | 0x08 | 공 위치/속도를 4프레임 앞으로 진행한 위치(앞서가는 분신) | 27 (1) |
  | 0x0C | x,y=공, z=공z+rand(0..15) -> 상하 떨림 | 3,47,51 (1) |
  | 0x10 | x,y,z 각각 ±rand(0..15) 랜덤 지터 | 31,35,37,40 (3) |
  | 0x14 | y 오프셋 표 0xAB1E(-16,+16,...)로 좌우 분신 | 32 (2) |
  | 0x18 | z 에 sin(t)>>4 (t+=0x40/f) 상하 진동 | 20,50 (1) |
  | 0x1C | z 에 sin>>6 (작은 진동) | 21 (1) |
  | 0x20 | x=cos>>4, z=sin>>4 원운동(반경 약 16) | 1 (1) |
  | 0x24 | 위와 같되 >>6(반경 약 4) | 2 (1) |
  | 0x28 | 공 속도의 -1/2 로 거꾸로 움직이는 거울 분신(n+1 스텝 진행) | 25 (3) |
  | 0x2C | 0x28 과 같되 매 프레임 x 플립 | 미사용 |

- **보조 이펙트**: 타입 0x78 (`$C900`, `$14=4` → 0xE328): ID 8/15 의 "정지" 구간에서 생성, 공이 0x90 인 동안 공 x,y 를 따라 그려지는 애니(0xE366 표) = 다이빙 착지 점멸 [코드+★생성 확인]. 같은 오브젝트 `$14=0`(0xE2E6)은 캐치 후 미끄럼(서브 0x20) 중 선수 발밑 먼지 [코드].

## 7. 확정/미확정 정리
### 확정 [확인]
- 발동: 점프(C)+공중 B 차지 13~15프레임(15-E69E..15, E69E=2)에서 해제, 지상 투구는 불가, 외야/규칙모드(E680)/리그(ID22 고정) 예외, 반격 글로우 규칙 일부(poke 검증).
- 전이: 0x14→0x90, ID=ROM[0x18732+team*8+선수] (-1=랜덤풀), 위력=ROM[0x187FA+ID] 로 덮어씀(투구 직후 프레임), V0 를 `$E26A` 에 저장하고 1.5배 등 배율 적용.
- 궤적: 54 ID → 30 핸들러, 전 분류에 대해 에뮬레이터 궤적으로 배율·타이밍 확인(ID 1~53 일괄 추적; 1,2,3,5,20,21,22,26,27,30~32,35,37,40,47,50,51,52 는 "등속" 계열이라 변화 없음을 확인).
- 비행 종료: 벽/바닥/천장 닿으면 0x1C 로 전환.
- 충돌/데미지/캐치: 일반 투구와 동일(데미지 = 위력-방어, HP 98→30 실측), 캐치 시 밀림 = min(위력,60)+8 px.
### 미확정 [미확인/코드만]
- 투구 속도벡터 vz 의 정확 식(0x7D90/0x22DA/0x2254), sin/cos 테이블 진폭(루프 반경 ±30px 는 관측치).
- 팀23(보스)·팀24 의 ID 0/랜덤 풀 실제 동작(해당 팀을 에뮬레이터로 세우지 않음).
- [해결 2026-11-18] 반격 규칙의 자연 발생 재현은 §3.3 에서 확인. 남은 것: 벽·바닥에 닿은 뒤(0x1C, `$76`=1)의 캐치, 받아치기 창이 열린 채 차지 필살(컴퓨터 지상 차지 15, 0xCC56)을 던질 때의 ID(0xB7EC 가 `$40`≠0 이면 공에 남은 `$14` 를 쓴다 [판독만]). §3.3 의 'CPU 의 캐치 확률'(0xD560~D5C2)은 캐치가 아니라 **공을 잡은 뒤 즉시 투구할지의 판단**이다(`$40`=받아치기 창, `$42`=잡은 공의 차지, analysis/25 §7).
- 잔상 패턴 0x00/0x10 의 일부 사용처, 0xAD7C 호출 경로.
- 이름 대응 전체(§5)는 추정.
- 사람 대 사람(2P) 시 필살기 입력 차이/사이드 미러(0x4C28 등), 규칙 모드 E680=1 실행 검증.
- 점프볼/외야 슬롯 4~6 번 선수의 내야 진입 시 ID 사용(코드만).

## 8. 재구현 난이도 평가
- **난이도: 낮음~중간.** 발동 조건·위력·충돌·캐치는 일반 투구 엔진을 그대로 쓰면 된다(추가 규칙은 "차지 13~15 → 필살", "위력=ID 표", "캐치 시 밀림=min(위력,60)+8", "벽/바닥에서 종료").
- 궤적은 30개 핸들러가 모두 `V0 배율 + 단순 가감속 + 타이머` 라 각각 5~15줄. 유일하게 번거로운 것은 루프 계열(ID48/49/53, sin/cos 위치 덮어쓰기)이며 근사식으로 충분.
- 가장 큰 불확실성: ① 투구 수직 속도(조준) 식 — 일반 투구 엔진과 공용이라 이미 필요; ② 연출(그래픽 불타는 공, 분신, 효과음 10종) — 서버 판정과 무관, 클라이언트에서 에셋 대체 가능; ③ 한국판 이름 매핑 — 추정뿐.
- 서버 부하: 궤적은 공 1개 상태만 갱신하므로 무시할 수준.
