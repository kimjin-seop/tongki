# 10. 부팅 인트로(오프닝 데모)·타이틀 로고·타이틀 메뉴

표기: [확인] = 자작 에뮬레이터 실행(상태/VDP 로그 + 렌더 PNG 육안 확인), [코드] = 디스어셈블만 읽음, [추정] = 정황.
프레임 f = **리셋 직후부터 센 프레임**(NTSC 60fps, 무입력 실행 기준). 화면 320x224(H40).
스크립트(cwd=프로젝트 루트, `python -I`):
- `analysis/scripts/t_intro.py <outdir> <N> [every] [입력]` : 상태($E600/$E400/$E402) 변화·사운드 명령 로그 + 주기 캡처. 입력 형식 `"프레임:버튼마스크:길이,..."`(START=128, DOWN=2).
- `analysis/scripts/t_intro_rec.py <out.pkl> <N>` : 프레임별 VDP 상태(reg/CRAM/VSRAM/VRAM) 기록.
- `analysis/scripts/intro_lib.py` : 기록에서 플레인 A/B·스프라이트 레이어 분리 렌더, 스크롤, 팔레트 페이드 판정.
- `analysis/scripts/t_intro_extract.py <rec.pkl>` : 에셋·타이밍 추출(아래 §6). 기록은 `t_intro_rec.py ... 2900` 으로 다시 만들 수 있음(약 2분).

## 3. 장면별 구성 상세
### 3-1. 타이틀 로고 구조 [확인]
로고는 3레이어 합성:
1. **불꽃**(플레인 B, 불꽃 폭발 마지막 셀과 동일) — 뒤
2. **"ドッジ弾平" + 불꽃 일부**(플레인 A, 세로스크롤로 위치 조정)
3. **"炎の闘球児"**(스프라이트 팔레트 라인1, 4조각) — 앞

| 상태 | A 세로스크롤(Av) | B(Bv) | 소로고 스프라이트 좌상단 | 로고 합성본 화면 좌상단 |
|---|---|---|---|---|
| 인트로(f650~2828) | −24 | 0 | (52,52) | **(34,36)** |
| 최종 타이틀(f2845~) | +8 | +32 | (52,20) | **(34,4)** |
합성본 크기 254x124(불꽃 상단 ~ "ドッジ弾平" 그림자 하단). 플레인 A 136행 이후는 메뉴 패널(파란 상자 + GAME/OPTION/저작권 글자)이라 로고 추출에서 제외.
배경 파랑 #246CFC(CRAM 0x0E42 계열, MD 3비트 → ×36). 로고 원본 팔레트는 빨강 본체 + 검정/짙은빨강 입체 그림자 + 흰 하이라이트, 소로고는 노랑 글자 + 검정 외곽 + 주황 불꽃.

### 3-2. 와이프(장면 4) [확인]
- 흰 가로선(플레인 A 라인스크롤 + 스프라이트)은 오른쪽에서 왼쪽으로 쌓이며 y42~156 범위, f612 에 y32~159 를 덮는 흰 띠 완성(스프라이트 67개).
- 정확한 재생 데이터: `intro_timeline.json` → `tracks.wipe_spans`(f564~650, 프레임별 [y, x0, x1, 색] 가로 띠 목록). 이것만 그대로 사각형으로 그려도 원본과 같은 모양이 나온다.
- 띠 아래 로고는 f612 이후 이미 그려져 있음 → 웹은 로고 레이어를 f612 부터 보이게 두고 띠를 위에 그리면 된다.

### 3-3. 띠 장면(6·8) 라인스크롤 [확인]
- 띠 = 플레인 B 의 화면 y64~159(96행), 그 밖은 검정. 그림은 512px 가로 반복.
- 라인마다 속도가 다름: 불꽃 띠는 y64 −12px/f … 중앙(y≈112) ≈0 … y159 ≈ −12px/f(가운데가 느리고 위아래로 갈수록 빠른 V자, 대략 |y−112|/4 px/f), 청록 띠는 같은 모양에 방향만 반대(+). 정수 속도가 아닌 라인은 두 값이 번갈아 나옴(소수 속도) → json `lines[].vx_avg`(평균 px/f)와 `x0`(시작 오프셋) 사용.
- 화면 x = 띠그림 x + h(y), h(y) = x0 + vx_avg·(f − f0), 512 로 나머지.
- 잔상 선: 1행 스프라이트(팔레트 0) 18종, 프레임별 위치는 `tracks.streaks_fire / streaks_cyan`(그대로 재생 가능). 규칙으로 만들려면 [추정] 오른쪽 밖(x≈232~304)에서 생성돼 빠르게 왼쪽으로 사라지는 짧은 선을 프레임당 2~10개.
- 장면 6 의 띠 색 깜빡임(f1168~1250, 검정/회색/빨강/흰색이 1~3f 씩)은 팔레트 교체 → 웹은 `frames[].band` 값(화면 (2,100) 픽셀 색) 또는 `fade` 로 재현하거나, 띠 이미지에 1~3f 간격 밝기/색 필터 플리커로 근사 [추정 근사].

### 3-4. 팔레트 효과(페이드/플래시/실루엣) [확인]
`intro_timeline.json frames[]` 에 프레임별 팔레트 라인 0~3 의 `fade=[모드,k]` 기록(기준 = 장면 정상 팔레트). 모드 white = 흰색 쪽으로 k 만큼, black = 어둡게 k 만큼, other = 단순 보간으로 설명 안 되는 교체(플래시·색 순환).
- 흰색 페이드아웃(장면 6 끝 f1313~1337, 장면 8 끝 f2383~2407): 약 4f 간격 단계로 24f 동안 k 0→1.
- 타이틀 페이드인(f2514~2538): 흰색에서 4f 간격 7단계, 약 24f.
- 라이벌 실루엣: 일러스트 라인(1~3)이 black k=1 → f1745~1826 에 k 1→0(약 3f 간격 단계).
- 로고 플래시(f744~831): 로고 라인 "other" 0.3 — 글자 본체가 흰색·하늘색 계열로 바뀌는 교체. 웹은 `intro.logo.flash` 이미지로 바꿔 끼우면 됨.

## 7. 웹 구현 사양 (제안, 60fps 틱, 320x224 논리 해상도 × 정수 배율, `image-rendering: pixelated`)
### 7-1. 레이어 스택(아래→위)
0 백드롭 단색(`frames[].bg`) → 1 띠/플레인 B(불꽃 폭발, 띠, 로고 불꽃) → 2 플레인 A(일러스트, 로고 본체, 와이프 흰 선) → 3 스프라이트(불덩이, 소로고, 공, 잔상, 와이프 띠) → 4 페이드 오버레이.
페이드는 원본이 팔레트 연산이므로 웹 근사: white k = 레이어 위에 흰색 사각형 알파 k(`mix`), black k = 검정 알파 k. 실루엣은 일러스트를 `brightness(0)`(검정 채움) 후 k 에 따라 `brightness(1−k)` [추정 근사, 원본은 색별 단계 감산이라 중간 단계 색감이 약간 다름].

### 7-3. 인트로 → "로고와 함께 로비" 전환 사양(제안)
- 원본 타이틀의 마지막 동작(로고가 2px/f 로 32px 상승 후 메뉴 등장)을 그대로 로비 전환으로 쓴다: 로고 상승이 끝나는 프레임에 로비 UI(모드 버튼들)를 아래에서 페이드/슬라이드인(16f 정도).
- 로비에서 로고 위치: 논리 화면 (34,4) 기준 254x124 = 화면 폭의 79%. 로비가 더 넓은 레이아웃(예: 1280x720)이면 정수 배율 2x(508x248) 또는 3x(762x372) 로 상단 중앙, 상단 여백 = 로고 높이의 0.1 배.
- 로고 대기 연출(원본엔 없음, 선택): 불꽃 레이어만 flame_burst 셀 10~12 를 6f 씩 반복하면 원본 불꽃 애니와 같은 리듬으로 살아있는 타이틀을 만들 수 있다.
- "PUSH START" 대체 문구는 32f 표시/32f 숨김(원본 리듬) 권장.

### 8-1. 원본 추출본 사용 범위
- `intro.logo.*` 는 원작 상표/저작권 그래픽 그대로다. 개발 중 위치·크기 잡기용 **플레이스홀더**로만 쓰고, 공개 빌드에서는 새 로고로 교체해야 한다(라이선스 메모: 공개 전 확인 항목).

## 9. 못 한 것 / 불확실한 것
- 소리: ID 와 시점만. 실제 음색·곡 확인 안 함(UNVERIFIED). 0x8A 가 BGM, 0xE1/0xE3 의미는 [추정]. 무입력 타이틀 도달(f2844) 때 코드상 0xE1/0xE3 송신 경로가 있으나 큐 등록이 관찰되지 않음 — 이유 미확인.
- 어트랙트 데모 종료 조건: 3600f 일치로 판단, 종료 코드 미확인. 데모 경기의 팀/스테이지 선택 규칙 미분석.
- 장면 6 띠 깜빡임·로고 플래시는 팔레트 교체라 웹에선 근사(fade 데이터·플래시 이미지). 원본과 색 단계가 완전히 같지는 않다.
- 공 시트 초반 셀(0~8)은 화면 오른쪽 밖(x>384) 부분이 잘린 채 추출됨 — 화면에 보이는 부분은 정확.
- 렌더러는 Window 플레인·Shadow/Highlight 미지원이나, 인트로 전 구간에서 해당 기능 사용 없음(reg12 bit3=0, reg17/18=0) [확인].
- 장면 6 의 플레인 A 가 일부 프레임에서 위/아래 라인 h 값이 1~2px 다름(갱신 타이밍 차이로 추정). 무시해도 화면 차이 미미.
