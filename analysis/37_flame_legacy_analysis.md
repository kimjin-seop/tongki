## 0-1. 핵심 결론 (10줄)

1. 엔진 진입점은 하나다: `Match` 생성자 옵션(`server/engine/match.js:45`). flame 은 `Match({flame:{...}})` 옵션 하나로 넣고, 주지 않으면 모든 훅이 건너뛰게 하면 기존 모드·하네스가 바뀌지 않는다(특훈 `training`, こうしき `ruleMode` 가 이미 같은 방식).
2. 능력치 주입 지점은 `makePlayer(seat, idx, st)` (`match.js:258~269`)다. `st` 는 전역 캐시 객체이므로 **flame 값은 복사본으로만 넣어야 한다**(직접 고치면 같은 프로세스의 다른 경기·스토리가 오염된다, [확인]).
3. **원작 선수당 필살기는 1개다**(기획 "선수별 기존 2개"와 충돌). 필살기 ID 는 0~53 의 **54종**이고 "32"는 무작위 풀 항목 수(중복 제거 27종)다.
4. **필살기 위력은 표값으로 덮어쓴다**(`match.js:1163~1164`): 공격력(s4)·점프·대시·차지 보정은 필살기에 들어가지 않는다 → 공격력 장비와 필살기 위력 장비는 중복 보정이 생기지 않는다. 예외 = 표값 255(ID 0·16·30·32·38·46·47)는 일반 계산값을 쓴다 → flame 필살기 후보에서 빼야 한다.
5. **기획의 필살기 계열(불꽃/도끼/회전/속구/특수 궤적/강위력)은 기존 데이터에 필드로 없다.** ROM 궤적 핸들러·위력표·확정된 슛 이름으로 매핑할 수는 있으나 불꽃=2개(22·25), 도끼=1개(11)뿐이다(§2.4).
6. **"이동속도 상한 3.0px/f"는 사람 조작 선수의 대시 상한뿐이다**(`match.js:1011~1013`). 걷기 속도식(`1+s2/16-2×마찰`)에는 상한이 없고, 컴퓨터형 빠른 이동(동료 AI 포함)은 원작부터 `s2/16+3` px/f 로 3.0 을 넘는다. s2 +1 의 실제 효과는 걷기 +0.0625px/f, 대시 가속 +1/512 px/f² 로 매우 작다.
7. R1(넉백)·R2(캐치 밀림)·R3(쓰러짐)은 각각 한 지점에서 걸 수 있다: `hitPlayer` 넉백 속도(`match.js:1902~1911`), 캐치 밀림 시작 속력(`match.js:1864`, 단계 처리 `689~705`), 쓰러짐 타이머(`match.js:658`/`663`, 값 `rules.json hit.downFrames=60`).
8. **드림팀(여러 팀 선수 혼합)은 지금 엔진·클라이언트가 지원하지 않는다**: 몸통 클래스(히트박스·손 위치)·필살기 표·스프라이트 시트·HUD 얼굴·말풍선 문구가 전부 "좌석의 팀 id + 선수 idx"로 찾는다(§2.10). 선수마다 출신 `{team, idx}` 를 들고 다니는 확장이 필요하다(엔진 4곳 + 클라이언트 5곳).
9. **포메이션은 팀마다 1개 고정(ROM 표 15종)이고 능력치 효과가 없다.** 고르는 UI·전술 태그·"포메이션 보너스"는 전부 신규다. 포메이션 패스는 8px/f 고정이라 패스 속도(s7) 보너스가 닿지 않는다.
10. 경기 중 소모품: 입력 8비트가 전부 쓰이고(`input.js` KEYMAP, S=128 이 포메이션), 서버 일시정지는 끊김 일시정지뿐이라(사용자 일시정지 없음) **경기 전후 사용만 가능**하다(기획 §9.1 초기안과 일치).

### 2.1 선수 데이터 로드·능력치 주입 위치

### 2.3 투구 위력·속도 계산과 중복 보정

- 직역 투구(`romThrow`, 1131~1172, 일반 경기 기본 경로):
  1. `power = s4 + (공중? s4>>2) + (대시? s4>>2) + ch(≤15, 16 자동발사는 0)`, `spd = s6<<4 + (공중? 0x100) + (대시? 0x100) + ch<<4` (1134~1136).
  2. 받아치기 창이 열려 있으면 `power = b.cpow; spd = b.cspd`(잡은 공 값 승계, 1137).
  3. 필살기면 `power = specials.power[ID]`(255 면 그대로) — **덮어쓰기**(1163~1164). 속도는 2단계 값이 V0 가 되고 ID 별 배율(special.js) 적용.
- 결론 [판독]: **공격력(s4)·점프/대시/차지 위력 보정은 필살기 위력에 들어가지 않는다.** 따라서 "공격력 +N"과 "필살기 위력 +N"은 서로 다른 공에 걸려 중복되지 않는다. 투구 속도(s6) 보정은 필살기에도 들어간다(V0 경유) → "투구 속도 +N"은 일반·필살 모두에 효과.
- flame 위력 가산 순서 권고 [자작 제안]: `최종 위력 = (일반: 1단계 식 | 받아치기: 잡은 공 위력 | 필살: 표값) + 조건부 가산(§2.12)`. 받아치기 공에는 원래 던진 쪽 가산이 이미 들어가 있으므로 **받아치기에는 가산하지 않는다**(같은 공이 오갈 때 누적 방지).
- 위력이 쓰이는 다른 곳(기획에 없던 부수 효과): 넉백 속력 = 위력/16(1905), 캐치 밀림 = (min(위력,60)+8)/16(1864, 60 상한), 피해. → 위력 장비는 상대를 더 멀리 날리고, 상대가 잡았을 때 내 쪽이 아닌 **상대가 밀리는 거리**를 60 까지 늘린다.
- 표값 255 인 ID(0,16,30,32,38,46,47)는 일반 계산값을 쓰므로 공격력이 들어간다 → flame 필살기 후보에서 제외 권고(§2.4).

### 2.5 필살기 잠금 구현 지점

- 결정점은 두 함수뿐이다 [판독]:
  - `specialReady(p, charge, air, auto, counter)` (1065~1079): 발동 여부. 검사 순서 = 활성·외야(1067) → 캐치 특훈(1068) → 강제(1069) → こうしき(1070) → **받아치기 `counter` → true**(1076) → 공중 차지 13~15(1078).
  - `pickSpecialId(p, keepId)` (1050~1059): 특훈 22 고정 → 강제 ID → 받아치기 ID 유지 → `specials.row[좌석 팀][p.idx]`(-1 = 풀).
- 호출: `romThrow` 1161(직역, 일반 경로), `doThrow` 1111(비직역·폴백). 컴퓨터도 같은 함수를 지난다(ai.js 는 `beginWind` 로 투구만 시작).
- flame 잠금 권고 [자작 제안]:
  - `specialReady` 의 こうしき 검사 바로 다음에 `if (this.fl && p.seat === this.fl.seat && !this.fl.canSpecial(p, counter)) return false;` 한 줄. false 면 こうしき 와 같이 **차지 위력·속도 가산은 남는 일반 슛**이 된다(원작 규칙 모드 동작과 같은 형태).
  - `pickSpecialId` 에서 flame 좌석이면 `row` 대신 그 선수의 장착 슬롯 ID 를 돌려준다(받아치기 keepId 는 그보다 먼저 유지).
  - 상대(컴퓨터 좌석)는 잠그지 않는다(기획 "통키를 포함한 모든 선수"는 내 팀으로 해석, §3-C3).
  - 장착·해제 즉시 갱신(§12.6): 경기 밖에서만 바뀌고 경기 시작 때 옵션으로 확정 → 경기 중 변경 없음.

### 2.6 R1·R2·R3 적용 지점과 방법

| 확장값 | 적용 지점 | 방법 [자작 제안] | 원작 동작 보존 | 수준 |
|---|---|---|---|---|
| R1 넉백 저항 r(0~0.60) | `hitPlayer` 직역 분기 1904~1906 `v = romDecomp(…, (b.power<<4)&0xffff)` → `q.vx=v[0]; q.vy=v[1]` / 비직역 1909 | 맞은 선수가 flame 좌석이면 `v[0]·v[1]` 에 `(1000 - r‰)/1000` 을 곱하고 0 방향 내림. `knockVz`(4.0)·쓰러짐 시간은 그대로 | 공의 튕김 `b.vx = -(v[1]>>3)`(1907)은 **줄이기 전 값**으로 계산(공 궤적은 원작대로) | [판독] |

- R2 대안: "거리"를 기준으로 줄이려면 감속을 `1/(1-s)` 배로 키우는 방식(시간·거리 모두 ×(1-s))도 가능. 기획 문구 "이동 관성 또는 밀림을 빠르게 줄인다"에 더 가깝다. 어느 쪽이든 한 줄이라 바꾸기 쉽다(§3-C8).
- R3 은 HP 0 으로 쓰러진 경우 **아웃 확정이 빨라질 뿐**(아웃 판정은 쓰러짐 끝, 680)이라 부작용 없음. 외야 슬롯 선수는 HP 가 줄지 않지만 쓰러짐은 있다.

### 2.7 20초 강제 투구 유지

- `match.js:829~835`: 공 보유 중 매 프레임 `++p.hold > R.holdMaxFrames(1200)` 이고 차지·투구 동작이 아니며 서기·대시·제동·점프 상태면 강제 투구(차지 0). 받아치기 창과 겹치지 않음(1075 주석) [판독].
- flame 은 이 코드를 건드리지 않는다. 보유 시간을 늘리거나 줄이는 아이템은 기획에 없다. 검증: §5 표 16번.

### 2.8 이동속도 상한 3.0px/f

- 원작 규칙의 실제 범위 [판독]: **사람 조작 선수 대시만** 3.0 상한(1012~1013 `M.dashMax` 196608). 걷기(976)는 `1 + s2/16 - 2×마찰`, s2 최대 23·마찰 0x2000 → 2.19px/f. 3.0 에 닿으려면 s2 ≥ 36(마찰 0x2000 스테이지 기준).
- 컴퓨터형 이동(상대 컴퓨터, 내 팀 비조작 동료)은 원작부터 `빠른 이동 = s2/16 + 3`(ai.js:72, s2=16 이면 4.0px/f), 아웃 이동도 같은 식(635). 비직역 컴퓨터 대시 상한 `rules.cpu.dashCapPx` 3.5 는 [추정] 값.
- 권고 [자작 제안]: (1) 사람 대시 상한 3.0 그대로. (2) flame 좌석의 사람 걷기 속도를 `min(walk, dashMax)` 로 자른다(지금 범위로는 거의 닿지 않음). (3) 컴퓨터형 이동 식은 원작 보존(건드리지 않음). (4) UI 의 "효과 낭비" 표시는 **걷기 기준**: `1+(s2/16)-2×마찰 ≥ 3.0` 이 되는 s2 부터 회색. 대시 최고속은 s2 와 무관하다는 사실을 장비 비교에 숫자로 보여 주는 편이 정확하다(대시 도달 프레임 수).
- 결론: 기획의 "s2 +1~+2 장비"는 체감이 매우 작다(걷기 +0.06~0.13px/f). 밸런스 데이터(임밸런)가 판단할 사항으로 남긴다(§3-C6).

### 2.9 HP 경기 간 유지

- 현재: `makePlayer` 가 언제나 `hp: st.hp`(263). 경기가 끝나도 선수 HP 를 바깥에 돌려주는 경로가 없다(`game_end` 에 HP 없음, roomGame.js:135~138).
- 방안 [자작 제안]: 옵션 `flame.roster[i].hp`(시작 HP) + `stat.hp`(최대 HP). 종료 시 `RoomGame.finish` 에서 `match.players` 의 flame 좌석 `hp` 7개를 결과(`res.flameHp`)에 실어 `lobby.onGameEnd` → flame 종료 처리가 저장.
- 주의 [판독]: 아웃된 선수는 HP 0 으로 외야에서 계속 뛴다(외야는 피해 없음, 1889). 시작 HP 0 인 선수를 내야에 세우면 한 번 맞는 순간(피해 0 이어도) 쓰러짐 끝에 아웃된다(680). → 경기 사이 HP 0 처리 규칙이 필요하다(§3-C12).
- HP 30% 조건(P08)·치사 생존(P10)은 최대 HP(`p.stat.hp`)·현재 HP(`p.hp`)로 판정 가능.

### 2.10 참가 인원·교체·"선수 7명" 매핑과 혼합 로스터

- [판독] 한 좌석 = 7명, 선수 idx → 시작 슬롯 `[0,1,2,3,4,7,10]`(10행): idx 0~3 내야, 4 상단 외야, 5 하단 외야, 6 후방 외야. **idx 0 = 점프볼 참가자**(117행), 포메이션 패스는 슬롯 0 부터 순환.
- 교체: 수동 교체 없음. 내야 선수가 아웃되면 살아 있는 외야(슬롯 번호 순)와 슬롯을 맞바꾼다(1929~1939). 아웃된 선수는 외야로 가서 계속 뛰고 맞아도 HP 가 줄지 않는다. `remaining`(7)이 0 이 되면 패배.
- 기획 "선수 7명" = 엔진 7명과 그대로 맞는다. **경기 전 순서(라인업)가 곧 내야/외야 배치**다. `prematch.js` 는 "교대(포지션 변경)는 서버가 선수 순서를 받지 않아 아직 없다"(3행) → flame 은 순서를 서버 옵션으로 넘기면 된다.
- **혼합 로스터(여러 팀 선수) 문제** [판독] — "좌석 팀 id + idx"로 찾는 곳:

### 2.13 상대 팀(15팀 + SPECIAL)·난이도

### 2.14 경기 중 소모품 불가 전제 확인

- [판독] 입력 비트 0~255 의 8비트를 전부 쓴다(방향 4 + B·C·A + S=128 포메이션, input.js KEYMAP·PROTOCOL §5.2). 남는 비트가 없다.
- 서버 일시정지는 연결 끊김 때만(roomGame.js:68~87). 특훈의 그만두기 창도 "서버 일시정지가 없어 경기가 흐른다"(HANDOFF §4-7).
- 원작 일시정지 메뉴(서브 0x04)는 웹에 없다.
- 결론: **경기 중 사용은 새 메시지·일시정지 설계 없이는 불가**. 기획 §9.1 "초기 버전은 경기 전후 사용"과 일치. 게임패드는 현재 미지원(키보드·터치만, HANDOFF §4 큐 메모).

### 2.15 전투 시작·종료 흐름과 저장 (flame 이 끼울 자리)

- 비공개 방 처리: `roomListMsg` 필터(455), `set_team`/`start`/`set_rules` 거절(539·552·573), 클라이언트 `room_joined{room.league}` 대기실 생략(main.js:118), `room_left` 때 리그 메뉴 복귀(133).

- 서버 재시작: 방·경기는 메모리라 사라진다(README). flame 도전 상태는 DB 에 있으므로 "경기 노드 진행 중" 상태를 저장해 두면 이어하기 가능(§3-C18).

## 8. 사용자 결정이 필요한 항목

권고안으로 진행해도 되돌리기 쉬운 것은 §3 표의 "되돌리기" 열로 처리한다. 아래는 게임의 성격이 바뀌어 **사용자 확인이 필요한 것**만 추린다.

1. **C1 필살기 2슬롯 발동 규칙**: 권고 = 경기 중에는 주 슬롯 1개만 발동(원작처럼 선수당 1개), 슬롯 2 는 예비. 대안 = 차지 13 / 14~15 로 나눠 두 개 모두 쓰기(원작 타이밍 감각이 바뀜).
2. **C2 필살기 계열 매핑**: §2.4 표(불꽃 2·도끼 1·회전 5·속구 12·특수 궤적 27, 강위력 = 위력 ≥70 태그)로 확정할지. 불꽃·도끼가 1~2개뿐이라 A01·A02 는 사실상 "통키·장도끼 슛 해금"이 된다.
3. **C4 슛 장착 범위**: 해금 계열의 슛을 아무 선수에게나 장착 가능(권고)할지, 그 슛을 원래 가진 선수만 쓸 수 있게 할지.
4. **혼합 드림팀(§2.10)**: 여러 팀 선수를 한 팀에 섞는다(엔진·클라이언트 확장 필요, 유니폼 색은 출신 팀 그대로)로 진행할지. 시작 선수 7명은 태동(팀 0)으로 할지.
5. **C12 HP 0 선수의 다음 경기**: 권고 = HP 1 로 출전(휴식·드링크로 회복).
6. **C18 끊김·기권·서버 재시작**: 권고 = 기권·유예 초과 = 패배(도전 종료), 서버 재시작 = 재경기, 무승부 상한 = 패배.
7. **포메이션 태그(§2.11)**: 15패턴의 6태그 배정이 원작 근거가 없는 자작이라 확인 필요.
8. **[수치 미정] 목록(§7)**: 임밸런 초안을 받아 확정할지, 사용자가 직접 정할지.
