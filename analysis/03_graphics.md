# 03. 그래픽 데이터 분석

상태: **압축 타일 포맷 2종(타일: 허프만+니블 런, 타일맵: Enigma 계열)과 RLE 타일맵 포맷 1종을 코드에서 역분석해 파이썬으로 구현·검증 완료.**
표준 포맷(Kosinski/Nemesis/Enigma/LZ)과의 관계: 타일 압축은 Nemesis 와 유사한 "허프만 코드 + (니블값, 반복횟수)" 구조지만 **표준 Nemesis 가 아님**(길이 기반 8비트 룩업, escape 6+7비트, 헤더 비트15=행XOR). 타일맵 압축은 **Enigma 와 사실상 동일**(0x1356).

## 1. 포맷

### 1-A. 타일 압축 (0x1126 = VDP 직접 전송, 0x1138 = RAM 출력) — 스크립트 `scripts/gfxdec.py`
```
u16 헤더   : bit15 = 행 XOR(delta) 모드 / bit13-0 = 타일 수
허프만 정의: [값바이트(>=0x80, 하위 니블=니블값)] 뒤에 항목 반복
             항목 = [b2: bit6-4 = 런길이-1, bit3-0 = 코드길이(1..8)] [코드바이트]
             b2 >= 0x80 이면 새 값바이트, 0xFF 로 종료
             코드는 "코드길이 비트"를 8비트로 좌정렬한 256엔트리 룩업표에 채움
비트스트림 : MSB 우선. 8비트를 엿봐서 표 조회. 값 >= 0xFC 이면 escape: 6비트 소비 후 7비트(상위3=런-1, 하위4=니블값)
출력       : 니블을 8개 모으면 1 long(타일 한 줄), 8 long = 1타일(32B, 4bpp).
             delta 모드면 이전 줄과 XOR 해 누적(이미지가 단조로운 배경에 유리)
```
검증: 코드가 호출하는 주소(예 0x2BDA, 0x5F712, 0x2ED02, 0x1FCDE)에서 모두 정상 해제, 타일 수가 헤더와 일치, 연속 스트림이 정확히 맞물림(끝 주소 = 다음 스트림 시작). **[확인]**

### 1-B. 타일맵 압축 (0x1356, Enigma 계열) — 스크립트 `scripts/enigma.py`
헤더 `[u8 타일비트수][u8 플래그(bit0=vflip비트 있음, bit1=hflip비트 있음)][u16 증가 시작값][u16 고정값]` + 비트스트림.
코드: `0xxxxx`(6비트) = 0:증가값 기록 / 1:고정값 기록 (횟수 4비트),
`1MMCCCC`(7비트) = 0:타일 1개를 반복, 1:타일 증가 시퀀스, 2:감소 시퀀스, 3:개별 타일 나열 (횟수15 = 종료).
호출 시 d0 = 타일 오프셋(VRAM 타일 번호 기저)이 더해짐. 스테이지 배경은 오프셋 0x730. 결과 64x28 워드 = 1792워드(검증). **[확인]**

### 1-C. RLE 타일맵 (0x2F46 / 0x2F10) **[확인]**
`[c]`: c=0 종료, c&0x80 이면 리터럴 (c&0x7F)바이트 복사, 아니면 `[v]` 값부터 1씩 증가하는 c개 바이트 (0x2F10 은 열 방향 stride 변형).

### 1-D. 1bpp 폰트 — ROM 0x1A000
8x8 1bpp, ASCII 영숫자(0x20~) 약 96자(0x1A000~0x1A300). 텍스트는 문자 그래픽이며 **SJIS 문자열은 ROM 에 없음**(검색 결과 없음).
그 외의 문자/메뉴 글자는 모두 압축 타일(위 2종 포맷)이라 텍스트 추출은 불가, 화면 그래픽으로만 존재.

### 1-E. 스프라이트 프레임 구조 (0x1944에서 역추정) **[확인]**
`frame = [n-1][플래그]` + n x `piece(6B) = [y:s8][size][tile:u16][x:s8][x_flip용 x:s8]`
size = VDP 스프라이트 크기 비트(bit3-2 가로-1, bit1-0 세로-1), tile 에 오브젝트 +0x12(타일 기저/팔레트/우선순위)가 더해짐. 반전 시 마지막 바이트의 x 사용.
애니 레코드 `[프레임수][속도][프레임 포인터(long) x 수]` 를 `scripts/scan_frames.py` 로 111개 후보 탐색(`gfx/anims.json`) — 일부는 오탐.

## 4. 미해결 / 다음 단계
1. **스프라이트 조립(선수/공)**: 선수 프레임 구조체 위치·애니 표(0x2FE00 인덱스표, `$3C(obj)`)는 형식까지 파악했으나, 선수별 (프레임→타일 시트→팔레트) 연결과 VRAM 타일 기저 매핑이 완성되지 않아 **완성된 선수 스프라이트 이미지는 아직 없음**. 다음 단계에서 프레임 포인터를 따라가며 시트별로 조립 필요.
2. 메뉴/타이틀 타일맵(0x2642 호출 표, 0x76000대) 디코딩 및 화면별 합성 → 메뉴 텍스트 확인에 필요.
3. 팔레트↔타일 시트 정확한 매칭(CRAM 라인 배정: $ED00 버퍼 라인0~3 = 사이드/스테이지/ UI).
4. 카탈로그의 false negative(디코더 엄격 조건으로 빠진 스트림: 0x252FA, 0x25ED4 등 일부는 스테이지 표로 확인) 보완.
