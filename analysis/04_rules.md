# 04. 게임 규칙 / 수치 테이블 (정적 분석 결과)

표기: **[확인]** 코드·데이터를 직접 읽고 일치 확인 / **[추정]** 정황 근거(이름·의미는 불확실) / **[미확인]**.
한계: 에뮬레이터를 쓸 수 없는 환경(설치 시도가 거부됨)이라 **실행 관찰 없이 68000 코드를 읽어서만** 분석했다. 능력치 의미(이름)는 코드에서 어떻게 쓰이는지로 유추한 것이므로 재구현 전에 실기/에뮬 비교로 한 번 검증해야 한다.
수치 CSV 는 `analysis/data/`, 추출 스크립트는 `analysis/scripts/dump_tables.py`.

## 1. 게임 구성 (모드/팀/선수)
- 메인 메뉴 → **모드 메뉴(커서 5개: $C024=0~4)** → 모드별 흐름 상태 0x9C/0xA4/0xAC/0xB4/0x94 → 팀(캐릭터) 선택 → 매치(상태 0x2C → 0x14). **[확인]** 모드 이름(스토리/대전/…)은 텍스트가 그래픽이라 **[미확인]**.
  - 모드0 흐름(0x11826)은 23개 서브상태로 가장 방대 → 스토리형 진행(상대 팀 순차 격파 + 연출)으로 **[추정]**.
  - 모드1/2(0x144CC/0x15494)는 구조가 거의 같음(팀 선택 → 0x1257A 표로 스테이지($E683) 결정 → 매치) → 1P vs COM / 2P 대전 계열 **[추정]**.
  - 모드3(0x157F0)은 18개 서브상태의 연속 대전 흐름 **[추정]**, 모드4(0x10E3C)는 7개 서브상태(옵션/기타) **[추정]**.
- **팀 수 = 25** (능력치·AI·그래픽 포인터표가 모두 25엔트리 [확인]). 팀 23 은 전 능력치 최대에 가까운 "보스급"(평균 HP 150), 팀 24 는 HP 평균 29 의 약체(튜토리얼/연습 상대 추정) — 능력치 평균표는 부록 A.
- **한 팀 = 7명** [확인]: 선수 0~3 = **내야(슬롯 0~3)**, 선수 4,5,6 = **외야** 각 1명(슬롯 4 = 상측 라인, 7 = 하측 라인, 10 = 후방). 슬롯→오브젝트 타입: 내야 0x20, 외야 4~9 0x24, 10~12 0x28.
  - 대체 배치(0x49F8, 모드에 따라 $57=1 계열): 선수0=슬롯0, 나머지 6명=슬롯 5,6,8,9,11,12(= **내야 1명 + 외야 6명**, 1:1 대결형 추정).

## 2. 코트와 물리
- **코트 좌표** (스프라이트 좌표계, 0x4AC8(왼쪽 팀) / 0x4AFC(오른쪽 팀=좌우 반전)) [확인]  `court_slots.csv`:

| 슬롯 | 왼쪽팀 (x,y) | 오른쪽팀 (x,y) | 역할 |
|---|---|---|---|
| 0 | 236,128 | 276,128 | 내야 전위(중앙선 쪽) |
| 1 | 96,128 | 416,128 | 내야 후위 |
| 2 / 3 | 160,64 / 160,192 | 352,64 / 352,192 | 내야 좌/우 |
| 4,5,6 | 352/288/416, 24 | 160/224/96, 24 | 외야 상단 라인(상대 진영 쪽) |
| 7,8,9 | 352/288/416, 238 | 160/224/96, 238 | 외야 하단 라인 |
| 10,11,12 | 464,128 / 448,64 / 480,192 | 48,128 / 64,64 / 32,192 | 외야 후방(상대 뒤쪽) |
  중앙선 x≈256, 코트 x≈96~416 (+외야 48~480), y≈24~238 (화면은 y 를 1/2 로 압축한 **의사 3D 평면 + z 높이**). 팀 A 내야 x∈[96,236], 팀 B 내야 x∈[276,416].
- **오브젝트 물리** [확인]: 위치 `x,y,z` 및 속도는 16.16 고정소수. 매 프레임 `pos += vel`(0x1B26), `vz -= $E200`(0x1DEA) — **중력 = 0x3000 (=0.1875 px/frame²)**. 이동속도 = `stat2 << 12`(0x8274: 16.16 로 stat2/16 px/frame). 바닥(z<0)에서 공은 `vx,vy >>= 1`, `vz` 반전 후 감쇠(시프트 $E22A: 스테이지별 1~3, 표 0x54E8). 지면 **마찰($E22C)은 스테이지별**(표 0x54BA: 0x2000 대부분, 0x3000/0x4000 = 사막·모래 등 높은 마찰, 0x1000 = 얼음)로 이동 제동에 사용(0x8282: 속도에 ±마찰을 더해 0 으로 수렴).
- **스테이지 14개** ($E682=0~13): 각자 배경/팔레트/마찰/바운스가 다름(`gfx/preview_stages_16.png`).
- **히트박스** (0x69D8, 8바이트 x N: `xoff,w,yoff,h` 워드) [확인] `hitboxes.csv`. 엔트리 1~16 = 선수·공 AABB(가장 흔한 값 w=16,h=8; 낙하 지점 판정 등 32x32, 64x64, 160x160 도 있음). 엔트리 17 이상은 **코트 존(영역) 경계 테이블**로 추정(0x6F5C 가 공 위치를 존 0/4/7/10 에 대입해 "공이 어디로 떨어졌는지($E75D)" 판정). 충돌 = 두 오브젝트 AABB 의 x/y 겹침 + z 조건(0x6C44, 0x6CDC).

## 3. 능력치 (팀당 7선수 x 8바이트, ROM 0x18836, 런타임 $FF8000) [확인: 위치·사용 위치 / 추정: 이름]
선수 오브젝트의 +0x40.. 에 워드로 복사(0x4C72). 표의 **이름은 사용 코드를 근거로 한 추정**.

| idx | 오브젝트 | 범위(전체) | 근거 | 추정 이름 |
|---|---|---|---|---|
| s0 | +0x40 | 20~150 | 피격 시 `HP -= 데미지`, 0 이면 아웃(0x84C0, 0x9522) | **체력(HP)** — 내야만 감소 |
| s1 | +0x42 | 2~16 | `데미지 = 공 위력 − s1` (0x8548, 하한 0) | **방어력** |
| s2 | +0x44 | 4~23 | `속도 = s2<<12`(0x8274), AI/이동 | **이동속도** |
| s3 | +0x46 | 32~59 | 공 초기 vz = `0x10000 + s3<<12` (+0x10000 플래그시) (0x7E66) | 로브/점프 높이(공의 포물선) **[추정]** |
| s4 | +0x48 | 14~50 | 투구 위력 기저: `s4 + s4/4(비트2) + s4/4(비트3) + 차지(≤15)` (0x89AA) → 공 +0x1A | **투구 위력(파워)** |
| s5 | +0x4A | 2~16 | 상태 0x14 진입 시 `$18(타이머)=s5` (0x77DA) | 회복/경직 프레임 수 **[추정]** |
| s6 | +0x4C | 63~128 | `s6<<4`(+0x100 비트2/3, +차지*16) → 공 +0x74 (0x7D0C) | **투구 속도/구속** **[추정]** |
| s7 | +0x4E | 64~81 | 패스 시 `s7<<4` 로 공 속도 산출(0x72BC) | **패스 속도** **[추정]** |

- 데미지 규칙 [확인, 0x8544~0x84CA]: `damage = max(0, ball.power − target.defense)`; `$E680 != 0` 이면 damage=0 이고 피격 즉시 아웃(0x9520~0x9554: 규칙 분기). 내야(슬롯<4) 만 HP 감소/아웃 처리, 외야는 대상 아님.
- 피격 후: 선수 타입 0x48(피격) → 0x4C(아웃) 로 변경, 사이드의 `+0x57`(남은 인원) 1 감소(0x958A). 초기값은 모드에 따라 7 또는 1. 승패 그래픽은 두 사이드 `+0x57` 차이로 선택(0x5802~0x5870). 시간 종료는 `$E684`(분/초) 카운트다운(0x5378)이 0 이 될 때 0x5618 이 Z 를 세움 → $E602=0x28(종료 연출). **[승리 조건의 정확한 규칙(전멸 vs 인원차)은 [추정]]**.
- 통계 카운터(결과 화면용 추정) 사이드 +0x63~0x69: 투구/명중/ 캐치 등의 횟수(0x8C46~0x8CC2, `$E697` 활성시).
- **팀 레이팅**(0x3460) = Σ(선수 x 능력치) `(stat<<8)/div[k]*mul[k]`, `div=(150,12,16,48,30,10,88,72)`, `mul=(16,2,1,1,12,2,2,1)` → 사이드 +0x60 (CPU 난이도/표시 점수로 사용 추정). 25팀 레이팅(참고): 팀23=77658(최강), 팀24=36701(최약), 팀15=58723, 팀20=55244 … (부록 A). `div` 는 각 능력치의 사실상 상한값으로 보임(150/12/16/48/30/10/88/72).

## 4. 던지기 / 잡기 / 회피 [확인 구조 / 추정 의미]
선수 오브젝트는 **타입 + 서브상태($16, 4 단위 점프표)** 로 구현된 상태 머신. 사람 조작 선수 핸들러(0x794C/0x7A2E/0x7B04 계열)의 서브상태 점프표(0x7A38)와 호출 루틴으로 본 역할:

| 서브상태 | 루틴 | 역할 |
|---|---|---|
| 0x00 | 0x7A60 | 대기/이동(방향 입력 → 속도 = stat2 기반, 마찰 적용) |
| 0x04 | 0x7A86 | 이동(공 소유 중 등) |
| 0x08 | 0x70E2 | **투구 준비/조준·차지**: 이동 정지, 방향별 보정(0x7FEA/0x7934), 차지 카운터 `$18` 증가(최대 15 → 위력 보너스) |
| 0x0C | 0x7166 | **투구 실행**: 대상($E21E)에게 `power=0x89AA`, 속도 `0x7D0C/0x7D90`, 공 타입 0x18(비행), 공 플래그 bit6 set → 공 +0x70 에 위치 저장 등 |
| 0x10 | 0x724E | **패스 실행**: 대상($E214=아군), 공 위력 고정 3(`$1A(공)=3`), 속도는 s7 |
| 0x14 | 0x730A | 캐치/수비 모션(타이머 s5) |
| 0x18~0x24 | 0x7494.. | 점프/캐치 판정/ 반응 등 **[미해독]** |
- **캐치 타이밍 판정**(0x8CF0): 공이 닿기 전 선수의 `$18` 카운터가 `15 − $E69E` 이하일 때만 성공(=난이도/보정 $E69E 가 창 너비 결정, 부팅값 2) **[확인 구조]**.
- **회피**: 별도 점프/회피 상태가 존재(상태 0x30~0x3C 공통 핸들러 0x935C, 0x946A, 0x94DA 등) 하나 입력 매핑/판정식은 **[미해독]**.
- **필살기**: 능력치 표에 "필살기" 전용 필드가 보이지 않음. 공 타입 0x18(일반 비행) 외에 특수 공 상태/효과음(0xA3 등)이 있으나 **필살기 시스템의 존재 여부 자체가 [미확인]** (원작에는 필살 슛 연출이 있음 → 있을 가능성 높음, 다음 단계에서 공 핸들러 0xA516/0xA54E 계열과 0x2FE00 애니표를 추적 필요).
- **입력 버튼 의미**(매치 중): 패드 비트 B/C/A 순열 리맵(0x2728) 후 상태별 사용 — 서브상태 0x7B04 계열에서 C 누름 → 0x7CD6(던지기/패스 시작 추정), B 누름 → 서브상태 8 진입(차지 추정). 정확한 매핑은 **[추정, 에뮬 확인 필요]**.

## 5. 컴퓨터(AI) 파라미터 (ROM 0x18DAE, 25팀 x 7선수 x 16B, 런타임 $FF8800) [확인 구조 / 추정 의미]
선수 오브젝트 `+0x5A` 가 자기 16B 레코드 포인터(0xD444: `$8800 + team*112 + player*16`). 난수 `0x14EA` 와 **누적 임계값 표**로 행동 선택:
- b0,b1 : 5비트 난수(0~31) < b0 → 행동0, < b1 → 행동1, 그 외 → 행동2 (0xD474: 3택).
- b2..b5 : 4개 임계값(8비트 난수) → 5택 (0xD496, offset +2).
- b6..b8 : 3개 임계값 → 4택 (0xD4CA, offset +6).
- b9..b12: 4개 임계값(오프셋 +9) → 택일 (0xD4F6).
- b13..b15: 별도 값(예 02,18,1C / 02,10,0A …): 기본 반응 지연/확률 파라미터 **[추정]**.
→ 즉 "한 프레임 확률"이 아니라 **선수별 행동 확률 분포(≈ 성격)** 를 ROM 표로 정의. 웹 재구현 시 이 표를 그대로 복사해 쓰면 원작 AI 성격을 보존 가능. 구체 행동(던진다/패스/움직인다/피한다/잡는다) 대응은 [미해독].
- 다른 AI 난이도 관련 표: `$E69C`(점프표 0x7D5E/0x89F8; 난이도 단계별 분기), 0x1B..: 투구 대상 선택은 0x78FE/0x7868 계열(타깃 락온)로 **[미해독]**.

## 6. 진행/기타 수치
- 제한 시간: `$E684`(분)/`$E685`(초), 60진 카운트다운 — `$E680==1` 모드에서 사용 [확인].
- 스테이지($E682 0~13)별 변수: 마찰(표 0x54BA), 바운스(0x54E8), 배경/팔레트/타일맵/타일(0x1A598/0x1A778/0x1FCBE), 점수판 위치(0x5416: 0xC4C4 등).
- 선택 팀→스테이지 대응표: 0x1257A (25바이트, 예: 팀0→1, 팀1→1, 팀2→2, 팀3→2, 팀4→8, 팀5→3 …) **[추정: $E683 = 스토리 상대 배경 번호]**.
- 팀 색상/스프라이트 그룹: 0x18000(4B x 팀색 인덱스, 사이드 구조체 +0x3A 로 조회) → 13슬롯 색 인덱스(내야4, 외야3x3).
