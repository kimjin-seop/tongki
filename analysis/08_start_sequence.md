# 08. 경기 시작 연출(입장·심판·점프볼)과 아웃/종료 연출

표기: [확인]=자작 에뮬레이터 실행(수치 로그 + 렌더 PNG 육안 확인)과 코드 일치, [코드]=코드만 읽음(실행 미관찰), [추정].
상태 파일 `analysis/state/match_story0.pkl`(스토리 1경기, 1P=왼팀 vs COM=오른팀) 기준 프레임 번호 f. 이 상태에서 f7 에 매치 서브상태 0x0C 가 시작된다(= 연출 T0).
스크립트(cwd=프로젝트 루트, `python -I`): `t_start1.py`(오브젝트 타입 로그), `t_start2.py`(입장 경로), `t_start3.py "<프레임,...>" <N>`(심판/공/점프볼/배너 로그+캡처), `t_start_tip.py [shots]`(1P 쳐내기 타이밍), `t_start_end.py 1 1 <N> end "<프레임>"`(아웃/GAME SET), `t_banner_dump.py`, `ref_extract.py <상태pkl>`(에셋 추출).
좌표: world (x 0~512, y 0~256, z 높이). 화면 x = world.x − cam_x, 화면 y = world.y/2 + 96 − z (ball.json 과 동일). **시작 연출 내내 cam_x = 96 고정**(HScroll −96, f0~f430 실측) → 코트 중앙 x=256 이 화면 x=160. [확인]
주의: 이전 메모의 `$E004` 는 카메라가 아님(시작 중 1~81 로 변동). 실제 카메라는 `$E00A`/HScroll. [확인: 심판 SAT x=148(=256−96−12)]

## 2. 입장 행진 (서브상태 0x0C, 코드 0x5ECA/0x51F8/0x520C/0x5252, 오브젝트 타입 0x5C 핸들러 0x9942)
- 시작점: 왼팀 7명 전원 (48,128), 오른팀 7명 전원 (464,128) — **한 점에 겹친 채 동시에 출발**(f8). 카메라 96 이라 두 지점 모두 화면 밖(화면 x −48 / 368) → 양쪽 가장자리에서 걸어 들어오는 모습. [확인]
- 목표점 = 슬롯별 기본 위치(ROM 0x4AC8 왼팀 / 0x4AFC 오른팀, 슬롯 0~12의 (x,y)). 직선 등속, 매 프레임 목표 방향 단위벡터 × 속도. [확인]
- 속도 = (obj+0x44 << 4 + 0x300)/256 px/f. obj+0x44 = 선수 능력치 s2(이동속도, RAM $8000 표와 14명 전원 일치) → 실측 값 8/12/16 → **3.5 / 3.75 / 4.0 px/f**. [확인]
- 도착 판정(0x6FEE): 목표 ±오차 박스 안이면 위치를 목표로 스냅, 속도 0, 서브 8(정지). [확인]
- 걷는 동안 애니: 진행 방향으로 결정(0x7868) — vy<0(화면 위로)이면 뒷모습 걷기 anim 2(walk_b), 아니면 anim 0(walk_a). vx<0 이면 좌우 반전. [확인]
- 도착 후 방향(0x9996): x ≥ 256 이면 왼쪽을 봄(반전), y ≥ 128 이면 뒷모습. 정지 애니 = 뒷모습 0x10, 앞모습 0x0E. [확인]

## 3. 심판 (오브젝트 타입 0x64 @ $C780, 핸들러 0xDA94) [확인]
### 3-1. 그래픽
- 타일: ROM **0x363DE** 무압축 4bpp, **12프레임 × 18타일(576B)**. 매치 초기화(0x598A)에서 RAM $FF6000 으로 복사, 매 프레임 현재 프레임 576B 를 `$E23E` 경유 DMA → VRAM 타일 0x00A~0x01B. 에뮬레이터 VRAM 과 ROM 프레임 바이트 일치. [확인]
- 조각 레이아웃 ROM 0xDDC2: 24x32(타일 0~11) + 24x16(타일 12~17) → **24x48 한 장**, 앵커 = 발밑 중앙(셀 내 12,48). [확인]
- 타일 속성 0xC00A: 우선순위 1, **팔레트 라인2(UI 팔레트, ROM 0x3A1AC)** — 공·HUD 와 같은 팔레트, 팀과 무관. [확인]
- 프레임 내용(시트 `public/assets/rom/sprites/referee.png`, 육안): 0 차렷(정면), 1 웅크려 공을 낮게 쥠, 2 한 손 위로(토스), 3 두 손 반쯤 올림, 4 두 손 만세, 5·6·7 걷기, 8·9 손뼉/호루라기 자세, 10·11 정면 시선 변형(오른쪽/왼쪽 보기).
### 3-2. 애니 표 ROM 0xDD78 ([프레임수][속도] + 프레임번호, 프레임 지속 = 속도+1 틱)
| anim id | 이름(JSON) | 프레임 | 지속 | 사용처 |
|---|---|---|---|---|
| 0x00 | stand | [0] | 정지 | 중앙 대기 90f, 관전 정면 |
| 0x02 | walk | [6,5,6,7] | 7f/프레임 반복 | 등장·복귀 보행 |
| 0x04 | hold_ball_go | [1] | 정지 | GO ~ 토스 전 |
| 0x06 | toss | [2] | 정지 | 토스 후 20f |
| 0x08 | out_call | [8,8,9,9,9,3,3,3] | 7f/프레임, 1회 | 아웃 판정 콜(호루라기) |
| 0x0A | unused_a | [3] | — | 사용처 미발견 |
| 0x0C | game_set | [4] | 정지 | GAME SET / TIME UP 시 만세 |
| 0x0E | look_left | [11] | 정지 | 공 x<224 |
| 0x10 | look_right | [10] | 정지 | 공 x>288 |
### 3-3. 상태(obj+0x16)
| 서브 | 동작 |
|---|---|
| 0x00 | (256,16) 생성, 목표 (256,120), 속도 (0x140 − 마찰>>7)/256 ≈ **1.0px/f**(실측 정확히 1px/f), walk. 도착 → 0x04 |
| 0x04 | stand, 90f → 0x08 |
| 0x08 | `$E247=0`, `$E239=1`(플레이 시작), 음악 0x81, 배너 GO(타입 0xB), hold_ball_go, 30+rand(0..31)f → 0x0C |
| 0x0C | 음악 0x82, 배너 FIGHT!(타입 0xC), toss, 공 발사(아래 §4), 20f → 0x10 |
| 0x10 | 목표 (256,12), 속도 0x300/256 = **3.0px/f**, walk. 도착 → 위치 (256,16) 고정, 0x14 |
| 0x14 | 관전: 공 x 로 stand/look_left/look_right. `obj+0x1C`(맞은 선수 포인터)가 내야 선수이고 HP ≤ 0 이면 → 0x18 |
| 0x18 | 효과음 0xAE(호루라기 추정), out_call 1회(실측 50f), 아웃 선수가 왼팀이면 좌우 반전 → 0x14 |
| 0x1C | game_set(만세) 고정. 매치 서브 0x10(GAME SET)/0x28(TIME UP) 진입 시 외부에서 설정 |
- 이동 중 반전: vx<0 이면 obj+2 bit7(0xDD4A). 시작 연출은 수직 이동이라 반전 없음. [확인]
- 공을 쥐고 있는 동안 공 위치(코드 0xA32E, 표 0xA3BE/0xA3D4): 공 world = 심판 + (dx, dy=+2, dz). stand (0,16) / walk 프레임별 dx 0,−2,0,+2, dz 16 / hold_ball_go (0,14) / toss (0,14). 실측: 등장 중 공 z=16, GO 후 z=14, y=심판+2. [확인]
- 그리기 순서: 다른 오브젝트와 world.y 정렬. 중앙 대기 시 심판(y116)은 점프볼 두 선수(y128) 뒤에 가려진다. [확인: f300 렌더]

## 4. 점프볼(티프오프) [확인]
- 참가자: 각 팀 슬롯0 한 명씩(1P 쪽 obj0 (236,128), COM 쪽 obj7 (276,128)), 심판 (256,116) 사이. 나머지 12명은 일반 타입으로 제자리.
- **입력 유효 시점**: 서브상태 0x18(GO 전)에는 1P 입력 무시(f300 C 입력 → 반응 없음). GO(f353) 이후부터 유효. [확인]
- 공 토스(심판 서브 0x0C): 공 타입 0x1C(자유 낙하), vz₀ = 4.5 + (RNG & 0x1F000)/65536 (4.5~6.44 px/f), vy=+0.125, 중력 0.1875/f². 정점 높이 약 54~110px(실측 vz₀≈5.2 → z 최고 73.4, 상승 25f). [확인]
- 점프(C 버튼, 코드 0x7CD6): vz = 능력치 점프값(실측 CPU 4.0), vx = 상대 쪽으로 0.25px/f, 효과음 0xA6. 점프 중 애니 0x14.
- 쳐내기(점프 중 B, 서브 0x08, 0x7BB4): 효과음 0xA2, 선수는 상대 쪽을 보며 쳐내기 애니(0x28/0x2A). 이 서브 동안 **공이 내려오는 중(vz<0)이고** 히트박스 idx 0xF 와 겹치면 성공(0x7C7E): `$E247=1`, 공 vz = −3.0, **vx = 3.5 px/f 자기 진영 쪽**(왼팀 −3.5, 오른팀 +3.5), 공 소유 기록 obj+0x3C=쳐낸 선수. 한 번만(E247) 가능.
  - 1P 실측: C f408 + B f417~423 → f425 성공(공 z 58, vx −3.5). B 를 너무 빨리(f414) 누르면 쳐내기 자세가 공 하강 전에 끝나 CPU 가 가져감. [확인 `t_start_tip.py`]
- CPU(타입 0x88, 0xD35A): 공이 토스된 뒤 vz < 0.5 가 되면 **매 프레임 80/256(31%) 확률로 점프**. 점프 중 공과 겹치거나 상승속도가 0.5 미만이 되면 쳐내기 자세로 전환. [코드+확인: f414 점프, f434 쳐내기 자세, f435 공 vx +3.5]
- 쳐내기 후 착지(z<0)하면 일반 조작 타입으로 복귀(0x83E0/0x8228). 쳐내기 자세가 끝났는데 공중이면 60f 유지(0x7C5E).
- 점프하지 않은 1P: 공이 바닥(z=0)에 닿는 순간 일반 타입 0x10 으로 전환(f443). [확인]
- 토스 전(GO~FIGHT 사이) C 를 누르면 즉시 점프해 헛점프, 착지 시 일반 타입 → 그 경기 점프볼 포기. [확인: f360 C → f400 착지 후 타입 0x10]
- 공이 아무도 못 치고 떨어지면: 타입 0x1C 바운스/굴러감 → 일반 규칙(가까운 선수가 줍기). [코드]

## 5. 배너 (오브젝트 타입 0x54 @ $D900, 핸들러 0xDFD0) [확인: 렌더]
- 한 슬롯이라 새 배너가 이전 배너를 즉시 대체(GO 60f 수명이지만 FIGHT! 가 35f 만에 덮어씀). 화면 고정 좌표(카메라 무관). 팔레트 UI 라인2.
- 수명표 0xE1EA(0=무한, 상태 전환 시 소멸), 깜빡임 0xDFF8 분기.
| 타입 | 글자 | 화면 기준점(중앙 x, 하단 y) | 크기 | 수명 | 깜빡임 | 사용처 |
|---|---|---|---|---|---|---|
| 0xB | GO | (160,72) | 16x16 | 60f(실제 FIGHT! 가 대체) | 없음 | 심판 서브 0x08 |
| 0xC | FIGHT! | (160,72) | 48x16 | 32f | 없음 | 토스 순간 |
| 3 | GAME SET | (160,112) | 64x16 | 상태 유지(180f) | 없음 | 매치 서브 0x10 [확인] |
| 4 | TIME UP | (160,112) | 56x16 | 180f | 없음 | 서브 0x28(시간 종료) [코드] |
