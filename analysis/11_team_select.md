# 11. 팀(학교) 선택 화면 — 원작 재생·추출·웹 대체 사양

표기: [확인] = 자작 에뮬레이터 실행(RAM/VDP 기록 + 렌더 PNG 육안 확인), [코드] = 디스어셈블만 읽음, [추정] = 정황.
화면 320x224(H40), 프레임 f = **모드 메뉴에서 START 를 누른 프레임 = f0**(60fps).

스크립트(cwd=프로젝트 루트, `python -I`):
- `analysis/scripts/t_select2.py` : 부팅 → 모드 메뉴, 커서 2(1Pvs2P)에 둔 상태 `analysis/state/modemenu.pkl` 저장. (방향 입력은 **3f 이상** 눌러야 인식, 2f 는 무시됨 [확인])
- `analysis/scripts/t_select_rec.py <out.pkl> <모드 1|2> <N> [입력 "f:mask:len[:pad]"] [unlock 0|1]` : modemenu.pkl 에서 모드 선택 후 프레임별 VDP·RAM·사운드 큐 기록. pad 1 = 2P 패드. unlock=1 이면 `$E500` bit0 을 세워 SPECIAL TEAM 해금 상태로 진입.
- `analysis/scripts/t_select_cont.py <in_md.pkl> <out.pkl> <N> [입력]` : 저장된 상태에서 이어서 기록.
- `analysis/scripts/t_select_log.py <rec.pkl>` : 커서 오브젝트·상태 변화 로그. `t_select_sheet.py` : 프레임 몽타주.
- `analysis/scripts/t_select_extract.py` : 에셋 추출(아래 §5). `t_select_gfx.py` : 문서 몽타주. `ui_mock.py` : 한국판 목업.
- 기록 파일: `analysis/state/sel/m2.pkl`(1Pvs2P 900f), `m1.pkl`(1PvsCOM 700f), `m1b/m1c.pkl`(라인업 이후), `m2u.pkl`(해금).

## 1. 화면 흐름과 상태 [확인]
| 모드(메뉴 항목) | $E600 | 팀 선택 이후 순서 ($E400 서브) |
|---|---|---|
| 1PvsCOM | 0xA4 (0x144CC) | 0 팀 선택 → 1 규칙 창(ルールをきめてください) → 2 라인업(VS) → 3 편성(1P) → 4 편성(COM) → … → 6 매치(0x2C) |
| 1Pvs2P | 0xAC (0x15494) | 0 팀 선택 → 1 규칙 창 → (이후 라인업/편성 같은 구조 [추정, 미재생]) |
| 倒せ!(스토리) | 0x9C | 팀 선택 없음: はじめから/つづきから 창 → 스토리 |
- 팀 선택 진입 타임라인(1Pvs2P, f0=START): f0 결정음 0xA1 → f0~38 모드 메뉴 유지(정리) → **f39 상태 전환** → **f41~48 창 열림 애니**(가로 선 → 세로로 자라는 초록 창, 8f, 루틴 0x107BE) → f49 엠블럼·약칭 그려짐 → **f50~51 커서·공 아이콘 등장, 입력 유효**.
- 두 커서 모두 확정 → **배경 메달 회전 애니 40f**(5f x 8컷) → 다음 화면(규칙 창). 1Pvs2P 에서 2P 확정 f522 → f562 전환 [확인].

## 2. 레이아웃 (원작 320x224 좌표) [확인: 타일맵 판독]
레이어(아래→위): 백드롭(검정, 가려짐) → **플레인 B 배경**(메달/DODGE 패턴) → **플레인 A 창**(팔레트2) + 엠블럼(팔레트3) + 글자 → **스프라이트**(커서 프레임, 공 아이콘). 스크롤 없음(A/B 모두 0).

| 요소 | 위치(px) | 크기 | 비고 |
|---|---|---|---|
| 배경 | (0,0) | 48x96 반복 | 48x48 메달 블록, 6타일마다 가로 24px 어긋난 벽돌 배치. 메달 가운데 3x3 타일(0xD3~0xDB) 애니 |
| 메인 창 | (48,8)-(272,160) | 224x152 (타일 열 6~32, 행 1~19) | 9-slice: 모서리 0x16, 위/아래 0x11, 좌/우 0x12, 채움 0x17(#004824) |
| 제목 문구 | (80,16) | 144x16 | プレイするチームを えらんでください (탁점 줄 포함 2행) |
| 공 아이콘 | (56,16), (240,16) | 16x16 | 4프레임 x 5f 회전 |
| 엠블럼 (c,r) | **(64+40c, 40+40r)** | 24x16 | c=0~4, r=0~2. 타일 0x284+6n(3x2 열 우선), 팔레트3 |
| 약칭 | (64+40c, 56+40r) | 24x8 | ASCII 8x8 글리프 3자(흰) |
| 커서 프레임 | **(56+40c, 32+40r)** | 40x40 | 엠블럼 바깥 8px, 위 변에 1P/2P/COM 라벨 |
| SPECIAL TEAM 창(해금 시) | (8,152)-(304,216) | 296x64 | 제목 "SPECIAL TEAM"(노랑 글리프) (104,160). 엠블럼 (24+40k,176) k=0~6, 커서 (16+40k,168) |

격자(화면 위치 → ROM 팀): `T.D S.A B.A A.T HOK / KYO OKI TOK CHN URS / EGY GRE BRA CHI USA` = `0 1 3 2 5 / 6 7 4 10 11 / 14 12 13 9 8`. 커서 (x,y) → 인덱스 x+5y → 표 0x14FC0 [코드 0x1514E].
SPECIAL 행(화면 왼→오): `CHN URS EGY GRE BRA CHI USA` = 팀 `17 18 21 19 20 16 15`. ROM 커서 x 는 URS=0 … USA=5, **CHN=6(화면 맨 왼쪽)** 이라 오른쪽 이동은 URS→…→USA→CHN→URS 순환 [확인].
- 몽타주: `analysis/gfx/select/01_select_flow.png`(흐름 12컷), `02_select_layers.png`(B/A/스프라이트 분리), `03_select_grid_x3.png`(좌표 오버레이).

## 3. 커서·입력 규칙
| 항목 | 규칙 | 근거 |
|---|---|---|
| 초기 위치 | 1P (0,0)=T.D, 2P (1,0)=S.A. 1PvsCOM 의 COM 커서는 1P 확정 후 (0,0) 에 생김 | [확인] |
| 이동 | 방향 1회 = 1칸, **자동 반복 없음**(40f 눌러도 1칸) | [확인 f100~140] |
| 순환 | 좌우·상하 모두 끝에서 반대편으로(왼쪽 끝 L → 오른쪽 끝, 아래 끝 D → 맨 위). 해금 시 세로는 4행(0~3) 순환 | [확인] |
| 겹침 | 다른 커서가 있는 칸은 **건너뜀**(1P (0,0) R → (2,0), 2P 가 (1,0)) | [확인 f101] 세로 방향 건너뜀은 미검증 [추정 동일] |
| SPECIAL 행 이동 | 2행(c)에서 D → 3행 같은 화면 열, 3행에서 U → 2행 0열 쪽 | [확인 일부] |
| 확정 | Start/A/C(edge 마스크 0xE0) → 효과음 0xA1, 커서가 확정 색(빨강·노랑 글로우)으로 바뀜, 그 자리에 고정 | [확인] |
| 취소 | B → 확정 해제(이동 색으로 복귀, 효과음 없음). 확정 전 1P 의 B → 모드 메뉴로 복귀 | [확인 해제] / [코드 0x14612 복귀] |
| 1PvsCOM | 1P 가 자기 팀 확정 → COM 커서를 1P 가 움직여 상대 팀 확정 → 진행 | [확인] |
| 1Pvs2P | 각자 패드로 동시에 이동·확정, 둘 다 확정되면 진행 | [확인] |
| 깜빡임 | 커서는 **숨김 깜빡임 없음**. 팔레트 글로우만(라인0 색6~8 = 이동, 라인1 색6~8 = 확정), 6f 마다 7단계 순환(42f) | [확인 CRAM 기록][코드 0x1008E 표 0x100DA/0x100E2/0x100F0] |
| 공 아이콘 | 스프라이트 타일 1→5→9→13, 각 5f | [확인] |
| 배경 메달 | 평상시 프레임 0/1 을 5f 교대, 확정 후 0~5,0,1(40f) + 3·5번째 컷에서 팔레트2 색8 번쩍(#fcd890 → #fcd848) | [코드 0x10BC0][확인 40f] |

글로우 색(MD→RGB): 이동 `#fcfcfc #fcfcfc #00fcfc #48b4fc #0024b4 #00006c #000000` 중 연속 3색(오프셋 2,1,0,1,2,3,4), 확정 `#fcfcfc #fcfc00 #fcb400 #fc0000 #900000 #480000 #000000` 같은 방식. 정확한 값은 `select.json → assets.cursor`.

### 효과음/BGM ID (소리 미청취 UNVERIFIED, 큐 등록 시점만) [확인]
| ID | 시점 |
|---|---|
| 0xA0 | 커서 이동(매 칸) |
| 0xA1 | 모드 결정, 팀 확정, 규칙 창 결정 |
| (없음) | B 취소 |
| 0x8B | 1PvsCOM 라인업(VS) 화면 진입 시 BGM [추정 BGM 대역] |
| 0xE0 | 매치로 넘어갈 때(0x1450A) 정지/초기화 [코드] |
팀 선택 화면 고유 BGM 명령은 관찰되지 않음 → 모드 메뉴 BGM(0x8C, 10 문서)이 이어짐 [추정].

## 4. 팀 확정 이후 화면(참고, 팀 정보 패널)
- **규칙 창**: ルール(ノックアウト/こうしき), しあいじかん(むせいげん / 358 分), EXIT. 선택 불가 값은 회색 글자(#909090 계열) = 원작의 "비활성" 표현. 좌우로 값 바꾸는 항목형 메뉴 → 웹의 난이도·옵션 선택에 그대로 쓸 수 있는 문법.
- **라인업(VS)**: 좌우 두 창(각 152x216), 머리에 `1P`/`COM` + 엠블럼 + 팀명(카나) + 약칭, 그 아래 선수 7명 = 얼굴 24x24 스프라이트(왼쪽 (24,40+24i), 오른쪽 (184,40+24i)) + 이름. 가운데 "VS" 글자. 얼굴은 기존 `hud.faces`(faces_atlas) 와 같은 그림.
- **편성·능력치**: 위쪽 3창(팀 패널 / 선수 A / 선수 B 비교), 6줄 능력치(体力·ぼうぎょ力·すばやさ·ジャンプ力·シュート力·キャッチ力)를 주황 막대(1칸 4px 블록)로 표시, 아래 코트에서 얼굴을 커서(plain 프레임, 이동=하늘색/선택=빨강)로 골라 자리 교대. 문구 "ポジションの変更ができます" → 교대 중 "交代する人をえらんで下さい"(스프라이트 글자). EXIT 버튼(하늘색 테두리).
→ 웹에서 "팀 정보 패널"이 필요하면 원작 팀 선택 화면에는 없고 이 두 화면에 있다. §7 목업은 팀 선택 화면 오른쪽에 라인업 창 축소판(얼굴 7 + 팀명)을 붙이는 방식으로 합쳤다.

## 7. 웹 구현 사양 (제안, 구현 안 함)
### 7-1. 캔버스 해상도(16:9)
| 후보 | 장점 | 단점 |
|---|---|---|
| 398x224 | 원작 세로 224 그대로(배경·HUD·창 좌표 그대로 이식) | 가로 398 은 8의 배수 아님(타일 정렬 깨짐), 1080p 정수배 아님(4x=1592x896 + 레터박스), 720p 3x=1194 |
| **384x216 (권고)** | 48x27 타일(8px 격자), **1080p 정확히 5x**, 720p 3x(1152x648)+작은 여백, 1440p 6x(2304 초과→5x+여백) | 원작 224 → 216: 메뉴·팀 선택은 창 재배치로 해결, 원작 배경 화면(경기 HUD 등)은 위아래 4px 잘라야 함 |
- 권고: **메뉴·로비·팀 선택·대기실 = 384x216**. 경기 화면은 별도 판단(원작 320x224 를 그대로 가운데 두고 좌우를 stage 배경 연장으로 채우는 방식 권장, 이 문서 범위 밖).
- 배경은 `select.bg.unit` 를 (0,0)부터 타일링(384 = 48x8 정확히, 216 = 96x2.25 → 아래 잘림 정상). 창은 9-slice 로 8px 단위 폭/높이만 사용.
- 표시: 캔버스 384x216 → `floor(min(W/384, H/216))` 정수배, `image-rendering: pixelated`, 남는 영역은 가운데 정렬 + 검정 레터박스.

### 7-3. 입력·동작(원작 규칙 이식)
- 키보드: 방향키 = 1칸 이동(자동 반복 없음, 원작대로), Enter/Space/Z = 확정(0xA1 대응 효과음), Esc/X/Backspace = 취소(무음). 순환·겹침 건너뛰기 원작대로.
- 터치/마우스: 엠블럼 칸(40x40 → 5x 시 200px, 3x 시 120px) 탭 = 그 칸으로 커서 이동, 같은 칸 다시 탭 = 확정. 확정된 상태에서 내 정보 창 탭 = 취소. 44px 최소 터치 크기는 3x 이상에서 충족(40x3=120).
- 글로우: 6f(100ms) 마다 7단계 색 순환 — 스프라이트 시트 열 교체로 구현(팔레트 연산 불필요).
- 둘 다 확정 → 메달 애니 40f(약 0.67초) 후 다음 화면.

### 7-4. 현재 웹 흐름(public/js/screens/room.js)에서의 대체
- 현재: 대기실 카드 2개 안에 `<select.team-sel>` 드롭다운(25팀 목록) → `net.send('set_team', {team})`, 준비/시작 버튼.
- 제안: 대기실(시안 B `mock_B_room.png`)의 "팀 변경" 항목 또는 방 입장 직후 **팀 선택 화면(전체 캔버스)** 으로 전환.
  - 내 좌석 = 1P(왼쪽)/2P(오른쪽) 커서 하나만 조작, 상대 커서는 서버 상태로 표시(상대가 고르는 중 = 이동 색, `set_team` 받은 뒤 = 확정 색). 실시간 커서 위치 공유는 선택 사항(프로토콜 추가 필요 → 박백엔/윤프론 판단).
  - 확정 = `set_team`(기존 메시지 그대로). 취소 = 로컬 확정 해제만(서버 팀 값 유지) 또는 `ready:false`. 둘 다 확정되면 대기실로 돌아와 준비/시작(방장) — 기존 `r.start.ok` 규칙 유지.
  - 컴퓨터 대전 좌석(`isCpuSeat`)은 원작 1PvsCOM 처럼 **내가 COM 커서도 움직여 상대 팀을 고름**(서버가 CPU 좌석 팀 지정 허용 여부 확인 필요).
  - 팀 15~24(스토리 전용)는 원작처럼 "스토리 클리어 후 SPECIAL" 행으로 숨기거나 항상 공개 중 결정 필요(현재 웹은 25팀 모두 선택 가능).

## 9. 못 한 것 / 불확실한 것
- 1Pvs2P 의 라인업·편성 단계, 1PvsCOM 에서 COM 커서 활성 중 B 동작, 확정 전 B 로 모드 메뉴 복귀는 실행 확인 안 함([코드]만).
- 세로 이동 시 겹친 칸 건너뛰기, SPECIAL 행 ↔ 위 행 이동 세부(모든 열) 미검증.
- 소리는 ID·시점만(UNVERIFIED). 0x8B 가 BGM 인지 [추정].
- 해금 플래그 `$E500` bit0 은 스토리 최종전(E688=0xE) 승리 시 세팅 [코드 0x11904]. EEPROM 저장 여부 미확인. 실험은 RAM 직접 세팅으로 함.
- 팀24(연습) 엠블럼 없음. 웹에서 쓰려면 T.D 대용 또는 새로 그려야 함.
- 원작 일본어 문구(제목·규칙·편성)는 참고 이미지로만 추출, 한글 문구 이미지는 만들지 않음(웹에서 폰트로 그림).
