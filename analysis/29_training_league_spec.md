## 1. 특훈 (炎の猛特訓)

### 1-1. 구성 [확인: 상태 `tr0`·`tr3` RAM]
- 경기 상태 0x4C(초기화 0x3750) → 0x48(진행 0x387A). `$E697`=1(통계 집계), `$E68E`=4(특훈), `$E680`=0, 스테이지 `$E682`=13(학교 운동장).
- 사이드 A = 팀 22, 사이드 B = 팀 24. 양쪽 **남은 인원 `$57` = 1**: 내야는 슬롯 0 한 명씩(p0, p7), 나머지 6명씩은 외야 슬롯(5,6 / 8,9 / 11,12)에 선다.
- p0(팀 22 선수 0): HP 112, 방어 12, 주력 21, 점프 50, 위력 34, 캐치 지속 11, 구속 88, 패스 80. p7(팀 24 선수 0): HP 80, 방어 10, 주력 16, 점프 44, 위력 25, 캐치 16, 구속 88, 패스 72. (ROM 0x18836 표 값과 같다)
- 시작 위치(0x3E46): p0 x=128, p7 x=384, y=128. 캐치 특훈은 공을 p7 이, 필살 특훈은 p0 가 들고 시작.
- `$E69C` = 단계: 0·1·2 = 캐치 특훈 1~3단계, 3 = 필살 슛 특훈. 도입 3지선다에서 캐치 = 0, 필살 = 3 으로 시작(0x10FCA/0x10FDE). **캐치 3단계를 마쳐도 필살 특훈으로 이어지지 않고 완료**된다 [확인 `tr_full`: 3단계 통과 뒤 `$E600`=0x94].
- 특훈에서는 아웃이 없다: 쓰러짐이 끝날 때 `$E68E`==4 면 아웃 처리를 건너뛴다(0x950C) [판독만] / 연습 상대 HP 0 에서도 계속 진행 [확인 `sp_pass10`].

### 1-2. 진행 상태(`$E602`) [확인: 전이, 판독만: 세부]

|---|---|---|

| 0x00 | 연습. 매 프레임 종료 검사 0x3C2E | - |
| 0x08 | 종료 조건 충족. 모든 선수가 멈출 때까지 대기 | 6~140f (관측) |
| 0x0C | 페이드 | 약 24f |
| 0x10 | 결과 말풍선(0x3CB2) → 합격 판정(0x3D70) | 180f |

종료 조건(0x3C2E) [판독만 + 확인]
- 캐치: 상대 투구 수 `$E7E4` >= 10 이고 공이 살아 있지 않을 때(공 `$3` bit6 = 0).
- 필살: 내 투구 수 `$E764` >= 20 이고 공이 살아 있지 않을 때.

합격 판정(0x3C72/0x3C92 → 0x3D70) [확인: 실입력]

| 필살 | `$E768` | 0~3 | 4~9 | 10~17 | 18~20 | 등급 2 이상 = 10개 |

| 2 | もう少しだ! | 결과 등급 1 |
| 3 | そのちょうしだ! | 결과 등급 2 |
| 4 | やるじゃないか! | 결과 등급 3 |

### 1-4. 캐치 특훈 투구 표 [확인: 실입력 `tr_full` 30구]
연습 상대는 일반 컴퓨터 두뇌를 쓰되, 공을 든 순간의 공격 plan 을 단계 표(0xD9C8 = [4, 0x0C, 0x10, 4])로 고정하고 대상을 p0 로 고정한다(0xBD30).
| 단계 | plan | 구종 | 수평 속력(px/f) | 공 플래그 | 통계 칸 | 관측 |
|---|---|---|---|---|---|---|
| 1 | 0x04 | 발사선(x=288)까지 걸어가 지상 투구 | 5.5 | 0x41 | `$65` 아님(기본) | 10구 전부 5.5, vz -0.168~-0.254 |
| 2 | 0x0C | 뒤(x=416)로 갔다가 대시 → 발사선에서 지상 대시 투구 | 6.5 | 0x49 | `$66` | 10구 전부 6.5, vz -0.199 |
| 3 | 0x10 | 대시 → 점프 → 공중 차지 투구 | 7.5 + 차지/16 | 0x4D | `$67` | 7.56~7.94 (차지 1~7), 발사 z 약 78, vz -2.5~-2.9. **10구 중 1구는 필살 슛**(타입 0x90, ID 22, 속력 12.56) |
- 속력식은 일반 경기와 같다(0x7D0C): `구속/16 + 1.0(점프) + 1.0(대시) + 차지/16`. 상대 구속 88 → 5.5.
- 코스: 발사 시점의 p0 위치를 조준. 발사선은 x=288 고정, y 는 상대가 그때 서 있던 y(48~216). 관측한 발사 y 는 60~160.
- 3단계 차지: plan 0x10 의 공중 차지(0xCA0C)는 매 프레임 난수&0xFF < 0x40 이면 던진다. 차지가 13~15 에서 떨어지면 필살 판정(0x8CF0)에 걸리고, 특훈에서는 필살 ID 가 22 고정(0xB810). 그래서 3단계에 가끔 필살 슛이 섞인다. 필살 슛도 캐치로 셀 수 있다 [확인: f6528 발사 → f6543 캐치].
- 간격: 타이머가 없다. 흐름으로 정해진다. 상대 캐치 → plan 0x48 대기(약 3~5f) → plan 실행(걷기/대시) → 투구 동작 10f. 내가 잡자마자 되던졌을 때 투구 간격 관측값: 1단계 104~133f, 2단계 205~376f, 3단계 278~311f.
- 내 쪽 규칙
  - B = 언제나 상대(p7) 조준 투구(0x76CC → `$E21E`=0xC380), A 도 같다(패스 없음) [판독만 / B 는 확인].
  - 내 투구는 위력 1/4(0x8A08), 속력은 구속/16 만(점프·대시·차지 가산 없음, 0x7D6E), 필살 불가(0x8C24 → 일반). [판독만] / 내 지상 투구 속력 5.5 [확인].
  - 상대는 내 투구에 대해 **언제나 캐치**를 고른다(0xD612) [판독만 + 확인: 30회 전부 캐치].
  - 캐치로 세는 조건(0x7448 → 0x8CA8): 선수 번호 0 이, **지상에서**, 살아 있는 투구를 잡았을 때만 +1. 공중에서 잡거나 바운스 공을 잡은 것은 세지 않는다 [판독만].
  - 맞으면 평소대로 데미지(상대 위력 25 − 내 방어 12 = 13) [확인: HP 112 → 99], 쓰러졌다 일어난다. 공은 내 코트에 남고, 걸어가 A 로 줍거나(15f) 약 470f 뒤 자동으로 내 손에 온다 [확인: 무입력 실행 f203 피격 → f672 보유].
- 미해결: 3단계에서 캐치 직후 B 를 누르면 투구 통계(`$64`)가 오르지 않은 채 공이 상대에게 돌아간 구간이 있다(`tr_full` f5107~). 원인(받아치기 경로인지) 미해독. 합격 판정에는 영향이 없다.

### 1-5. 필살 슛 특훈 [확인: 실입력 `sp_pass10`, `sp_fail9`]
- 필살 조건은 일반 경기와 같다: 점프(C) 중 B 를 눌러 차지, 차지 카운터가 13~15 일 때 떼면 필살(0x8CF0, `$E69E`=2). 봇은 차지 13 에서 떼어 20회 중 시도한 횟수만큼 전부 성공했다.
- 필살 ID 는 22 고정(0xB810), 위력 75(specials 표), 속력 약 7.4 [확인]. 상대는 캐치 결정(plan 0x38)을 고르지만 필살 슛에는 캐치 자세에 들어가지 않고 서서 맞는다(HP 80 → 15 → 0, 아웃 없음. §4-2-3) [확인].
- 통계(0x8C46): 투구마다 `$64`+1. 필살이면 `$68`+1, 아니면 구종 칸(`$65` 점프 / `$66` 대시 / `$67` 점프+대시). 선수 번호 0 의 투구만 센다.
- 상대의 되던지기: plan 4(지상 투구, 5.5px/f), 위력 1/4(25>>2 = 6 → 내 방어 12 에 데미지 0), 대상 p0 [확인: 속력, HP 불변]. 잡거나 맞은 뒤 주워서 다시 던진다.
- 지상 B 투구도 투구 수에 들어간다(20구 중 일반 투구는 실패로 남는다) [확인 `sp_pass10`: 필살 10 + 일반 10 → 합격].

### 1-6. HUD [확인: 화면 `tr_01`, `tr_06`; 판독만: 좌표 0x211C·0x3DDE·0x3EA2]
| 요소 | 캐치 | 필살 |
|---|---|---|
| 왼쪽 글 | `キャッチNN球` | `必殺シュートNN球` |
| 왼쪽 숫자 | `$E763` 2자리, 화면 x=80·96, y=8 | `$E768` 2자리, x=112·128, y=8 |
| 오른쪽 글 | `あとNN球` | 같음 |
| 오른쪽 숫자 | `10 − $E7E4`(남은 상대 투구), x=256·272, y=8 | `20 − $E764`(남은 내 투구), 같은 자리 |
| 게이지 | 없음 | 가로 막대(어두운 빨강 → 빨강 → 초록 구간) + 위쪽 ▽ 표시 |
- 숫자는 남은 인원 숫자와 같은 16x16 큰 숫자(타일 0x5D7 + n*4). 글 그림은 배너 오브젝트(타입 0x54) ID 0x0F(오른쪽 `あと…球`), 0x10(캐치), 0x11(필살), 0x12(게이지 막대).
- 게이지 ▽(타입 0xC0, 0x3EA2): x = 20 + 8 × 차지(0~15), y = 32. p0 가 공중 차지(서브 0x24) 중일 때 공의 차지 칸(`$3E`)을 따라 움직이고, 던진 뒤 120f 깜빡인 다음 0 으로 돌아간다. 초록 구간이 차지 13~15 자리(x 124~140)와 겹친다 [확인 화면: 초록 약 x 120~143].
- 남은 인원 숫자·얼굴 HUD 는 없다. 일시정지 창은 28 문서 `tr_01`.

### 1-7. 진입 조건·보상 [판독만 + 확인]
- 진입 조건 없음(모드 메뉴 5번째, 언제나 선택 가능) [확인 28].
- 보상 없음. EEPROM 쓰기(0x153B2)를 부르는 곳은 스토리 세이브(0x12C28)와 리그 저장(0x16F46) 둘뿐이고, 특훈 경로에는 능력치 표(`$8000`)나 저장 영역을 쓰는 코드가 없다 [판독만 xref]. 완료 뒤에는 완료 대사 → 모드 메뉴 [확인].

### 2-2. 성적·순위 [확인 `league_3team_2turn`]
- 경기 뒤 기록(0x16302): 이긴 팀 승 +1, 진 팀 패 +1, 양쪽 남은 경기 −1, **승률 = floor(승 × 1000 / (승 + 패))**(경기가 없으면 0). 행렬은 `[승자][패자].승` +1, `[패자][승자].패` +1.
- 승점·득실·세트 수 같은 것은 없다. 경기에는 무승부가 없다(시간 종료도 승패를 낸다, §3).
- 순위(0x16E56): 팀마다 **자기보다 승률이 높은 팀의 수 = 순위 번호**. 같은 승률은 같은 번호를 받고, 다음 번호는 건너뛴다(1위, 1위, 3위). 같은 번호 안의 표시 순서는 참가 순번(먼저 고른 팀이 위).
  - 관측: 1경기 뒤 승률 1000/0/0 → 순위 0,1,1. 2경기 뒤 500/500/0 → 0,0,2. 6경기 뒤 500/500/500 → 0,0,0.
- 승패표(勝敗表, 0x16AE8)는 순위 목록 순서로 순위 번호+1, M/C, 팀, 승, 패, 승률(`.500`, 전승은 `1.000`), 남은 경기 수를 그린다 [판독만 + 28 화면].
- 남은 경기 수 초기값 = (팀 수 − 1) × 턴 수(0x15BAC) [확인: 3팀 2턴 = 4].

### 2-3. 대전 카드와 턴 [확인]
- 대전 카드 표(0x16CA0)의 칸 = 행 팀이 열 팀에게 거둔 `승-패` 누적. 2턴이면 `1-1`, `2-0` 처럼 쌓인다 [확인 `lg_11_two_turn_grid.png`].
- 칸의 `승 + 패` 가 턴 수에 이르면 글자색이 바뀌고(완료 표시) **그 카드는 선택되지 않는다**(0x16034) [확인: 2번 치른 카드를 다시 고르자 화면이 넘어가지 않음].
- 순서 제한 없음: 턴 구분 없이 남은 카드를 아무 순서로 고른다. "턴"은 같은 쌍이 치르는 횟수일 뿐이다 [확인].
- 좌우 배치(0x1603C) [확인: COM-COM, MAN-MAN / 판독만: 나머지]
  | 행 팀 | 열 팀 | 왼쪽(사이드 A) | 오른쪽(사이드 B) | 조작 |
  |---|---|---|---|---|
  | MAN | COM | 행 팀 | 열 팀 | 1P / COM |
  | COM | MAN | 열 팀(좌우 바꿈) | 행 팀 | 1P / COM. 사람은 언제나 왼쪽 |
  | MAN | MAN | 행 팀 | 열 팀 | 1P 패드 / **2P 패드**. 2P 패드 ID(`$E64D`)가 0x0D 가 아니면 선택 불가 |
  | COM | COM | 행 팀 | 열 팀 | `しあいけっか / しあいをみる` 창(서브 14) |
  - MAN 끼리: 2P 패드가 꽂힌 상태에서 카드가 받아들여지고 사이드 A `$17`=1, 사이드 B `$17`=2 가 됐다 [확인 `lgmm`]. 2P 패드가 없을 때의 거절은 `$E64D` 가 매 프레임 하드웨어에서 다시 읽혀 poke 로 만들지 못했다 [판독만].
- 스테이지 = 오른쪽 팀의 홈(표 0x1257A) [판독만, 28].
- 모든 팀의 남은 경기 수가 0 이면 우승 화면(서브 13), 아니면 자동 저장(서브 15) 뒤 리그 메뉴 [확인: 6경기째 뒤 서브 13].

### 2-4. SPECIAL 팀 [확인: 해금 비트 poke]
- 리그 팀 선택(0x15C0E)은 `$E500` bit0 이 서 있으면 아래에 `SPECIAL TEAM` 7칸 줄(CHN URS EGY GRE BRA CHI USA)을 더 그리고, 커서가 그 줄로 내려가 팀을 고를 수 있다 [확인 `lg_09_special_team_select.png`: CHI 확정].
- 해금 비트는 스토리 최종 승리 때 선다(28 §3-1). 스토리를 깨서 얻은 상태로는 돌려 보지 않았다.

### 2-5. 즉시 판정(しあいけっか) [확인 `t29_lg_quick.py`, `league_3team_2turn`]
레이팅(0x3460)
```
raw(team) = Σ(선수 7명) Σ(능력치 j=0..7) floor(능력치[j] * 256 / DIV[j]) * W[j]     (16비트로 잘림)
W   = [16, 2, 1, 1, 12, 2, 2, 1]        (ROM 0x34BC)
DIV = [150, 12, 16, 48, 30, 10, 88, 72] (ROM 0x34CE)
rating = (raw − K) mod 65536,  K = 7 * 16 * b
```
- 능력치 순서는 선수 표 8바이트(HP, 방어, 주력, 점프, 위력, 캐치, 구속, 패스). HP 와 위력의 가중이 크다.
- `b` 는 **원작 버그로 들어오는 값**이다: 둘째 루프가 선수 표가 아니라 직전에 남은 주소 레지스터(a2)의 +9 바이트를 7번 읽는다. 관측한 b 는 127(K = 14224)과 162(K = 18144) 두 가지였다. 한 경기 안에서는 양 팀이 같은 K 를 쓴다 [확인: 명령 단위 가로채기].
- 값 검증: 팀 1 raw 0x9ED4 → 0x6744, 팀 3 raw 0x9F1E → 0x678E(K = 14224) 이 RAM `$E760`/`$E7E0` 과 일치 [확인].

판정(0x34DE)
```
a = rating(왼쪽) >> 8,  c = rating(오른쪽) >> 8        (상위 바이트)
if c >= a: a >>= 1   else: c >>= 1                    (낮거나 같은 쪽을 절반으로. 같으면 왼쪽이 깎인다)
p = floor(a * 256 / (a + c))
r = 난수(0x14EA) & 0xFF                               (난수 호출 1회)
r <= p 이면 왼쪽 승, 아니면 오른쪽 승
```
- 관측: a=103, c=103 → a=51, p=84, r=46 → 왼쪽 승 [확인]. 왼쪽 승률 = (p+1)/256.
- 결과로 이긴 쪽 남은 인원 4, 진 쪽 0 으로 놓고(0x5DCC/0x5DF8) 승리 포즈로 간다. 득점·인원은 기록되지 않는다.
- 난수는 경기 엔진과 같은 시드(`$E620`, VBlank 마다 +2)라 창에서 버튼을 누르는 프레임에 따라 결과가 달라진다.

## 3. こうしき 규칙 (`$E680` = 1)

### 3-1. 규칙 창의 값 [판독만 0x14716·0x16958·0x5436, 화면은 28]
- 규칙 줄: ノックアウト(0) / こうしき(1).
- 시간 줄: 값은 3개뿐(3·5·8분, 표 0x5446). **ノックアウト 일 때는 시간 줄이 잠기고 `むせいげん` 으로 표시**된다(커서를 좌우로 움직여도 소리·변화 없음). こうしき 일 때만 3/5/8분을 돈다.
- 따라서 원작 조합은 `ノックアウト + 무제한`, `こうしき + 3/5/8분` 4가지다. 체력제에 제한 시간을 거는 조합은 원작에 없다(우리 규칙 창은 허용: 자작).

### 3-2. 시간 종료 [확인: poke(`play0` 에 `$E680`=1, 시계 0:02, 남은 인원 변경)]
- 검사(0x5618): `$E220`==0(PLAY OFF 전) 이고 `$E680`==1 이고 시계(`$E684` 4바이트)가 0 이면 경기 상태 0x28.
- 0x28(0x612C): 배너 ID 4(TIME UP) + 효과음 0xAE, 180f. 그 뒤 **남은 인원 `$E757` 과 `$E7D7` 을 비교**해 많은 쪽 승.
- 같으면 0x2C(0x618A): 배너 ID 2(PLAY OFF) 180f → `$E220`=1, **양쪽 남은 인원을 1 로 만들고** 경기 재개. 다음 아웃 1번으로 끝난다. 시계는 0:00 에 멈춘 채 다시 검사하지 않는다.
- [2026-11-18 추가 확인] 0x28·0x2C 핸들러는 공(`$C700`)·심판·배너 오브젝트만 돌리고 선수 오브젝트(`$C000`~)를 돌리지 않는다: TIME UP 181프레임 + PLAY OFF 181프레임 동안 선수는 제자리에 멈추고 공만 움직인다 [확인 `t33_rule_timeup_freeze.py`, 자료 `analysis/data/33_koushiki_oracle/timeup_freeze.txt`].
- 관측: 7-5 → 왼쪽 승, 5-7 → 오른쪽 승, 7-7 → PLAY OFF 뒤 HUD 1-1 로 재개.

### 3-3. HUD [확인]
- 가운데 숫자 쌍 = 양 팀 남은 인원(`$E757`-`$E7D7`, 0~7). 체력제와 같은 숫자다(07 문서 §2-3). 캡처 `lg_08` 의 `6-7` 은 왼쪽 한 명 아웃.
- 얼굴 아이콘은 체력에 따라 내려오지 않고 맨 위(y 8) 고정(07 §2-1). 시계 `M:SS` 가 전광판에 나온다(07 §2-4).

### 3-4. 피격과 아웃 [확인: 바닥 → 아웃(poke), 상대 캐치 → 아웃·같은 편 캐치 → 세이프(2026-11-18 좌표 poke) / 판독만: 나머지]
- 데미지 0(0x853E): HP 는 줄지 않는다 [확인: HP 85 그대로].
- 넉백·쓰러짐은 체력제와 같은 경로(0x84AC → 타입 0x3C → 쓰러짐)다. 방어력으로 무효가 되는 공은 없다.
- 맞는 순간 선수 `$6D`=1(유예 표시), 공 `$3C` = 맞은 선수.
  - 공이 **바닥에 닿으면**(0xA5E2) 그 선수의 `$6D`=0.
  - 공을 **맞은 선수의 상대편이 잡으면**(0x73DE) `$6D`=0.
  - 같은 편이 잡으면 `$6D` 는 그대로 1.
- 쓰러짐 타이머가 끝날 때(0x950C) 내야 슬롯(<4)이고 `$6D`==0 이면 아웃(HP 를 0 으로 놓고 교체 처리 0x8930), `$6D`!=0 이면 일어난다.
- 즉 "맞으면 즉시 아웃"이 아니라 **맞은 공이 바닥에 떨어지거나 상대에게 넘어가면 아웃, 같은 편이 노바운드로 잡으면 세이프**다. 아웃 시점도 피격 순간이 아니라 쓰러짐이 끝날 때다.
- 관측: f272 피격(`$6D`=1) → f309 공 착지(`$6D`=0) → f374 쓰러짐 끝, 남은 인원 7 → 6, 외야와 교체.
- [2026-11-18 추가 확인, `t33_rule_official_safe.py`] 같은 편 캐치: f272 피격 → f274 동료가 캐치 자세로 획득(바닥 접촉 없음) → `$6D` 1 유지 → f374 아웃 없이 기상(7-7, HP 그대로). 상대 캐치: f15 피격 → f18 던진 쪽이 획득 순간 `$6D`=0 → f117 아웃(7-6). 공 `$3C` 는 '맞은 선수'가 아니라 **마지막으로 맞거나 잡은 선수**다(획득 0x73E2·패스 수신 0x746C·수신 대기 캐치 0x9C28·점프볼 쳐내기 0x7CAE 에서도 쓴다). `$6D`=1 은 규칙과 무관하게 모든 피격에서 쓴다(0x850E).
- 외야 슬롯은 체력제와 마찬가지로 아웃 대상이 아니다.

### 3-5. 필살 슛·그 밖의 분기
- 필살 슛(0x8BFA): `$E680`≠0 이면 차지 값과 상관없이 일반 슛(타입 0x14). 차지 입력 자체는 되고 위력·속력의 차지 가산도 그대로다 [확인 poke: 같은 입력이 체력제에서는 타입 0x90·ID 22, こうしき 에서는 타입 0x14, 위력 50·속력 7.42 동일]. 받아치기 필살(`$76`)도 같은 분기 뒤라 나오지 않는다 [판독만].

### 4-1. こうしき 규칙
데이터(`rules.json` 에 추가할 블록 초안)
| 키 | 값 | 근거 |
|---|---|---|
| `official.damage` | 0 | 0x853E |
| `official.outOn` | `floor`, `enemyCatch` | 0xA5E2, 0x73DE |
| `official.special` | false | 0x8BFA |
| `official.cpuDefend` | [서기, 캐치, 웅크림, 캐치, 서기] | 0xD624 |
| `official.times` | [3, 5, 8] 분 | 0x5446 |
| `official.playOffRemaining` | 1 | 0x61C8 |

상태 변화
1. 선수에 `grace`(원작 `$6D`), 공에 `lastHit`(원작 `$3C`) 추가.
2. `hitPlayer(q)`: `ruleMode==='official'` 이면 `dmg=0`, `q.grace=true`, `ball.lastHit=q.pid`. 이벤트 `hit{dmg:0}`.
3. 공이 바닥에 처음 닿는 지점(비행·바운스 공의 z<0 처리): `lastHit` 선수의 `grace=false`.
4. 캐치 성공 지점: 잡은 선수의 사이드가 `lastHit` 선수와 다르면 `grace=false`. 이어서 `lastHit` = 잡은 선수.
5. 쓰러짐 종료 지점(현재 HP 0 이면 아웃으로 가는 곳): `official` 이고 슬롯<4 이면 `grace` 가 false 일 때 아웃, true 면 기상. 체력제 분기는 그대로.
6. `specialReady()`: `official` 이면 false(강제 발동 옵션보다 뒤, 원작 순서는 `$E694` 강제 → `$E680`).
7. `defend()`: `official` 이면 결정 3 → 캐치, 4 → 서기.
8. `checkTime()` 동수: 양쪽 `remaining=1` 로 놓고 `sudden=true`. 이후 아웃은 일반 전멸 판정으로 끝난다(지금의 `sudden_death` 사유는 유지해도 됨).
9. 스냅샷: `rem` 이 1-1 로 바뀌므로 HUD 는 그대로 따라온다. `game_start.rules.mode==='official'` 이면 클라이언트는 얼굴을 맨 위 고정, 체력 표현 끔.

켜는 순서: 엔진 → 차분 하네스 시나리오 2개(피격 후 착지 아웃, 시간 종료 3경우; 원작 쪽은 `poke:E680,1`) → `OFFICIAL_ENABLED`·`OFFICIAL_READY`.

규칙 창 보정(1단계 구현과의 차이): 원작은 `knockout` 이면 시간을 고를 수 없다. 원작과 맞추려면 `knockout` → `time` 0 고정, `official` → 3/5/8(기본 3). 지금의 `knockout + 3/5/8분` 은 자작 조합으로 남길지 결정이 필요하다(§6).

특훈 진행기(엔진 안 또는 `roomGame` 옆의 얇은 상태 기계)
```
intro(120f, 카운터 0) → play → settle(전원 정지 대기) → result(180f) → [합격] 다음 단계 intro | 완료
                                                                  → [불합격] retry 표시 후 같은 단계 intro
```
- 카운터(사이드별): `catch`(선수 0 이 지상에서 살아 있는 투구를 잡음), `throws`(선수 0 의 투구), `special`(그중 필살), `hitTaken`. 엔진 이벤트 `catch`/`throw`/`hit` 로 셀 수 있는지 구현 때 확인. 없으면 이벤트에 `air`·`live` 표시 추가.
- 종료 조건: 캐치 = 상대 `throws` >= 10 이고 공이 비행 중이 아님 / 필살 = 내 `throws` >= 20 이고 공이 비행 중이 아님.
- 단계가 바뀌어도 선수 위치·공 보유자는 그대로.

### 4-3. 리그
데이터 구조(서버 저장, 닉네임당 1개 권고 — 28 §8-7)
```
league = {
  teams: [{team: 0~24, com: bool} x 2~6],     // 참가 순번 = 배열 순서
  turns: 1~9,
  rules: {mode: 'knockout' | 'official', time: 0 | 3 | 5 | 8},
  res:   [[ [승, 패] x n ] x n],               // res[i][j] = i 가 j 에게
  done:  bool
}
```
- 파생 값(저장하지 않고 계산): `wins[i]`, `losses[i]`, `rate[i] = floor(wins*1000/(wins+losses))`(0경기 = 0), `left[i] = (n−1)*turns − wins − losses`, `rank[i] = rate 가 더 높은 팀 수`.
- 원작 레코드(§2-7)와 1:1 로 바꿀 수 있다(니블 압축은 필요 없음).

서버 규칙
| 동작 | 규칙 |
|---|---|
| 만들기 | 팀 수 2~6, 턴 1~9, 팀 중복 불가(원작은 고른 칸에 빨간 틀이 남는다. 중복 선택 가능 여부는 미확인 → 불가로 둠), SPECIAL 7팀은 스토리 클리어 계정만 |
| 설정 변경 | 팀별 MAN/COM, 규칙, 시간만. 팀 수·턴 수 불변 |
| 카드 고르기 `(i, j)` | `i != j`, `res[i][j]` 의 합 < turns. 아니면 거절(토스트) |
| 좌우 | §2-3 표. 사람이 낀 카드는 사람이 왼쪽 |
| MAN 끼리 | 원작은 2P 패드. 온라인에는 맞는 것이 없다 → 1차 구현은 "한 사람이 MAN 팀 여럿을 번갈아 조작"만 받고 MAN 끼리 카드는 (가) 선택 불가 (나) 한쪽을 컴퓨터가 대신 (다) 방 코드로 2번째 사람 초대 중 결정(§6) |
| COM 끼리 | `quick`(즉시 판정) / `watch`(관전: 양쪽 컴퓨터 경기) |
| 즉시 판정 | §2-5 식. `K = 14224` 고정(관측값 중 하나, 원작은 쓰레기 값이라 경기마다 다를 수 있음). 난수는 서버 난수 1회 `& 0xFF` |
| 스테이지 | 오른쪽 팀의 홈(표 0x1257A, 추출 필요) |
| 경기 끝 | `res` 갱신 → 전원 `left == 0` 이면 `done`, 우승 = `rank == 0` 인 팀 전부 |
| 저장 | 만들 때와 매 경기 뒤 |

서버 ↔ 클라이언트 초안
| 방향 | 메시지 | 필드 |
|---|---|---|
| C→S | `league_get` | - |
| S→C | `league_state` | `league`(없으면 null) + 파생 값 `table: [{idx, team, com, w, l, rate, left, rank}]` |
| C→S | `league_new` | `teams[]`, `turns`, `rules` |
| C→S | `league_config` | `com[]`, `rules` |
| C→S | `league_card` | `i`(행), `j`(열), COM 끼리면 `how: 'quick' \| 'watch'` |
| S→C | `league_result` | `i`, `j`, `winner`, `quick: bool` 뒤에 `league_state` |
| S→C | `league_champion` | `champions: [idx...]` |
| C→S | `league_abandon` | 리그 지우기 |
- 사람이 낀 카드와 관전은 기존 방·경기 흐름을 탄다(`game_start` 에 `league: {i, j}`), 끝나면 서버가 결과를 리그에 기록.
- 화면 7장(28 §3-4): 설정, 팀 선택, MAN/COM, 개막식, 리그 메뉴, 승패표, 대전 카드 + 즉시 판정 창, 우승 화면. 좌표는 28 캡처에서 추출.

- ~~こうしき 같은 편 캐치 세이프~~: 2026-11-18 원작 실행으로 확인(§4-1-1). 남은 것은 수신 대기 캐치(0x9C28) 경로와 방어 표 다섯째 칸(둘 다 판독만).
- **つづきから(리그·스토리)**: 에뮬레이터가 EEPROM 읽기를 0 으로만 돌려준다. 레코드 형식은 RAM 사본으로 확정했고 불러오기는 판독만.
- **우승 화면 뒤 저장 처리**, **리그 팀 중복 선택 가능 여부**, **스테이지 표 0x1257A 값 대조**: 보지 않았다.
- **캐치 3단계의 캐치 직후 되던지기가 통계에 안 잡힌 경로**: 미해독(판정 무관).
- **레이팅의 b 값**: 관측 2가지(127, 162). 어떤 화면을 거쳤느냐에 따라 달라지는 것으로 보이나 [추정] 규칙은 찾지 않았다.
- 말풍선 글은 축소 렌더에서 읽었다. 소리는 듣지 않았다(TIME UP 효과음 0xAE 번호만).
