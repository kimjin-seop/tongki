# 07. 경기 중 HUD (원작 레이아웃과 웹 재현 사양)

표기: [확인]=에뮬레이터 렌더 PNG를 직접 열어 확인 + 코드/RAM 일치, [코드]=코드·RAM 수치만 확인(화면 미관찰), [추정], [미확인].
좌표는 320x224 기준 화면 픽셀(좌상단 원점). 스크린샷은 `analysis/gfx/hud/`, 렌더러는 `analysis/scripts/hud_render.py`.

## 0. 주의: 기존 렌더러 버그 수정
`vdprender.py` 가 가로 스크롤 부호를 반대로 처리(평면 x = x+스크롤 → x+416 위치)해 기존 `analysis/gfx/emu_*.png` 의 배경이 실제 화면과 다르다(스프라이트·HUD 위치는 영향 없음).
수정: vdprender.py 29행을 `hx=(hx&0x3FF)` 로 변경(평면 x = (화면 x − 스크롤) mod 512). 새 numpy 렌더러 hud_render.py 와 수정본은 픽셀 단위로 동일(차이 0)하고,
안아트의 `public/assets/rom/bg/stage_00.png` 와 카메라 정렬 시 배경 행 40~60 이 99% 일치 [확인]. 주의: `analysis/scripts/dis.py` 가 표준 `dis` 를 가려 numpy 를 scripts 경로 삽입 뒤에 import 하면 실패하므로 `import numpy` 를 먼저 할 것.

## 1. 결론: 원작 HUD 의 "게이지" = 기둥(폴) 위에 매달린 얼굴 아이콘의 높이 [확인]
- 별도의 HP 막대/색 변화가 **없다**. 내야 4명(좌 4, 우 4)의 얼굴 24x24 아이콘이 세로 기둥(8x32) 앞에 걸려 있고, **HP 가 높을수록 얼굴이 위로, 낮을수록 아래로** 내려온다. 색은 팀 팔레트 고정(HP 별 색 규칙 없음) [확인: hud_02_hp_montage.png, HP 150~1 비교].
- 상단 중앙에 남은 인원 "7 - 7"(큰 숫자 2개 + 하이픈). 하단(코트)에는 HUD 없음. 코트 위에는 조작 선수 머리 위 "1P"/"COM" 화살표 표식만 있다 [확인: hud_05_markers_1p_com.png].
- 필살기/차지 게이지, 이름, 팀 로고, 타이머(스토리) 등은 상단 HUD 에 **없다** [확인: 스토리 AI 경기 2500프레임 동안 HUD 영역에 위 요소 스프라이트가 나타나지 않음; 새로 나타난 UI 타일 0x59b~0x5ae 는 y≥98 코트 위 이펙트].
- 시간제한 규칙($E680≠0)일 때만 타이머 "M:SS" 가 무대 배경 전광판(평면 A 타일)에 표시 [확인: hud_06_timer_mode_E680_1.png].

## 2. 요소별 사양
구현 코드: HUD 얼굴 오브젝트 타입 0x50 핸들러 0xDDD0, 폴 그리기 0x2016/0x1FB6, 인원 숫자 0x208E, 타이머 0x53A4.

### 2-1. 얼굴 아이콘 (스프라이트 3x3타일 = 24x24, 우선순위 높음) [확인]
- 슬롯(내야 0~3) 중심 x: 왼팀(seat0) 116/84/52/20, 오른팀(seat1) 204/236/268/300 (슬롯0 이 중앙에 가장 가까움). 스프라이트 좌상단 x = 중심−12. (코드 표 0xDEFE: 0xF4,0xD4,0xB4,0x94 / 0x14C,0x16C,0x18C,0x1AC, 각 −0x80) [확인: 스프라이트 테이블 x=104,72,40,8 / 192,224,256,288 과 일치]
- 얼굴 상단 y = **28 − floor(hp/4)** (화면 px). 예: hp85→7, 76→9, 56→14, 150→−9(화면 밖으로 일부 잘림) [확인: RAM obj+0x2E = 0xB4 − hp>>2, 스프라이트 y−(−128)−24 와 일치]. hp 는 선수 오브젝트 +0x40 의 현재 HP(스탯 s0 와 같은 단위, 최대치 정규화 없음).
- 좌우: 왼팀(seat0) 가로 반전(HFlip), 오른팀 비반전 [확인: SAT hf=1/0].
- 팔레트: 왼팀 CRAM 라인0, 오른팀 라인1 = 각 팀의 스프라이트 팔레트(ROM 0x2FAEE: 팀별 u16 오프셋 → 16워드). 얼굴 배경색(초록/노랑 등)은 이 팔레트의 값 [확인: CRAM=테이블 일치].
- 어떤 얼굴인가: 슬롯에 서 있는 선수의 선수번호 idx(0..6) → 팀 얼굴 스트림의 idx 번째 24x24 (스트림 63타일 = 7 x 9타일, 열 우선). 팀별 스트림 포인터 ROM 0x4EFFE (u32 x25) [확인].
- 그리기 순서: 얼굴이 폴 앞(스프라이트 목록상 먼저).
- 상태 [확인: hud_01, hud_03, hud_07 montage + 수치]
  - 등장: 경기 시작 연출 시 y=192(상단 y=40) 에서 시작해 목표 위치까지 매 프레임 1px 상승(약 26~35프레임). 교체 투입된 선수의 얼굴도 동일(바닥에서 올라옴).
  - 아웃(HP 0): 얼굴이 현재 위치에서 매 프레임 1px 하강해 y_top=40 에 닿으면 얼굴과 폴이 함께 소멸(약 12프레임). 슬롯은 교체 선수가 내야에 들어올 때까지 빈 채 유지(폴도 없음). 남은 인원 숫자는 선수가 실제로 코트를 벗어난 뒤(아웃 연출 후) 감소 [확인: AI 경기 로그 f248 낙하 → f260 소멸 → f349 인원 6 → f420 교체 얼굴 등장].
  - 교체: 외야 선수(idx4~6)가 내야로 들어오면 그 선수의 얼굴이 해당 빈 슬롯에 등장(예: 슬롯3 에 p4) [확인].
  - HP<20 떨림 [코드+수치 확인]: 60프레임 주기 중 31~59프레임에 x,y 가 ±1~2px 무작위 흔들림(수치 로그 확인, 육안 미관찰).
  - 규칙모드($E680≠0, 데미지 없는 즉사 규칙) 에서는 y_top 8 고정 [확인: 수치 y=160→상단 8]. 스토리/기본 규칙은 위 식.
  - 사이드 교체 플래그(side+0x15≠0)면 좌/우 배치 테이블·반전이 뒤바뀜 [코드; 정상 경기에서 미관찰].

### 2-2. 기둥(폴) [확인]
- 8x32(1x4타일), 얼굴 중심 x−4, y 8~40 고정(얼굴 상태와 무관), UI 팔레트(라인2). 얼굴이 존재하는 동안만 표시. 파란 선+밝은 마디.

### 2-3. 남은 인원 [확인]
- 큰 숫자 스프라이트 16x16(2x2타일): 왼 (136,16), 오른 (168,16); 하이픈 8x8 (156,20). 값 = 각 팀 남은 인원(0~7, 한 자리) ($E757=왼, $E7D7=오른, 초기 7). 숫자 타일 = 0x5D7+n*4, 하이픈 0x5FF. 확인한 값: 7-7, 6-4, 5-3, 2-0, 1-1.
- 기타 모드($E69C 0~3, $E277)에서는 별도 2자리 카운터를 (256,8),(80,8) 등에 그림 [코드; 미관찰 — 웹 불필요로 판단].

### 2-4. 타이머 [확인(E680 강제 설정 렌더)]
- 시간제한 규칙에서만. 형식 "M:SS"(분 1자리, ':' , 초 2자리), 8x8 ASCII 폰트 타일 4개, 흰 글씨 검정 바탕. 평면 A 타일 열 34~37, 행 9 → 평면 좌표 (272,72)~(303,79). **스크롤하는 배경 평면에 그려지므로 카메라와 함께 움직임**(스토리 모드는 표시 안 함, 같은 자리에 SEGA 간판). 웹은 배경 합성본에 이 자리(전광판)를 맞춰 그리거나 화면 고정 위치에 그려도 무방 [추정].
- 시간 포맷: E685=분, E686=초(60fps 카운트다운). 스토리 경기 시작값 3:00.

### 2-5. 조작 선수 표식 [확인: hud_05]
- 2x2타일(16x16) 스프라이트 "1P"(타일 0x583), "COM"(타일 0x58B), UI 팔레트. 해당 선수 머리 위 월드 좌표에 따라다님(정확한 오프셋 [미확인], 화면에서 머리 위 약 16~24px 위로 관찰).
- 조작 선수 전환은 이 표식 이동으로만 표현. 얼굴 아이콘에 조작 강조 표시는 없음 [확인].

### 2-6. 아웃/시작 연출 문구 [미확인]
- 경기 시작 직후 화면에 "GO"/배너 스프라이트(타일 0x60, 0x78 등)가 보이는 구간이 있음(상태 0x0C~0x14). 배너 객체(0x54 핸들러 0xDFD0)의 글자 종류·위치·종료 시퀀스는 미해독. 결과/승패 배너도 미작성.

## 3. 팀 번호 대응
- 서버 팀 번호 0~24 = ROM 팀 인덱스($E704/$E784, 0x4EFFE 포인터표, 0x2FAEE 팔레트표) 와 동일 [확인: 서버 teams.id 가 ROM 표 인덱스, 스프라이트 시트 team_NN 과 같은 번호]. 아틀라스 행 = 팀 번호, 열 = 선수 idx.
- 일부 팀은 같은 스트림 포인터를 공유(예: 팀 8~14 와 15~21 의 얼굴 데이터 동일, 팔레트만 다름) — 추출은 포인터 기준으로 팀별로 완성.

## 6. 웹 구현용 그리기 사양 (320x224 캔버스, 모두 정수 좌표)
| 요소 | 좌표/크기 | 표시 조건 | 데이터 소스(서버 snap) |
|---|---|---|---|
| 폴 | (cx−4, 8) 8x32, pole.png | 해당 슬롯 얼굴 존재 | 아래 얼굴과 동일 |
| 얼굴 | (cx−12, 28−floor(hp/4)) 24x24, faces_atlas (idx*24, team*24), 왼팀 좌우반전 | 슬롯 0~3 에 살아있는 내야 선수 | snap.p[pid][4]=hp, p[pid][5]=slot, 선수 idx=pid%7, 팀=game_start.teams[seat].id |
| 슬롯 cx | seat0: 116/84/52/20, seat1: 204/236/268/300 (슬롯 0~3) | — | slot=snap.p[..][5] |
| 등장 | y_top 40→목표, 1px/프레임 | 슬롯에 새 선수가 생김(시작·교체) | slot 점유 선수 변화를 클라이언트가 검출 |
| 아웃 | 현재 y→40, 1px/프레임 후 얼굴+폴 제거 | hp==0 (p[6]&8 dead) | p[4], p[6] |
| HP<20 떨림 | ±1~2px, 60프레임 중 31~59 | hp<20, 규칙모드 아님 | p[4] |
| 남은 인원 | 숫자 (136,16)/(168,16), 하이픈 (156,20), digits_big.png | 항상 | snap.rem[0], rem[1] |
| 타이머 | M:SS, 8x8 글리프, 배경 전광판(평면 (272,72)) 또는 고정 위치 | 시간제한 규칙일 때만 | snap.clk(남은 프레임, 60fps)·sd(서든데스) |
| 조작 표식 | 16x16 "1P"/"COM", 해당 선수 머리 위 | 항상(1P 는 조작 선수, COM 은 상대 조작/ AI 대표) | snap.ctrl[0..1] |

서버 snap/game_start 에 없어서 추가 필요(또는 확인 필요)한 값:
1. 규칙모드 플래그(데미지 없는 즉사 규칙, 원작 $E680) — 웹이 이 규칙을 쓰면 game_start.rules 에 `noDamage`/`hpFixedHud` 필요(쓰지 않으면 불필요).
2. 시간제한 사용 여부 — `rules.limitFrames` 가 0/없음이면 타이머 숨김 처리(현재 limitFrames 로 판단 가능, 스토리 규칙 시 0 으로 내려오는지 확인 필요).
3. 교체 투입된 선수의 slot 갱신 — snap.p[pid][5](slot)가 외야→내야 교체 시 내야 슬롯 값으로 바뀌는지 확인 필요(안 바뀌면 "빈 슬롯에 들어온 선수" 를 알 수 있는 필드 추가).
4. 아웃 선수의 코트 이탈 후 rem 감소 시점이 원작(연출 후)과 같은지 — 얼굴은 hp==0 시점, 숫자는 rem 변화 시점에 각각 반영하면 원작과 같음.
5. 조작 표식의 머리 위 오프셋 — 원작 좌표 미해독이라 웹은 임의 오프셋으로 시작.
