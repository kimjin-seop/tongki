# 31. 필살슛 이름 매핑 (선수 → 필살 ID → 한국판 슛 이름 → 말풍선 문구)

조사일: 2026-11-18. 조사·매핑 자료만 작성했다(코드·서빙 데이터 수정 없음). 신규 파일은 이 문서와 `analysis/data/special_names_draft.json` 2개.
근거 수준 표기는 이 문서와 초안 데이터의 `level` 필드에만 둔다. 말풍선·대사·화면에는 넣지 않는다.
번호 주의: `31_campaign_remeasure_2.md` 가 이미 있어 번호 31 이 겹친다(지시된 파일명 그대로 썼다. 필요하면 번호만 바꾸면 된다).

## 0. 결론

- 나무위키 두 문서를 읽는 데 성공했다(막힘 없음). 다만 페이지 요약 도구를 거친 2차 판독이라 원문 직접 대조는 아니다(§1 한계).
- 이름이 붙은 선수 27칸 중 **확정 5 / 추정 9 / 미확인 13**. 나머지 148칸(게임 오리지널·한국판 이름 없는 선수)은 대상 밖이며 기본 문구를 쓴다.
- **통키(팀0 idx0, ID 22) = 불꽃슛**, 말풍선 `불꽃슛!!` [확정].
- **'도끼'가 들어가는 기술은 있다**: 장도끼의 도끼슛(도끼날슛, 원판 액스 슛)과 그 강화형 고공 미사일 슛. ROM 에서 장도끼(팀1 idx1)는 ID 11 을 혼자 쓴다 → `도끼슛!!` [확정].
- ROM 은 선수 한 명에 필살 ID 를 하나만 준다. 한 선수가 여러 ID 를 던지는 경우는 세 가지뿐이다(§4): 팀23 남타이거(무작위 풀), 받아치기(잡은 공의 ID 유지), 필살 특훈(ID 22 고정).

## 2. 서버가 필살 ID 를 정하는 규칙

`server/engine/match.js` `pickSpecialId(p, keepId)` (1049행), 표는 `server/data/specials.json`(`row` = `special_shots.csv` 와 동일, 대조함).

1. 특훈이면 `training.specialId`(22) 고정.
2. 받아치기(`keepId`)면 잡은 공의 ID 그대로.
3. 그 외 `row[팀id][p.idx]`. 값이 -1 이면 무작위 풀 32항목에서 뽑는다(팀23 idx0 뿐).

**선수 식별(말풍선용)**: `special` 이벤트 `{p, id}` 의 `p` = `seat*7 + idx`(`match.js` 262행). `seat = floor(p/7)`, `idx = p % 7`, 팀 id = `game_start.teams[seat].id`(`cutin.js` 가 `teamIds[seat]` 로 이미 같은 방식 사용). 조회 키 = `` `${teamIds[seat]}:${p % 7}` ``. 서버·프로토콜 변경은 필요 없다.

### 2-1. 말풍선 사양과 위치 따라가기 (구현 담당 전달용)

- 요구 연출: 필살 투구 순간 **투구 선수 머리 위 말풍선**에 슛 이름을 외치듯 표시(예: 통키 `불꽃슛!!`). 기존 컷인(`cutin.js`)은 2026-11-18 에 미사용 처리되었고(파일 1행 주석) 이 말풍선이 대신한다.
- 선수가 점프·이동·착지해도 말풍선은 그 선수의 현재 화면 위치를 따라가고 머리 위 간격은 일정해야 한다(필살은 공중 차지 투구라 표시 중 착지가 거의 항상 일어난다).
- **따라가기 방법(한 줄)**: 말풍선은 좌표를 저장하지 않고 `{pid, id, start}` 만 들고 있다가, 매 그리기마다 `render.js draw()` 의 `items.find((i) => i.pid === pid)` 로 그 선수의 보간 위치 `it.pos = [x, y, z]`(스냅 `a.p[pid]`·`b.p[pid]` 의 `lerpPos`)를 다시 읽어 `화면 x = round(x - cam)`, `발 화면 y = round(y/2 - z + Y0)`, `머리 위 = 발 화면 y + this.headTop(it)`(자세별 스프라이트 머리 top, 음수. 없으면 특훈 말풍선과 같은 -36)에서 일정 간격을 뺀 자리에 그린다.
- 같은 방식의 선례: 조작 표식 1P/2P/COM(`render.js` 154~165행, `headTop` + `MARKER_GAP`), 특훈 말풍선(`training.js bubble(g, a, pos, cam, top)`, 168~171행), 임팩트 오라(`impact.js` 의 `posOf(pid)`). 새 스냅샷 필드는 필요 없다(선수 `p[pid]` 의 x·y·z 와 자세가 이미 있다).
- 주의: 선수가 퇴장(`ST.GONE`)이면 `items` 에 없으므로 그 프레임은 그리지 않는다. 화면 위로 잘리지 않게 y 하한을 둔다(표식은 `Math.max(0, …)`). 표시 시간 40~60틱, 새 필살이 오면 교체. 그리기 층은 표식·말풍선 층(선수·임팩트 앞층 뒤, HUD 앞)이 맞다. 명중 흔들림은 세계 그림 이동이라 말풍선도 함께 흔들린다.
- 폭: 가장 긴 문구가 8자(`회전회오리슛!!`)다. 12px 도트 글꼴이면 약 96px, 8px 이면 약 64px. 화면 좌우 끝에서 잘리지 않게 x 를 가둔다.

### 8-2. 결정 C: byId 표

조회 순서: `byPlayer[키].shouts[id]` → `byPlayer[키].shout` → `byId[id]` → `default.shout`.
이름 없는 선수는 자기 ID 든 받아친 ID 든 그 공의 이름을 외친다(공 그래픽과 항상 맞는다).

작명 기준
- 궤적(`06` §2) → 공 색(`special.js` `PAL_ID`) → 잔상·숨김(`GHOST`·`HIDDEN`) 순으로 특징을 잡았다. 같은 핸들러를 쓰는 ID 는 색으로 갈랐다.
- 느낌표 포함 5~8자. 가장 긴 것은 `회전회오리슛!!` 8자 그대로.
- `불꽃슛!!`(22·25) 한 쌍을 빼면 이름이 겹치지 않는다.
- 이름 있는 선수의 슛 이름(불꽃·도끼·파워·회전회오리·면도날·번개·스위치·크로스)은 그 선수의 ID 에만 쓰고 다른 ID 에 쓰지 않았다. 스위치슛·크로스슛은 투구 폼·합동 기술이라 `byId` 에 넣지 않았다(선수 전용).
- 공 색 C·E(옅은 하늘색)는 명단에서 팀 5·11·18(서북 탱크스·러시안 베어즈·크렘린 베어즈)만 쓴다. 그래서 9·50·51·52 를 눈·얼음 계열로 묶었다.
- 한계: 공 스프라이트 모양(`SPR` 0x0C~0x1E)은 눈으로 대조하지 못했다. 이름은 궤적·색·잔상만으로 지었다.

- **일치**: 이름 있는 선수의 슛 이름과 같다(§3 의 확정/추정을 따른다).

### 8-4. 구현 전달 (윤프론, `shout.js` `textFor`)

한 줄: `const s = e?.shouts?.[id] ?? e?.shout ?? this.data?.byId?.[id] ?? this.data?.default?.shout;` 로 `byId` 폴백을 한 단계 넣고, 파일 머리 주석 4~5행(받아치기 = 기본 문구)을 새 순서로 고친다. 데이터 키는 문자열이지만 `byId[id]` 는 숫자 id 로도 읽힌다. 서버·프로토콜 변경 없음.
