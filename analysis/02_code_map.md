# 02. 코드 맵 (68000): 부팅 / 메인 루프 / VBlank / 상태 머신 / 입력

범위: ROM 0x200 ~ 0x17075 가 68000 코드(+ 코드 사이사이 데이터 테이블). 0x17078~ 에 소형 코드 일부, 0x18000 이후는 순수 데이터.
전체 선형 디스어셈블: `analysis/disasm_code.asm` (자동 생성, 데이터 구간은 쓰레기 명령이 섞임). 임의 주소 보기: `python -I analysis/scripts/dis.py <hex주소> [줄수]`.
표기: **[확인]** = 코드를 직접 읽어 확인, **[추정]** = 정황 근거.

## 1. 부팅 (0x200 ~ 0x458)
- 0x200: 모든 미사용 예외 벡터의 도착점(`nop;nop;bra.b $200` 정지). 0x206: Reset. 표준 SEGA 초기화(TMSS, Z80 버스/리셋, VDP/PSG 테이블 0x294) 후 0x300.
- 0x300~0x358: VDP 대기 → **체크섬 검증**(0x200~ROM끝 워드합 == [0x18E]) → 실패 시 0x490(화면 단색+무한루프). [확인]
- 0x35C~0x3E0: 패드 포트 초기화, RAM 전체 클리어, `'init'`($696E6974 @ $FFFC) 마커 검사(웜부트 시 RAM 유지),
  ROM 0x18836(1400B) → RAM $FF8000 (**팀/선수 능력치**), ROM 0x18DAE(2800B) → RAM $FF8800 (**AI 파라미터**) 복사. [확인]
- 0x3EA: 0x5436 호출(사운드/EEPROM 초기화로 추정), 두 "사이드 구조체" $E700/$E780 초기화(+0x17 = 사이드 번호 1/2), 0x1418/0x1452(VDP 레지스터 초기화), Z80 사운드 드라이버 업로드(0x15B4).
- VDP 설정 [확인, 0x142A 테이블]: H40(320px) 224라인, 64x32 플레인, Scroll A=0xC000, Scroll B=0xE000, Window=0xB000, Sprite table=0xA800, HScroll=0xAC00, VInt 사용. HInt 허용 비트는 켜져 있으나 SR=$2500 이라 레벨4는 항상 마스크됨(= HInt 미사용).

## 2. 메인 루프 (0x458) [확인]
```
0x458: SR=$2500; SP=초기값
       d0 = [$E600] ; jsr (0x5D4 + d0)  ; ← 게임 상태 디스패치(롱 포인터 테이블)
       $E60C++ (프레임 카운터)
       jsr 0x16CE  ; 사운드 커맨드 큐($E610..) → Z80 메일박스($A01C0A..)
       bra 0x458
```
- 상태 번호는 **4의 배수 바이트 오프셋**($E600)이며, 상태 핸들러는 보통 "VBlank 대기 후 1프레임분 처리"(0x2A60 폴링 / 0x2562 페이드 / 0x256C 페이드아웃)와 서브상태($E400 또는 $E602)로 구성.
- 프레임 동기: VBlank 핸들러가 `$E620 += 2`(RNG 시드 겸 프레임 틱)를 증가시킴.

## 3. VBlank 핸들러 (0x914) [확인]
```
SR=$2700; 레지스터 저장; $E60E 카운트다운; $E620 += 2;
d0=[$E608]; jsr ([0x8D4 + d0])   ; VBlank 모드 테이블
복귀
```
VBlank 모드 테이블 0x8D4 (4바이트 엔트리): 0:rts(0x4AE) · 4:0xA68(0x3242 호출 후 0x94A: 화면 표시ON+패드+DMA) · 8:0xA72(**인게임**: 패드 읽기, 팔레트 DMA(0xED00→CRAM), 스프라이트 DMA(0xE800→VRAM 0xA800), 스크롤, 시간 표시 갱신) · 0xC:0xBCC · 0x10:0xC3A · 0x20:0xF7DC · 0x24:0xB42 · 0x28:0x17078 · 0x2C:0x142D8.
- 일반 상태 코드는 `$E60A` 에 원하는 모드를 쓰고 0x2562 가 `$E608` 로 확정(메뉴=4, 인게임=8 등).
- DMA 는 모두 68000 → VDP 직접 전송(Z80 버스 요청 $A11100 으로 Z80 정지 후 수행).

## 4. 입력 처리 [확인]
- 0x0D82/0x0D9A: 포트1($A10003)·포트2($A10005)를 **3버튼 방식(TH=0/1 2단계)**으로 읽음(6버튼 확장 없음). 결과 4바이트:
  `$E634`=P1 **현재 눌림**, `$E635`=P1 **방금 눌림(edge)**, `$E636/$E637`=P2 동일.
  비트: bit0 Up, 1 Down, 2 Left, 3 Right, 4 B, 5 C, 6 A, 7 Start. (논리 반전해 "눌림=1")
- 0x2728: **버튼 배치(키 컨피그) 리맵** 함수. d0=설정 번호(0~5, 사이드별 $E692/$E693), d1=원본 패드 워드(상위=현재, 하위=edge). A/B/C 의 6가지 순열을 지원하며 방향키·Start 는 마스크 $8F8F 로 그대로 통과. 결과를 `$E20C`(현재 입력 워드)에 두고 선수 핸들러가 읽음. [확인]
- 컴퓨터 조작 선수는 같은 `$E20C` 형식의 입력을 AI 가 만들어 넣는 구조로 보임(아래 AI 섹션). [추정]

## 6. 사운드 [확인/추정]
- Z80 드라이버: ROM 0x7DE0C(0x105C 바이트, `F3 F3 ED 56`=DI/IM1 시작) → Z80 RAM 0x0000, 데이터 ROM 0x7EE68(0x888B) → Z80 0x1100, 초기 파라미터(0x15FC) → 0x1C00. 업로드 루틴 0x165C.
- 메인 CPU → Z80: 커맨드 바이트를 `$A01C0A/B/C` 에 씀(0x16CE: 큐 $E610(8엔트리) 소비). 효과음/BGM 번호는 `jsr $16B6`(d0=ID; 예: 0xA1, 0xA2, 0xA3, 0xC2, 0x8C, 0x98, 0xE0, 0xE1). FM 음색 데이터 0x7C000대(0x31 0x20 ...) 추정.
- 재구현 시: 웹에서는 ID→효과음/BGM 매핑만 가져오면 되며 Z80 에뮬은 불필요(음원 자체는 별도 제작/대체 권장).

## 9. 오브젝트 시스템 [확인]
- 0x18D0: 64개(0x80B 간격) 순회, `[obj+0]`(& 0x7FFC)로 **0x6D4 핸들러 테이블**(4B 엔트리, 약 0x50개)의 함수 호출. 비트15=초기화 완료 플래그.
- 0x18F0: 오브젝트 갱신 + 스프라이트 구성(0x1944): 프레임 구조체(+0xC)의 조각 6B(y,size,tile,x,flipx)를 VDP 스프라이트 엔트리로 변환. 화면좌표 $2C/$2E = (x - 카메라 + 0x80, y/2 - z + 0xE0) → **y 를 반으로 줄인 의사 3D(아이소메트릭)**, z 가 높이.
- 위치/속도는 16.16 고정소수: `$20(x) $24(y) $28(z)`, `$30/$34/$38`=속도(vx,vy,vz), 0x1B26 이 매 프레임 `pos += vel`, 0x1DEA 가 `vz -= gravity($E200=0x3000)`.
- 애니메이션: 0x19EC/0x1AA2 계열 — 애니 레코드 [프레임수][속도][프레임포인터…] 로 `+0x10(프레임 idx) +0x11(타이머)` 를 진행.
- 대표 타입(0x6D4 테이블 인덱스): 0x20=내야 선수, 0x24=외야(상·하 라인), 0x28=외야(후방), 0x10=?, 0x18=투구(비행 중) 공, 0x1C=구르는/정지 공, 0x2C=커서, 0x3C/0x40/0x44/0x48/0x4C=피격·아웃 상태 등.

## 10. 난수 (0x14EA) [확인] — 웹 재구현에서 그대로 복제 가능
```
seed = [$E620] (0이면 0x2A6D365A)
x = seed
t = x*41            (32bit)
r = (t & 0xFFFF) + (t >> 16)   (16bit)
new_seed = (r << 16) | (t & 0xFFFF)
return r
```
VBlank 마다 `$E620 += 2` 되므로 시드에 프레임 타이밍이 섞임(리플레이 재현엔 시드/입력 로그 필요).
