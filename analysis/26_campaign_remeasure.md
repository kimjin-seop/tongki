## 0. 결론 먼저

1. [관측] 캠페인은 **전 구간에서 어려워졌고 경기는 짧아졌다.** 같은 봇·같은 시드로 캐치 50% 봇(aggr50) 승률 평균 71.3% -> 52.2%, 방어 없는 필살기 봇(aggr0) 27.1% -> 11.9%, 평균 경기 시간 252초 -> 195초(aggr50). 변화가 가장 큰 곳은 초반(k0~2, aggr0 87% -> 28%)과 보스(k14, 캐치 100% 봇도 100% -> 60%).
2. [사실+관측] 가장 큰 원인은 컴퓨터 필살기다. 컴퓨터 필살기는 이제 캠페인 표(`specialChance256`)가 아니라 **원작 선수 파라미터**에서 나온다. `specialChance256` 이 0 인 1경기(k0)에서도 경기당 3.3~4.5회 나오고(이전 0회), 필살기 한 방의 데미지는 평균 63(k0)으로 통키 팀 내야 HP 55~85 의 대부분이다. 컴퓨터의 일반 투구도 대시·점프·차지가 붙어 세졌다(k0 내야 일반 투구 위력 평균 28 -> 38).
3. [관측] **무한 경기는 없다.** 현재 엔진 12,600경기에서 draw_cap 0, 미종료 0, 예외 0, 최장 경기 시계 504초. 이전(f4)에는 4,500경기 중 draw_cap(15분 무승부) 14경기가 있었다.
4. [관측] 극단 구간: (a) 방어 입력이 없는 봇(random, chase)은 15경기 전부 0%, (b) 캐치를 놓치지 않는 봇(aggr100)은 k0~13 전부 100%, (c) k14(팀 24)는 캐치 75% 봇이 3%, 100% 봇이 60%이고 그 60%는 전부 시간 종료·서든데스 판정이다. 원인 후보는 §4.
5. [사실+관측] 난이도 설정 중 지금 살아 있는 것은 `rules.cpu.levels.1.blunder256`(레벨 1 의 방어 실수 [자작]) 하나다. **레벨 2 와 3 은 통계적으로 같고**(49.2% vs 50.4%), `specialChance256` 은 승률에 영향이 없다(51.8% vs 52.2%). 로비에서 고르는 난이도 2·3 도 같은 상대다.
6. 방침("원작과 같은 난이도")에 비추면 지금 값은 대부분 원작 데이터 그대로이므로 **수치를 조정하자는 제안은 없다.** 정할 것은 원작에 없는 장치 3개의 처리다: 레벨 1 방어 실수, 5분 제한시간, 죽은 설정 정리(§5).

## 1. 측정 방법

### 1-1. 사람 역 봇 (tools/campaign_remeasure.mjs) [자작]
종전 `tools/campaign_sim.mjs` 는 좌석0 도 엔진 AI 가 움직였다(`humans=[false,false]`). 이번에는 **좌석0 을 사람 좌석(`humans=[true,false]`)으로 두고 패드 비트만 넣는다.** 조작 전환·동료 움직임·강제 회수는 실제 사람 경기와 같은 경로를 탄다.

| 봇 | 입력 규칙 | 뜻 |
|---|---|---|
| random | 4~24프레임마다 방향 9종 + B 35% / A 10% / C 15% 를 새로 뽑는다 | 무작위 입력 |
| chase | 느슨한 공으로 걸어가 줍고, 내야가 공을 들면 x 200 까지 걸어가 지상 투구. 방어 입력 없음(서 있는다) | 단순 추적 |
| aggrNN | chase + 내야 보유 시 뒤로 물러났다 대시 -> 점프 -> 공중 차지 13 에서 뗌(필살기 창). 상대 투구마다 NN% 확률로 캐치 시도(닿기 4프레임 전 공 쪽을 보고 B) | 공격적. NN = 0/25/50/75/100 |
| aggrNN + FM | 위에 더해 포메이션 어택(Start) 3회를 쓸 수 있을 때마다 쓰고 B 를 눌러 엔드 어택 | 환경변수 `FM=1` |

- 시드: 경기 k 마다 `1000*(k+1)+2*i`, i=1..60 (짝수만. 엔진이 난수 시드의 최하위 비트를 버리므로 홀수 시드는 시드-1 과 같은 경기가 된다, 문서 25 §11-3). 봇 난수는 엔진 난수와 분리.
- 한 칸 60경기, Wilson 95% 구간. 한 칸의 구간 폭은 ±10~13%p 다. 칸 하나의 5~10%p 차이는 읽지 말 것. 구간 평균(180~900경기)은 ±2~5%p.
- 이전 엔진 비교: `_backup/engine_before_fidelity4/engine` + 그 rules.json 을 임시 폴더에 놓고 `ENGINE=` 환경변수로 같은 스크립트·같은 시드를 돌렸다. 팀·캠페인·스테이지 데이터는 현재 것(그 사이 바뀌지 않음).

### 1-2. 봇의 한계 (절대 승률이 아니다)
- 봇은 피하지 않는다(점프·웅크림·옆걸음 없음), 패스하지 않는다, 외야에서는 지상 투구만 한다.
- aggr 봇의 캐치는 공 위치·속도를 읽어 정확한 프레임에 누른다. 사람의 반응 시간·지연이 없다. aggr100 은 "실수하지 않는 사람"의 상한이고 사람에게는 나오지 않는 값이다.
- 그래서 이 표는 **봇 사이 / 버전 사이 / 경기 사이의 상대 비교**로만 읽는다. 사람이 어느 봇에 가까운지는 실플레이로 확인해야 한다(§6).

### 1-3. 실행한 명령
```
ENGINE=<현재 엔진 사본>/index.js node tools/campaign_remeasure.mjs 60 random,chase,aggr0,aggr25,aggr50,aggr75,aggr100   # 27분
ENGINE=<f4 엔진>/index.js        node tools/campaign_remeasure.mjs 60 random,chase,aggr0,aggr50,aggr100               # 17분
OVLV=1|2|3 ENGINE=<현재 사본> node tools/campaign_remeasure.mjs 60 aggr50     # 전 경기 cpuLevel 덮어쓰기
OVSP=0     ENGINE=<현재 사본> node tools/campaign_remeasure.mjs 60 aggr50     # specialChance256 전부 0
FM=1       ENGINE=<현재 사본> node tools/campaign_remeasure.mjs 60 aggr0,aggr25,aggr50   # 봇이 포메이션 어택 사용
node tools/campaign_sim.mjs 60 2 - 0 14      # 종전 지표(컴퓨터 대 컴퓨터): 03:38 시점 엔진·f4·f3 엔진 각각
```
전부 순차 실행. `ENGINE=` 을 빼면 `server/engine` 을 그대로 쓴다. 원자료(출력 그대로)는 `analysis/data/26_remeasure/`. `npm test` 44개 통과(도구 추가 뒤 확인).

### 1-4. 측정 도중 엔진이 바뀌었다 (보고)
- 첫 측정(03:00~04:25)을 돌리는 사이 다른 작업으로 `server/engine/match.js` 가 바뀌었다(난수 시드 짝수 고정, 문서 25 §11-3, 백업 `_backup/engine_before_outfield`). 첫 측정은 수정 전·후 엔진이 섞였고 홀수 시드가 절반이었다.
- 그래서 04:36 에 현재 엔진·데이터를 임시 폴더에 복사해 고정하고(측정이 끝난 뒤 `server/engine`·`server/data` 와 다시 비교해 같음을 확인) **짝수 시드로 전부 다시 쟀다.** 이 문서의 표는 전부 다시 잰 값이다.
- 첫 측정(시드 1~60, 수정 전 엔진)은 `analysis/data/26_remeasure/first_run/` 에 남겼다. 두 측정은 시드가 절반만 겹치는데(짝수 2~60 은 같은 경기, 나머지는 다른 표본) 봇별 전체 승률이 random 0.0/0.0, chase 0.0/0.0, aggr0 13.1/11.9, aggr25 25.9/26.6, aggr50 51.6/52.2, aggr75 82.8/82.2, aggr100 97.1/97.3% 로 같다. 시드 수정은 캠페인 승률을 바꾸지 않았고, 결론은 두 측정에서 같다.

## 3. 사실 정리 (코드·데이터에서 읽은 것)

1. [사실] 컴퓨터 활성 내야의 필살기는 plan 0x14(`ai.js` attackRom: 난수 8비트가 선수 파라미터 b5 이상일 때)에서 나온다. `specialChance256` 을 읽는 코드는 `ai.js` 922행 부근의 종전 자작 경로뿐이고, 그 경로는 직역 모드에서 **포메이션 진행 중의 보유자**에게만 돈다(측정: 좌석1 보유 프레임의 약 17%가 포메이션 중, 그 밖 0). 포메이션 중에는 서버가 선수를 직접 움직여 그 계획이 실행되지 않으므로(측정: 포메이션 중 필살기 0회) 값이 0 이 아니면 난수만 한 번 더 쓴다.

## 4. 극단 구간과 원인 후보

### 4-1. 방어 입력이 없으면 0% (random, chase 전 경기 / aggr0 는 k4 이후 0~10%)
- [관측] 서 있는 선수를 향한 컴퓨터 투구는 사실상 전부 맞는다(chase k0: 경기당 CPU 투구 17.3, 봇 피격 17.2). 이것은 이전(f4)도 같았다(41.9 / 41.8).
- [관측] 달라진 것은 한 방의 크기다. k0 기준 내야 일반 투구 9 -> 29, 여기에 필살기 63 이 경기당 3~4회 더해진다(T10). chase 봇의 k0 경기 시간이 262초 -> 108초로 줄었다. 이전에는 맞아도 오래 버텨 20%를 이겼고, 지금은 버티지 못한다.
- [가설, 약함] 초보 사람도 1경기에서 같은 벽을 만날 수 있다. 봇은 피하지도 않으므로 사람보다 나쁜 쪽의 극단이다. 사람은 움직이고 웅크리므로 0%는 아닐 것으로 보지만 수치는 없다.

### 4-2. 캐치를 놓치지 않으면 k0~13 이 전부 100% (aggr100)
- [사실] 캐치 판정에 타이머 창이 없다(`match.js` hitOne: 캐치 자세 중 공에 닿고 공을 보고 있으면 성공, 원작 0x8416 직역). 자세 길이 s5 프레임(통키 팀 7~10) 안에만 닿으면 된다.
- [관측] aggr100 은 CPU 투구의 90% 이상을 잡는다(k0: 투구 15.6 중 캐치 13.9). 필살기도 같은 판정으로 잡힌다.
- [가설] 사람은 이 정밀도를 내지 못한다. 실제 난이도는 "캐치 성공률이 몇 %인 사람인가"로 결정되고, 표 T1 에서 aggr25 -> aggr75 사이에 승률이 27% -> 82%로 움직인다. 캠페인 난이도의 주된 축은 캐치 숙련도다.

### 4-3. k14 (팀 23 vs 팀 24): aggr75 3%, aggr100 60%
원인 후보(큰 것부터):
1. [사실+관측] 포메이션 엔드 어택: 경기당 2.6~3.0회(3회 한도를 거의 다 쓴다), 평균 데미지 163 = 맞으면 한 명 아웃. 다른 경기는 0.3~1.7회(T6).
2. [산수+관측] 팀 24 의 체력: 내야 HP 150 x 4 + 교체 150 x 3, 방어 12~16, 방어 선택의 72%가 캐치. 봇의 필살기(위력 50~85)로는 한 명에 3~4번을 맞혀야 하고 CPU 캐치율이 76%(T6)라 5분 안에 전멸시키지 못한다. aggr100 의 k14 경기는 **전멸 종료 0%, 시간 종료 85% + 서든데스 15%**.
3. [사실] 5분 제한은 원작에 없다. 원작이라면 계속 싸우는 경기를, 지금은 5분 시점의 남은 인원 수로 가른다. 엔드 어택 3번으로 인원이 먼저 줄어드는 쪽이 사람이므로 판정이 불리하다.
4. [관측] 컴퓨터 투구의 66%가 필살기(다른 경기 20~40%). 팀 24 는 패스를 많이 하고(b0 0.28) 던질 때는 필살 plan 비율이 높다.
- 이전(f4)에서 aggr100 이 100%였던 것은 엔드 어택이 같았는데도(2.3회, 평균 157) 필살기가 1.4회뿐이고 내야 일반 투구가 약했기(평균 23) 때문으로 본다 [가설, 중간].

### 4-4. k12·k13: aggr50 7%·3%, aggr75 42%·45%
- [산수+관측] 팀 17(k12)·팀 16(k13)은 방어 선택의 64~65%가 캐치, 실측 CPU 캐치율 75%·65%. 필살 plan 비율 0.71·0.78. k12 는 내야 일반 투구 위력도 높다(pow 33~48).
- 포메이션을 쓰는 봇(T8)은 k12 7% -> 20%, k13 3% -> 5%. 사람은 포메이션 3회를 쓸 수 있으므로 봇 수치보다 덜 극단적이다.

### 4-5. 곡선이 단조롭지 않다 (k2 가 k3 보다, k6 이 k7 보다 어렵다)
- [관측] aggr50: k1 100% -> k2 80% -> k3 97%, k5 67% -> k6 40% -> k7 80%, k8 62% -> k9 27%.
- [사실] 상대 순서·팀 능력치·선수 파라미터는 전부 원작 데이터(analysis/09). 원작 그대로의 굴곡이다. 손대지 않는 것을 권한다.

### 4-6. 무한 경기·교착
- [관측] 현재 엔진 12,600경기: draw_cap 0, 미종료 0, 예외 0. 최장 경기 시계 504초(k14 aggr100, 서든데스 204초). 서든데스 72경기, 시간 종료 1,124경기.
- [관측] 이전(f4) 4,500경기: draw_cap 14경기(0.3%. random 6, 나머지 봇 2씩).
- [관측] 자작 안전망 이벤트(`stall_*`)는 현재 7회, 전부 random 봇 경기(900경기 중). 이전(f4)은 19회, 역시 전부 random. 문서 25 §10 이 적어 둔 "사람이 낀 경기에서 원작 규칙으로 회수할 선수가 없는 경우"와 같은 종류로 보이며 원인은 조사하지 않았다. aggr·chase 봇 경기에서는 0회.

## 6. 사람이 확인할 것 (하플레이·사용자)
1. 1경기(k0)에서 캐치를 잘 못 하는 상태로 몇 번 만에 깨는가. 컴퓨터 필살기(k0 경기당 약 4회, 한 방 63 안팎)가 초반부터 나오는 것이 원작과 같은 느낌인가.
2. 사람의 실제 캐치 성공률이 어느 봇에 가까운가(aggr25 / 50 / 75). 이 값 하나로 표 T1 의 어느 열을 볼지가 정해진다.
3. k14: 5분 안에 끝나는가, 시간 종료 판정이 납득되는가, 엔드 어택 한 방 아웃이 원작과 같은가.
4. 로비 난이도 2 와 3 을 번갈아 했을 때 차이를 느끼는가(측정상 없다).
5. 포메이션 어택 3회를 사람이 실제로 얼마나 쓰게 되는가(봇은 쓰면 승률이 평균 +13~15%p).
6. 컴퓨터가 선 이탈을 경기당 7~21회 한다(aggr50, T6). 원작 그대로라고 문서 25 가 적고 있으나 화면에서 어색하지 않은지.

## 7. 남은 가설·하지 않은 것
- 봇은 회피·패스를 하지 않는다. 회피하는 봇을 넣으면 방어 없는 구간(4-1)의 0%가 얼마나 올라가는지 알 수 있다. 하지 않았다.
- D3 의 레벨 2 blunder 30 은 측정하지 않은 시작값이다.
- 레벨 덮어쓰기(T7)·포메이션(T8)은 일부 봇으로만 쟀다.
- `stall_*` 7회(random 봇)의 원인은 조사하지 않았다.
- f4 -> 현재 사이에는 공격 plan 직역(4차), 정검수 4차 리뷰 수정(강제 회수 정지, 넉백 벽 반사 등), 난수 시드 짝수 고정이 함께 들어 있다. 시드 수정의 영향이 없다는 것만 확인했고(§1-4) 나머지는 나눠 재지 않았다.
- T9(종전 지표)와 §3-1 의 "보유 프레임의 약 17%가 포메이션 중" 은 시드 수정 전 엔진에서 잰 값이다.
- 원작 실기에서의 스테이지별 체감 난이도 자료가 없어 "원작과 같은가"는 이 측정으로 판정할 수 없다. 판정 근거는 차분 하네스(63/64)와 원작 데이터 사용 여부다.
