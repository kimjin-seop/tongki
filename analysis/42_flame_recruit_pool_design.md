# 42. 불꽃의 계승 2차 — 영입 풀(오리지널 클론 + 원작 희귀 발견) 밸런스 설계 (2026-11-19, 임밸런)

기준 문서: `analysis/36`(§7.2·§11.1), `analysis/39`(D4·D15~D21, B5·B11·B20), `analysis/40`(§12·§13), `analysis/41`.
이번 작업에서 만든 것은 **이 문서 한 개**다. 데이터(JSON)·서버·엔진·도구는 고치지 않았다. 시뮬은 읽기 전용으로만 돌렸다(`DB_PATH=:memory:`, 진행·리그·결과·백업 경로는 세션 임시 폴더. `data/` 목록은 실행 전후 같다. 3000/3300/3410/8765 접속 없음).

표기: [사실] 코드·데이터에서 읽음 / [산수] 데이터로 계산 / [관측] 시뮬 결과 / [가설] 확인하지 못함. **수치는 전부 시작값**이다.

## 0. 결론 먼저

1. [사실] 지금 영입은 **원작 선수만** 나온다(`nodes.js recruitChoices`: 해금 팀 1~7 의 선수 42명 중 무작위 3명). 시뮬 봇은 영입을 **하지 않는다**(`sim_balance.mjs` 195행 `choose(-1)`, 노드 우선순위도 맨 끝). 그래서 analysis/40 의 승률표에는 영입 효과가 0 으로 들어 있다.
2. [사실] flame 에는 "체력 고정" 개념이 없다. HP(s0)는 선수마다 20~150 이고 `stats.js` 는 하한 1 만 둔다. 클론은 HP 도 역할·등급에 따라 달라진다(상한 112 = HUD 얼굴 칸 한계 `hud.js HP_FACE_MAX`).
3. 클론 모델 = **역할 7 × 등급 5, 점수 예산제**(§2). 등급 예산 D −12 / C −6 / B 0 / A +7 / S +14 점(B = 시작 7명 평균), 역할은 주 능력을 5~6점 올리고 다른 능력을 그만큼 깎는다. 300명 풀 평균 −2.1점 ≤ 시작 팀 0.2점 [산수].
4. [관측] 약한 시작 선수 3명(1·3·4번 칸)을 같은 등급 클론 3명으로 바꾸면 어려운 5조건 승률이 **46% → D 58 / C 58 / B 68 / A 74 / S 84%**. 등급 격차는 재진다(D 와 S 는 구간이 겹치지 않는다). 다만 **D 급도 시작 약체보다 나쁘지 않다** = 점수가 실제 강함과 어긋난다(수비·캐치형이 강하고 패스·속공형이 약하다, §2.5). 역할 보정점을 다시 맞춰야 한다.
5. [산수] 원작 선수는 "희귀 = 강함"이 아니다. 팀 1~7 원작 49명은 평균 −4.3점(클론 C 급)이고 28명이 C 이하다. 팀 8~14 는 평균 +5.6(A 급), 팀 15~21 은 +12.5(S 급)이며 S 초과가 12명이다. [관측] 팀 1~7 최강 3명을 넣으면 85%(S 클론 3명 84% 와 같은 급).
6. 희귀 발견 확률: 사용자 시작값 3/5/8% 를 **칸당**으로 쓰면 스카우트 인맥(PB04) 3단계에서 한 도전 63% 까지 오른다 [산수]. **"방문당 1칸" 방식 8/12/18%** 를 권한다(기본 3칸에서 칸당 3/5/8% 와 같은 값, 후보 수가 늘어도 그대로). 세 번 다 영입실에 가는 도전에서 34%, 보통 수준 봇 기준 4~11 도전에 1명.
7. [사실] 통키 팀(팀 0)은 지금 코드로는 **영입 후보에도 상대에도 나올 수 없다**(시작 7명의 `from` 이 팀 0 이라 `map.js conflicts` 가 늘 걸린다). [관측] 최종 보스로 세우면 후반 빌드 승률 65 / 80 / 80% 로 지금 보스 팀 4(70 / 65 / 100%)와 같은 급이다. 보스 전용 권고는 타당하고, 넣으려면 `conflicts` 를 고쳐야 한다(§6).
8. 팀 2·4 는 상대 풀에 **그대로 둔다**(§6.2).

근거가 약한 곳: 칸당 20판 × 5조건 = 100판이라 ±10%p 다. 한 명만 바꾼 측정(51~64%)은 서로 구분되지 않는다. flame 좌석을 컴퓨터가 조작하고(캐치 약 60%), 클론의 몸·컴퓨터 표는 태동 원래 칸 그대로 두고 능력치만 바꿔 쟀다. 도전 한 판(HP 이월) 측정은 서버 구현 뒤에만 할 수 있다(§7).

### 2.1 점수 예산제 [자작 제안]

능력치마다 1점의 크기가 다르다(전체 175명 표준편차의 약 1/3). 선수 점수 = Σ (능력치 − 기준값) ÷ 단위.

읽을 것
- 등급 순서는 맞게 나온다(58 → 58 → 68 → 74 → 84). D·C 는 구분되지 않고, D 와 S 는 구간이 떨어져 있다.
- **D 급 3명도 기준보다 낮지 않다.** 바꾼 세 칸의 시작 선수가 평균 −8.3점이라 D(−12)와 점수는 비슷한데, D 급 수비형(HP 84·방어 12)이 표우람(HP 56·방어 8)보다 버틴다. 봇 경기의 60~70% 가 시간 종료로 끝나 HP·방어가 승패를 가른다.
- 역할 차이: 수비 66 > 캐치 64 > 에이스·균형 55 > 고공 52 > 속공 51 > 패스 46. 양 끝(66 대 46)은 구간이 거의 겹치지 않는다. **패스형은 보정점 +3 을 주고도 효과가 0** 이다.
- 한 명만 바꾼 값(61·64%)은 기준과 구간이 겹친다. 한 명 영입의 효과는 100판으로는 재지지 않는 크기다.
- [가설] 사람은 봇보다 잘 잡아 HP 가치가 낮고 공격·투속 가치가 높다(40 §13.1: 숙련 조작 캐치 87%). 봇 결과만 보고 수비형을 깎으면 사람에게는 반대로 어긋날 수 있다.

### 7.2 봇 영입 정책 초안 (도구에 넣어야 한다) [자작 제안]

지금 봇은 영입을 고르지 않으므로 풀을 바꿔도 위 표가 그대로 나온다. 정책을 인자로 고르게 한다(`--recruit=off|safe|always`).

| 단계 | off (지금) | safe (주 지표) | always |
|---|---|---|---|
| 노드 선택 | 영입 맨 끝 | 팀 HP 80% 이상이면 영입 > 상점 > 특훈, 미만이면 휴식 | 영입 층에서는 언제나 영입 |
| 후보 점수 | - | §2.1 점수. 원작 선수도 같은 식 | 같음 |
| 교체 대상 | - | 주인공을 뺀 6명 중 점수(영구 성장 A 포함)가 가장 낮은 선수 | 같음 |
| 영입 조건 | - | 후보 점수 ≥ 대상 점수 + 3 일 때만. 아니면 영입 안 함 | 같음 |
| 역할 빈자리 | - | 로스터에 없는 역할의 후보는 +2점. 수비·에이스가 없으면 +4점 | 같음 |
| 뒤처리 | - | 빠진 선수 장비를 자동 장착으로 다시 끼운다, HP 많은 4명을 내야로 | 같음 |

### 7.3 측정 순서

| 단계 | 내용 | 판수 | 보는 것 |
|---|---|---|---|
| 1 | 역할 보정점 맞추기(`cond`, 클론 3명 고정 빌드) | 역할 7 × 100판 | B 급 역할별 승률이 서로 15%p 안. 벗어난 역할의 보정점을 1점씩 |
| 2 | 등급 간격 확인(`cond`) | 등급 5 × 100판 | D < B < S 순서와 D·S 구간 분리. D 가 기준(46%)보다 높으면 예산을 3점씩 내린다 |
| 3 | 몸통 분류 0/1/2 차이(`cond`, 같은 능력치에 `from` 만 바꿈) | 3 × 100판 | 차이가 구간 밖이면 역할별 몸 배정 규칙 추가 |
| 4 | 도전 5조건 × 정책 3종 | 15 × 40판 | 아래 목표 지표 |
| 5 | 희귀 확률은 산수로 충분. 시뮬에서는 "원작을 본 도전 수"만 세어 §5.1 과 맞는지 확인 | 4 에 포함 | |

한 번에 한 묶음만 바꾸고 같은 시드로 다시 잰다. 40판은 우승률 ±15%p 라 "같은 시드에서 바뀐 판 수"를 같이 적는다.

### 7.4 목표 지표 [자작 제안]

| 지표 | 목표 | 지금 |
|---|---|---|
| safe 정책의 평균 승수 − off | +0.3 ~ +1.0 (영입이 쓸모 있지만 필수는 아님) | 0(영입 없음) |
| always − safe | 0 이하(다쳤을 때 영입실에 가면 손해여야 휴식과 선택이 된다) | - |
| 봇 2·없음 우승 | 0~10%, 40판 중 1판 이상이면 좋다(불가능 금지) | 0/40 |
| 봇 2·중간 우승 | 10~25% | 10% |
| 봇 2·전부 우승 | 30~50% | 25% |
| 봇 2·전부·고난도 우승 | 10~25% | 13% |
| 봇 1·없음: 구간 1 통과 | 20% 이상 | 3/40 |
| 구간별 경기 승률(봇 2·없음) | 구간 1 일반 85~95 / 강팀·보스 75~90, 구간 2 일반 55~75 / 보스 40~60, 구간 3 50~75 / 최종 보스 40~60 | 구간 1 87~93, 구간 2 일반 50~52·보스 33 |
| 영입한 도전의 비율(safe) | 30~70% | - |

"+0 기준 40~60%"의 해석: 다른 프로젝트 메모의 수치라 flame 에 그대로 옮기면 영구 성장 없이 우승 40~60% 가 되어 반복 육성의 뜻이 사라진다. 여기서는 **영구 성장 없음(+0)의 구간 2 일반 경기 승률 40~60%, 영구 성장 전부의 우승 30~50%**로 읽었다(§9-6, 팀장 확인).

### 7.5 사람이 확인할 것

- 영입 화면에서 D·C 급 3명이 떴을 때 "꽝"으로 느끼는지, 역할이 눈에 들어오는지.
- 수비형(HP 92)과 속공형(HP 44)의 차이가 조작에서 느껴지는지. 봇은 이동·패스의 가치를 재지 못한다.
- 원작 선수를 처음 본 순간이 "드디어"인지, 몇 도전 만에 봤는지.
- 같은 몸이 색만 다르게 상대 팀에 섰을 때 헷갈리는지.

### 12.0 결론 먼저

1. **§0-4 의 "D 급도 시작 약체보다 나쁘지 않다"는 절반은 표본 탓이었다.** 기준(시작 7명)을 1,000판으로 다시 재니 50.0% [47-53] 이다(§2.5 의 46/100 은 낮게 나온 표본). 종전 모델의 등급 승률은 7역할 합 1,400판씩 D 48.1 / C 51.9 / B 54.4 / A 61.0 / S 66.4% 로, D 는 기준과 구분되지 않고 D·C 구간이 겹쳤다 [관측].
2. **등급 예산을 D −20 / C −10 / B 0 / A +10 / S +20 으로 바꿨다**(종전 −12 / −6 / 0 / +7 / +14). 보정 뒤 D 40.9 [38-43] / C 48.8 [46-51] / B 54.4 [52-57] / A 63.5 [61-66] / S 70.1 [68-72]%. D 는 기준·C 와 구간이 떨어지고, C 는 시작 약체와 같은 급, 순서는 단조다. 역할 산식·보정점은 그대로 두었다(B 급 수비 68% ~ 속공 45.5%, 22%p 격차 유지).
3. **풀의 실제 클론은 위 수치보다 약 10%p 약하다(세 명 기준).** 서버는 클론의 엔진 `from` 을 몸(팀 1~7 원작 선수)으로 준다(39 B24). 같은 능력치에서 `from` 만 몸으로 바꾸면 B 급 57.0 → 46.0%, S 급 74.5 → 65.0% 다 [관측]. 몸통 분류가 같든 다르든 같은 크기라 히트박스가 아니라 **몸의 컴퓨터 성향 표**가 원인으로 보인다 [가설]. 데이터로는 고칠 수 없다(§12.7 박백엔 요청 2).
4. **영입은 지금 봇 기준으로 이득이 아니다.** safe 문턱을 팀 HP 80 → 60% 로 내리면 영입한 도전이 10% → 41% 로 목표(30~70%) 안에 들지만, safe − off 평균 승수는 **−0.32 [−0.55, −0.09]**(600판, 같은 시드 짝)로 목표(+0.3~+1.0)의 반대쪽이다.
5. **always 가 off 보다 나쁜 까닭은 클론 수준이 아니라 휴식을 버린 값이다.** 영입실에 가되 영입하지 않는 진단 정책(visit)이 off 보다 −1.21승 [−1.62, −0.80], always 는 −1.18 [−1.60, −0.76]. 즉 영입 자체의 값은 +0.03(구간 ±0.5)이고, 후보를 전부 S 급으로 바꿔도 +0.25 다. **등급 확률표·후보 수·원작 희귀 확률은 바꾸지 않았다**(바꿔서 닿을 수 있는 폭이 목표에 못 미친다).
6. 통키 팀 최종 보스: 팀 0 은 도전에서 16승 2패(89% [67-97])로 팀 4 와 같은 급이다. **[16, 0] 을 권한다**(우승 판 합계 19 → 19 로 지금과 같고, [4, 16, 0] 은 19 → 23 으로 쉬워진다). `run_config.json` 은 바꾸지 않았다.

근거가 약한 곳은 §12.8 에 모았다.
